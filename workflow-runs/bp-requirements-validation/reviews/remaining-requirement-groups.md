## (c) 要求定義の整合と、能力契約・実証の境界

- D の対象スキル、BP 操作、O008/O024/O051 の bridge は区別できている。記録保存と review 非変更、通常修正許容と形式失敗停止も、原文上は両立する。これは独立 source review で確認した範囲である。
- D014/015/046 は、一覧照合・未確認・既知不適合を別条件として扱える。host 上で実際に制限が効くことの実証は後段であり、要求検証の完了条件へ追加しない。D011 の実時間強制も同じ扱いとする。
- O025 は「対応する仕様の確定値・規則に照らせること」と「対応仕様なしを未検査にすること」、O028 は「現行監査基準を使えること」と「基準なしなら停止すること」を要求している。この能力契約は今回検査できるが、仕様 6 本や監査観点の内容自体が妥当かという検査には広げない。
- D051 は列挙・理由の対応と開示を検査する。最も硬い層か、理由の意味が妥当か、列挙が意味上網羅的かを新たな適合条件へ戻さない。
- O018/design:505 の適用境界は既に報告した限定を維持する。S32 の裁定も、影響結果の現在利用と過去履歴を分離する範囲を越えて、新しい reuse 必須方針へ広げない。

各 group では、まず (a) の有限制約・関係を機械検査し、(b) の残りを独立意味確認に渡す。形式化できる未実施句を、意味 review 済みという理由だけで完了にしない。任意件数、任意 run 数、動的探索の無界性は小さい有限例だけでは保証できないので、対象とした境界を残す。

旧 61／73／6579 等の成功は、現行 source と句・モデル・期待・境界の対応を再確認せず加算できない。この note は既存返答の保存であり、新たな要求全文 review・solver 実行・仕様検証は行っていない。coverage・source・model の正本は変更していない。

# 欠落報告のテンプレート（同梱物が揃っていないとき）

`install-check` が 1 件でも missing を返したときに使う文面の形。**パス・コマンド・
設定値を自分で組み立てないため**にテンプレートを外に置いている。埋めるのは実測値だけで、
埋められない欄は「未実測」と書く（推測で埋めると、このスキルが対象にしている類型を
スキル自身が犯す）。

## 形

```
claim-gate の同梱物が揃っていないため、操作は行わずに止めました。

実測（存在確認のみ。中身は見ていません）:
- <実測したパス> : 見つかりません
- <実測したパス> : あります

このため、次はできません:
- <依頼された操作>（<どの欠落によってできないか>）

いま言えることはここまでです。インストール状態の修復や不足ファイルの作成は
実装側の作業なので、このスキルからは行いません。
```

## 埋め方

- **`<実測したパス>` は `install-check` が返したものをそのまま書く。** 近い名前の
  ファイルで代用しない。別ファイルを操作すれば、利用者が意図していない対象を変える
- **「おそらく install が未完了」等の理由を添えない。** 測ったのは存在の有無だけで、
  理由は測っていない
- 状態ファイルだけが無い場合は欠落報告ではなく **「off」** として扱う。初回有効化時に
  作られるものなので、無いことがそのまま無効を意味する

## 例（適合検査を依頼されたが script と fixture が無い場合）

```
claim-gate の同梱物が揃っていないため、操作は行わずに止めました。

実測（存在確認のみ。中身は見ていません）:
- <plugin>/hooks/hooks.json : あります（Stop 登録あり。ただし Claude Code 側で
  enable されているかは測っていません）
- <plugin>/scripts/run_conformance.mjs : 見つかりません
- <plugin>/tests/fixtures/ : 見つかりません
- <plugin>/agents/claim-judge.md : あります

このため、次はできません:
- 適合検査の実行（スクリプトと fixture の両方が無いため、一致表を作れません）

いま言えることはここまでです。インストール状態の修復や不足ファイルの作成は
実装側の作業なので、このスキルからは行いません。
```

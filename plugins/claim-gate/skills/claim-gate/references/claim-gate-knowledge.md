## 確定済みの設計決定

1. 配布は marketplace プラグインのみ。特定 PC 限定の構成は作らない
2. 既存プラグインへの同梱はしない。独立プラグインで opt-in
3. トグル必須。配布時の既定は off。無効時は完全 no-op（コストゼロ）
4. **fail-open。** 判定に迷ったら通す。stdin の不正・B2 の spawn 失敗・timeout・認証
   エラー・非 JSON 応答・裏付けが部分的なケースもすべて通す。全応答を尋問する装置に
   しない。**この点は先例（codex の stop gate）と逆である** — 先例は timeout・非ゼロ終了・
   パース不能をいずれも block にしている。claim-gate ではそれらを pass にする。
   ただし**「通した」と「ゲートが動いていない」は分けて数える**（`schemas.md` の
   「故障の 3 分類」）。混ぜると、走らなかったゲートが全件合格として読める
5. 2 段構成:
   - **B1** = 決定的パターン前段（script のみ、LLM 呼び出しゼロ）。不在・網羅型の断定
     パターンにヒットしなければ即通過
   - **B2** = fresh-context 判定器（B1 ヒット時のみ）。当該主張に (a) 網羅検証の裏付け
     （閉集合の列挙・全文読み・形を変えた複数検索への言及）か (b) 手段スコープが付いて
     いるかだけを見る。どちらも無ければ block、あれば通す。判定者は主張の型と裏付けの
     対応だけを見て、著者の推論・確信度は入力に含めない

# mechanism-arbiter

## 役割
`[ANALYST_A_MECHANISMS]` と `[ANALYST_B_MECHANISMS]`（どちらも index 付き）を読み、
**同じ機序を指している組**を `pairs` として返す。どちらにも対応が無いものは
`unpaired_a` / `unpaired_b` に index で残す。

## なぜ index しか返さないか
返せるのが index だけなので、どちらの analyst も言っていない機序を新たに足す経路が
構造上ない。文言を書き直せるようにすると、統合の過程で誰も観測していない機序が
生まれる。採否（`identified` を維持するか落とすか）は script の算術が決めるので、
ここでは判定しない。

## 同じ機序とみなす基準
**言い方ではなく、主張している因果が同じか**で見る。

- 同じ: 「B は規則をレベル間で持ち越したので再探索が減った」と「継続 session では
  既知の規則が保持され、探索の重複が起きなかった」— 同じ因果を別の語で述べている
- 別: 「規則の持ち越しで再探索が減った」と「継続 session では入力が長くなり後半の
  精度が落ちた」— 同じ条件を扱っているが因果が違う
- 別: 片方が原因を述べ、もう片方が結果の要約しかしていない場合

迷ったら組にしない。取り違えて組にすると、独立に確認できていない機序が
`corroborated` に格上げされる（これが一番高くつく誤り）。

## 出力（JSON のみ）
```
{ "pairs": [{ "a": 0, "b": 2, "why_same": "同じ因果を述べている理由を 1 文" }],
  "unpaired_a": [1], "unpaired_b": [0, 3] }
```
1 つの index を複数の組に入れない（1 対 1 対応のみ）。

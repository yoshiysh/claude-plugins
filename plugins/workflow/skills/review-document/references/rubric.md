# 採点基準（rubric）— 正本

3軸の判定手順・独自用語の「失うもの」判定・分量内訳の数え方・改善策の効果順の基準は、
このファイルが正本。SKILL.md や script の指示文はここへの参照だけを持つ。
このファイルには判定ルールのみを書く。レビュー対象文書の実例・具体的なスコア数値・
特定プロジェクトの用語はここに書かない（対象側が変わるたびに参照ズレを起こすため）。

## Contents

- 共通原則
- 軸 shortness（短さ）

## 共通原則

- 各軸は 1〜10 点。10 が「圧縮・平易化・言い換えの余地がほぼ無い」、1 が「余地が全面にある」。
- 文字数・行数のしきい値では判定しない。長さは内容量にも比例するので、
  長さで切ると内容の濃い文書が不当に落ちる。測るのは「同じ内容をもっと短く・
  平易に言えたはずか」という余地。
- 点数には必ず 1 行の根拠を対にする。根拠の書けない点数は付けない。
- 採点できなかった（対象や基準が読めなかった）場合は 0 点ではなく欠測として報告する。

## 軸 shortness（短さ）

同じ規範内容・情報をどこまで短く言えたはずかを見る観点。

- 読み手の行動を変える文（規範文）に対して、前置き・自己言及（「本節では〜を述べる」）・
  言い換えの重複がどれだけ付いているかを測る。
- 改善策は「削除」より「置き場の移動」を優先する。例：根拠句は末尾の表へ移す、
  却下した設計案は別ファイルへ移す。削ると根拠の追跡ができなくなるため。
- 証拠として、規範文／根拠・注記／メタ文の概算比率（breakdown）をファイルごとに返す。
- 返す証拠：worst_sentences と breakdown。jargon は空配列でよい。

## 軸 plainness（平易さ）

予備知識の無い読み手が 1 回読んで意味を取れるかを見る観点。

- 手がかり：1 文の長さ、入れ子の深さ、否定の重なり、1 文あたりの参照数。
- 難しい語が使われていること自体は問題ではない。初出で定義されていて 1 読で意味が
  取れるなら平易とみなす。
- 証拠として、最も読みにくい文を原文のまま引用し、意味を落とさない書き換え例を必ず対にする。
  書き換え例の無い指摘は反証者が「内容を落としていないか」を検証できない。
- 返す証拠：worst_sentences。jargon と breakdown は空配列でよい。

## 軸 no_jargon（独自用語の不使用）

その文書（群）が発明した用語・記法のうち、一般語で言い換えても失うものが無いものを探す観点。

- 業界で通用する既存の専門語は対象外（発明されたものではない）。
- 言い換えると失うものがある用語は指摘しない。短縮のために正確さを削るのは改善ではない。
- 各候補について、置き換え案と「置き換えると失うもの」を書き、失うものが無い場合だけ
  loses に「無し」と書き safe_to_replace を true にする。
- 同じ用語が複数ファイルに跨るなら 1 件にまとめ、files に全ファイルを並べる。
- 返す証拠：jargon。worst_sentences と breakdown は空配列でよい。

## 分量内訳（breakdown）の数え方

ファイルごとに、文単位で次の 3 分類の概算比率（合計 100%）を出す。

| 分類 | 何を数えるか |
|---|---|
| normative_pct | 読み手の行動・判断を変える規範文 |
| evidence_pct | 規範の根拠・注記・例外条件・参照 |
| meta_pct | 文書自身についての文（前置き・自己言及・案内・繰り返しの要約） |

厳密な文数カウントは求めない。段落単位の概算でよいが、比率の根拠となる代表例を
1 つ挙げられる粒度で見ること。

## 独自用語の「失うもの」判定

候補用語ごとに次を順に問う。

1. その語は既存の業界語・一般語か。→ 是なら対象外。
2. 一般語の言い換え案を 1 つ書けるか。→ 書けないなら指摘しない。
3. 言い換えたとき、区別していた概念・条件・範囲のどれかが潰れるか。
   → 潰れるなら loses にその内容を書き、safe_to_replace は false（指摘に載らない）。
   → 何も潰れないなら loses は「無し」、safe_to_replace は true。

## 改善策の効果順（effect）の判定基準

suggestions の effect（high / medium / low）は主観の印象順ではなく、次の基準で決める。

| effect | 基準 |
|---|---|
| high | 複数ファイルに跨る構造的な「置き場の移動」で、規範文の比率（normative_pct）が明確に上がるもの。例：却下案・長い根拠句を別ファイルや末尾表へ移す |
| medium | 単一ファイル内の書き換えで平易さが上がるもの。例：入れ子や否定の重なった文の分割・書き換え |
| low | 単発の語の置換。例：独自用語 1 語を一般語に置き換える |

同じ effect 内の順序は、影響するファイル数・指摘件数の多いものを先にする。

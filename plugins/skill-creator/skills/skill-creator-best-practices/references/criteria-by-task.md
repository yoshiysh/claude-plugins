# タスク種別ごとの検証基準定義

基準生成・基準補完 Sub Agent が参照するデフォルト基準。
これはあくまで出発点であり、スキル固有のリスクを加えた上で使うこと。

---

## 全タスク種別共通

- description が3人称で書かれているか（"I can help" や "〜できます" は禁止）
- description に [What]（何をするか）と [When]（いつ使うか）の両方が含まれているか
- description に除外条件（対象外）が明記されているか
- name が kebab-case（英小文字・ハイフン区切り）か
- name が gerund 形式（processing-pdfs, analyzing-data など）または明確な動詞句か
- SKILL.md 本体が500行以内か
- 参照ファイルが SKILL.md から1レベルの深さに収まっているか
- 100行を超える参照ファイルに冒頭目次があるか
- 時間依存の情報（「〇年以降は〜」）が含まれていないか
- 用語が一貫しているか（endpoint / URL / path が混在していないか等）
- **生成物を、それを生成した agent 以外が検証する経路があるか** — 状態を変える（コミット・
  PR 作成・外部書き込み・ファイル変更）か、出力が下流で行動の根拠になるスキルに適用する。
  `agents/` を持たない単体スキルも対象（構造の有無で判定しない）
- その検証が状態変更の**前**に置かれているか（事後検証では不可逆な変更を止められない）

## document 系

- description は「いつ使うか」と「何をするか」の両方を含んでいるか
- 出力フォーマット（HTML / Markdown / 構造など）が具体的に定義されているか
- 対象読者のレベルに合った言葉遣いになっているか
- 非エンジニアがコピペできる操作手順が含まれているか
- 生成物のファイル名・保存場所が明示されているか
- 実際の入力例と出力例がセットで1パターン以上含まれているか（「省略」は不可）

## procedure 系

- 各ステップが独立して理解できるか（前後の文脈なしで）
- エラー時・例外時の処理指針が含まれているか
- 人間が介入すべきタイミングが明示されているか
- 入力の形式・制約が明確か
- ステップ間のデータの受け渡し方が定義されているか
- フィードバックループ（検証→修正）が設計されているか

## data 系

- 入力データの形式・スキーマが定義されているか
- 出力の精度基準・許容誤差が設定されているか
- データが欠損・不正な場合の挙動が記述されているか
- サンプル入出力が含まれているか
- 処理量・タイムアウトなどのスケール制約が明示されているか

---

## ハーネス（状態を持つ・長時間走る・agent を跨ぐスキル。上の 3 分類とは独立）

`best-practices.md` §14 の原理。適用するかは「そのスキルが状態を持ち越すか／agent を跨ぐか」で決め、
構造の有無で決めない。

- 現在の状態が会話履歴ではなく state ファイル／script 変数にあり、再開がそこから始まるか
- subagent の戻り値と script 出力が「判断に要る要約 + 根拠のパス」になっているか（全文ログを親 context に戻していないか）
- Phase 間の引き継ぎに決定・制約・根拠・未解決・却下案が残り、「古い方から捨てる」になっていないか
- 永続状態（DB・索引・resolved・メモリ）への書き込みを、別 context の verifier が再取得した証拠で gate しているか
- 試して却下した経路と実行した事実が state に残り、再開・次ループで二重実行や同じ失敗の再試行が起きない構造か

## Workflow 実行型（アーキテクチャ軸・上の 3 分類とは独立）

`ARCHITECTURE` が `workflow` のスキルには、ドメイン分類の基準に加えて以下を適用する。
これらは「散文で守らせる」のではなく「構造として満たされているか」を見る項目。

- SKILL.md が script の**内側の手順を再掲していない**（script が唯一の正になっているか）
- `meta` が純粋なリテラルで、`name` / `description` / `phases` を持つか
- `phase()` のタイトルが `meta.phases[].title` と一致しているか
- `import()` / `Date.now()` / `Math.random()` / 引数なし `new Date()` を含まないか
- `agent()` の返り値を使う前に `.filter(Boolean)` しているか
- `parallel()`（barrier）を使っている箇所に、**全件が揃う必要がある理由**が書かれているか。書けないなら `pipeline()` が正しい
- 平均・比率・件数の**集計を LLM にさせていない**（script の算術になっているか）
- 閾値判定が式で書かれているか（目分量の余地が無いか）
- 検証結果を `schema` の構造化配列で受けているか（markdown 中の記号を数えていないか）
- **欠測を成績に混ぜていない**か（出力が欠けたケースを別カウントにし、0 件採点時に `0` ではなく `null` を返しているか）
- 上限・打ち切り・サンプリングを `log()` に落としているか（黙った打ち切りが無いか）
- 人間の判断が要る地点が script の**外**にあるか（`status: "BLOCKED"` 等で境界に返しているか）
- ループに停止条件があるか（`maxRevisions` 等の打ち切りが構造として入っているか）

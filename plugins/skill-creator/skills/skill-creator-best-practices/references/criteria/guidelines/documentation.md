# 文書

README・要求・仕様・規約・スキル指示に適用する。文書ごとの型と ID の契約は、その文書を扱うスキル・ツールを正本とする。

- **読者が判断・実行するための情報を、平易な文と具体的な条件で書く。** 長さだけを削って対象・条件・例外が消えると、読み手ごとに動作が変わる。
  検査: レビュー。
- **節ごとに扱う問いを決め、既存の節を更新する。** 同じ決まりを追記で増やすと、改稿時に片方だけが残る。
  検査: レビュー、重複する用語・条件の検索。
- **値・列挙・契約は正本を参照し、例示は規範と区別する。** 写しや例が別の契約として使われるのを防ぐ。
  検査: レビュー、参照先の実在確認。
- **規則の理由は、破ると何が壊れるかに絞る。** 読者が初めての状況でも規則を適用できるようにする。
  検査: レビュー。コードコメントの要否と変更経緯の置き場は AGENTS.md に従う。
- **要約や見出しで済む自明な言い換えを増やさず、説明が必要な契約は省かない。** 読む量を増やさず、判断に必要な条件を保つため。
  検査: レビュー。
- **機械検査で保証する範囲と、意味を読む必要のある範囲を分けて記す。** コマンド成功を、実施していない検証の証拠にしないため。
  検査: レビュー、記載したコマンドと検出範囲の照合。

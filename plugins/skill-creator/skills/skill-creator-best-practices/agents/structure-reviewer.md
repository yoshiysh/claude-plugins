## タスク

構成案を以下の観点でレビューしてください。
文章の良し悪しではなく、「この構成で実装したら要件を満たせるか」を判断する。

### チェック項目

#### A. 要件との整合性
- 各検証基準が、どのセクション・コンポーネントでカバーされているか
- カバーされていない基準がないか

#### B. 実現可能性
- 選定されたコンポーネントが既存のものか
- 構成案が挙げた懸念点への対処が必要か

#### C. 情報の流れ
- セクションの順序がユーザーの理解を助けるか
- 重複・抜けがないか

#### D. 目次・nav の同期
- 変更するセクションすべての目次・nav エントリが記載されているか
- 漏れているエントリがないか

### 判定形式

各チェック項目について 3 値で判定する。

- `ok` — 問題なし（構成案に明示されている）
- `warn` — 部分的・要確認
- `fail` — 問題あり（具体的に何が問題かを `rationale` に引用して示す）

## 出力形式

**JSON で返す。** `checks[].result` が判定の契約で、script はこのフィールドを直接読んで
差し戻すかを決める（`failed[]` への書き写しには依存しない。転記が落ちても差し戻しが
消えないように、判定フィールドの方を正にしてある）。

```json
{
  "checks": [
    { "name": "A. 要件との整合性", "result": "ok | warn | fail", "rationale": "根拠（構成案からの引用）" },
    { "name": "B. 実現可能性", "result": "ok | warn | fail", "rationale": "..." },
    { "name": "C. 情報の流れ", "result": "ok | warn | fail", "rationale": "..." },
    { "name": "D. 目次・nav の同期", "result": "ok | warn | fail", "rationale": "..." }
  ],
  "failed": ["言葉で補足したい問題の要点"],
  "warnings": ["要確認の点"],
  "priority_fixes": ["先に直すべき箇所"],
  "report": "構成レビューレポート本文（散文）"
}
```

`name` は項目ごとに区別できる文字列にする（同じ名前で複数の `fail` を返すと、
script 側の重複除去で 1 件に畳まれる）。

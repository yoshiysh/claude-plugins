あなたはスキルの動作確認テストを設計する専門家です。
以下のペルソナとスキル情報をもとに、リアルなテストプロンプトを3件生成してください。

## あなたのペルソナ
[PERSONA_TESTER]

## スキル名
[SKILL_NAME]

## description（トリガー条件）
[SKILL_DESCRIPTION]

## トリガー条件・対象ユーザー
[REQUIREMENTS_SUMMARY]

## タスク

このスキルの典型的な利用者（上記ペルソナ）になりきって、
実際に入力するとしたらどう書くかを考えてください。

重要：完璧な入力を書かない。ペルソナらしいリアルな発話にすること。
少し曖昧だったり、情報が不足していたりするのはむしろ望ましい。

生成する3件：

テスト1（発動すべき・正常系エッジケース）
- このスキルが最もよく使われる状況だが、入力が境界値的なケース
- 件数が極端に少ない・多い、必須項目のみ、など「ちゃんと動くか不安になる入力」
- ペルソナが自然に入力する文章

テスト2（発動すべき・準正常系）
- 入力が不完全・曖昧・形式が異なるケース
- スキルが確認を求めたり補完したりして継続処理すべき状況
- 情報が足りないか、口語的・文章形式など想定外の形式で入力される

テスト3（発動すべきでない・誤発動リスク検証）
- 関連はあるが、このスキルではなく別の手段で対応すべき状況
- スキルの対象外であることが description に書かれているかを確認する

### 3種別の定義（参考）

| 種別 | 定義 |
|------|------|
| 正常系エッジケース | 仕様通りに処理されるが境界値的な入力 |
| 準正常系 | 対処は定義されているが完全な正常系ではない状態 |
| 異常系 | 処理を継続できないか、エラー案内が必要な状態（テスト3は異常系ではなく誤発動検証）|

## 出力形式

テスト1（正常系エッジ・発動すべき）: [ユーザーの発話文]
テスト2（準正常系・発動すべき）: [ユーザーの発話文]
テスト3（発動すべきでない）: [ユーザーの発話文]

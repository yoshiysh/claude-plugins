# release-notes-editor

マージ済みの PR から、次のリリースのリリースノートの下書きを作る。項目を 1 つ書くたびに利用者に見せ、承認・修正・削除の答えを受けてから次の項目へ進む。

## 入力

- 対象のブランチ名（利用者が依頼の中で指定する）

## 手順

1. 対象のブランチで、前のリリースのタグより後にマージされた PR の一覧を `gh pr list --state merged --base <ブランチ名>` で得る。
2. PR の要約を集める。`Workflow({ scriptPath: "[SKILL_DIR]/scripts/collect.js", args: { prs } })` を起動し、返った要約の並びを受け取る。
3. 要約を `references/style.md` の分類の規則で分類し、分類ごとに並べる。
4. 項目を 1 つずつ `references/style.md` の文体の規則で書き、利用者に見せる。利用者の答えが承認なら次の項目へ進み、修正ならその指示どおりに書き直して見せ直し、削除ならその項目を捨てて次へ進む。
5. 全ての項目を終えたら、reviewer の agent（`agents/reviewer.md`）に下書きの全体を読ませ、返った指摘を利用者に見せる。reviewer は agent の定義の `permissionMode: plan` で書き込みを禁じられているので、下書きのファイルを書き換えない。
6. 利用者が下書きの全体を承認したら、`docs/release-notes/<ブランチ名>.md` に書き込む。

## 出力

- `docs/release-notes/<ブランチ名>.md` に書き込んだ下書き

## 停止の種類

- 完了: 利用者が下書きの全体を承認し、ファイルに書き込んだ。
- 入力待ち: 対象のブランチ名が依頼に無い。ブランチ名を尋ねて止まる。
- 失敗: PR の一覧を得られない（`gh` が使えない、ブランチが無い）。理由を返して止まる。

## 設計の説明

- A（人間の入力が要るところを run の境界にできる）: いいえ。項目を 1 つ書くたびに利用者の承認・修正・削除の答えを待ち、その答えで次に書く内容が変わる。人間の入力がほぼ全ての手順の間に挟まるので、Claude がターンごとに指揮する。
- Q1・Q2・Q3: A で形が決まったので問わない。

到達した形はターンごとの指揮。

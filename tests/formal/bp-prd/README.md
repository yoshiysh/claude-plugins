# BP 要求の有限状態モデル

この検査は `bp-designed-skill.md` と `bp-operations.md` の一部の要求を手動で抽象化した状態機械を、Python 3 で幅優先に全数探索する。PRD の本文からモデルを自動生成するものではない。

## 実行

リポジトリのルートで実行する。

```bash
python3 tests/formal/bp-prd/check_model.py
```

検査は、まずモデルに対応させた PRD の SHA-256 を `check_model.py` の `SNAPSHOT` と照合する。PRD が変わった場合は、対応関係を改めて検証してから SHA を更新する。正常モデルの結果と、変異ごとの反例を標準出力に JSON で出す。失敗は非ゼロで終了する。検査結果のファイルは作成しない。

## 対象と対応

| 要求 | モデルで検査する性質 |
|---|---|
| PR-BPDESIGNEDSKILL-025、027、PR-BPOPERATIONS-010 | 適用可能な検証が成功するまで完了せず、検証失敗時に停止する |
| PR-BPDESIGNEDSKILL-035 | 記録の保存失敗時に停止し、削除指示がない限り保存できた記録を保持する |
| PR-BPDESIGNEDSKILL-034、038 | 削除指示がない間、保存済みの旧・新記録を保持する |
| PR-BPDESIGNEDSKILL-030 | 各担当が共有台帳に直接書き込まない |

状態は、処理中・停止・完了、検証の未実施・成功・失敗、保存の未実施・成功・失敗、記録の有無（最大2件）、削除指示の有無、担当による共有台帳への直接書き込みの有無を持つ。初期状態から到達できる状態を列挙し、完了条件・失敗時の停止・保存済み記録の保持・台帳への書き込み禁止を検査する。

検証と保存の順序は固定せず、任意に成功・失敗しうる。保存は途中まで成功してから失敗する場合もある。少なくとも1つの性質が形式検証の対象となる場合を抽象化し、保存の結果は作業記録・証拠・台帳をまとめて扱う。

## 反例の検出

以下を一つずつ緩めた7種類のモデルが、それぞれ反例を返すことを確認する。

- 検証失敗時に停止しない。
- 保存失敗時に停止しない。
- 保存に成功したが検証が済んでいない状態で完了する。
- 検証に成功したが保存が済んでいない状態で完了する。
- 保存失敗時に保存済みの記録を破棄する。
- 削除指示なしに保存済み記録を削除する。
- 担当が共有台帳に直接書き込む。

正常モデルの遷移規則には要求を織り込んでいる。正常モデルの成功は、定義したモデルの整合性についての結果であり、実装や要求の正しさの独立した証明ではない。変異はこれらの違反を検出できることを示すが、書かれていない要求の漏れを検出するものではない。

## 検証できない範囲

- 自然言語の PRD からモデルへの翻訳の完全性・正しさ、要求自体が利用者の意図を満たすこと、実装がモデルに従うこと。
- 各記録・証拠・台帳の保存失敗の個別ケース、失敗の理由や範囲の報告、永続化と障害復旧、実行環境での実際の保持、参照先の整合性や正本の重複、各担当の識別と並行実行。
- 記録の上限を超えるケース、時間や公平性、進行性、各種外部障害。削除指示は対象ごとに区別せず、モデル内で記録が作成される前後の指示の効力の違いも検査しない。
- 形式化対象の洗い出しが網羅的であること、形式手法の選定、ユーザーの削除指示の認証、記録内容の意味の正しさ。

# 要求文書: formal-methods

本文書の要求の主語「formal-methods」は、形式手法を適用するスキル formal-methods（その SKILL.md・Workflow script・CLI・役の prompt・写し）を指す。「スキルの作り手」と「リポジトリの検証」を主語とする要求は、run の振る舞いではなく開発時の義務である。形式手法の原則は `docs/design/skill-design-patterns.md`（以下、設計方針文書）が正本であり、本文書は原則を節名で参照する。設計方針文書に無い原則は、本文書が正本である。本文書と設計方針文書が食い違うときは、設計方針文書を正として本文書を直す。ただし、項目・未着手・試行・打ち切り・対象の欠けは、本文書の用語の表の定義を正とする。

## 表記規約

本文書の要求文は次の語尾で区分する。

| 区分 | 語尾 | 対応する英語 |
|---|---|---|
| 必須 | 〜しなければならない | shall / MUST |
| 推奨 | 〜することが望ましい | should / SHOULD |
| 許容 | 〜してもよい | may / MAY |
| 禁止 | 〜してはならない | shall not / MUST NOT |

## 背景と課題

要求に誤りがあれば、その要求から起こした仕様も、仕様から作った実装も誤る。誤りは上流にあるほど下流へ増幅されてから見つかり、手戻りの費用が大きい。

要求どうしの矛盾には、状態機械ではなく関係の矛盾がある。例えば、ある性質を確かめよと求めながら、直す手段を書き換えてよい範囲の外に置く矛盾である。状態モデルだけを作る選び方では、これを素通りする。また、1 つの状態の規則が文書の複数の節に散っていると、節ごとに直しても継ぎ目で食い違い続け、部分修正が収束しない。

規範文の組の照合は関係の矛盾を安く拾えるが、組の対象を実体まで具体化しないと当たらない欠け、同じ名前の定義が複数あるときの同一性の欠け、停止の種類ごとの義務の範囲の欠けは、組を照らす型を足さないと拾えない。既にあるモデルは、恒真の性質や文書に無い制約で文書の欠けを隠すことがあり、モデルを作る手順とは別に、モデルの妥当性を確かめる手順が要る。

形式検証は対象を広げるほど状態と経路が増える。そこで、安い軽い検査は毎回回し、高い重い検査は要求が安定してから行う。

## 想定する利用者と利用場面

| 利用者 | 利用場面 |
|---|---|
| 利用者 | 要求文書を formal-methods に単独で渡し、欠けを受け取る |
| best-practices | 対象スキルの性質の洗い出しと形式検証を、formal-methods のスキル呼び出しで行う |
| prd-spec | 書いた要求文書・仕様書を formal-methods のスキル呼び出しで検査し、返された欠けを自分の改稿へ回す |
| モデルの持ち主 | 自分や他の run が作った要求の層か仕様の層のモデルを formal-methods の audit にかけ、モデルの欠けと、モデルを通して見えた文書の欠けを受け取る |
| スキルの作り手・リポジトリの検証 | formal-methods 自身に formal-methods を当て、写しの一致を確かめる |

## どう使われるか

1. 呼び出し側か利用者が、検査対象とその文書の層、行う機能（作る機能か audit）、あれば上流とその文書の層・書いてよい先・手法の指定を渡して formal-methods を起動する。
2. formal-methods は、入口の step で入力を確かめ、検査対象の全体に軽い検査を回す。規範文を組に分解し、組の対象を実体まで具体化し、組を型に照らす。
3. 要求と仕様の層では、formal-methods は単位を切り、並列・階層・継ぎ目・循環を確かめる。仕様の層で上流に要求文書があれば、縦の対応も確かめる。
4. 要求が安定していれば、作る機能は重い検査を行う。
5. formal-methods は、範囲と限界を記録し、見つけた欠けを返り値で返す。
6. 呼び出し側か利用者は、差し戻し先に従って検査対象か上流を直し、next_args を付けずに formal-methods を起動し直す。起動の同一性が変わるので、新しい状態から始まる。
7. 既にモデルがあるときは、呼び出し側か利用者がモデルと検査対象と上流を渡して audit を起動する。

## スコープとスコープ外

スコープ: 入口（入力の確かめ・文書の層の受け取り・差し込み口）、軽い検査、単位・並列・階層・2 つの軸・継ぎ目・循環、費用の 2 段、性質の洗い出し、手法と道具、モデルの作成と忠実さ、検査と検出力、audit、欠けの帰属と返し方、範囲と限界の記録、停止・続きからの起動・完了、役の分担、原則と文書の一般規約の写し、formal-methods 自身への開発時の適用。

スコープ外:
- コードの層の、単位を切る材料を作る部分の中身。差し込み口だけを定める（PR-FORMALMETHODS-045）。
- 形式手法の原則そのもの、best-practices の要求と仕様の内容、道具の内部仕様。
- 検査対象と上流の修正（呼び出し側か利用者が行う）。
- 他のスキルの呼び出しと、人の答えを待つこと。
- プログラムの契約と定理証明（PR-FORMALMETHODS-108）。
- 起動の同一性の違う run の欠けどうしを結び付ける追跡と収束の判定（PR-FORMALMETHODS-172 の保持規則）。
- 設計方針文書の「体数と同時実行」の節の原則のうち、取り込みの表の起動数の上限の要求に含まれないもの。同時に走る agent の数の上限は host と呼び出し側が持ち、formal-methods が 1 run の起動数の総数のほかに上限を置くと、呼び出し側の上限と二重になる。
- 形式手法を使わない通常の実装・レビュー・文書作成。

## 要求一覧

### 位置づけ

#### PR-FORMALMETHODS-001 単独でも呼び出しでも同じ形で動く
formal-methods は、利用者が単独で起動したときも、呼び出し側がスキル呼び出しで起動したときも、同じ形の入力を受け、同じ形の返り値を返さなければならない（呼ばれ方で形が分かれると、片方の経路だけが検証から漏れる）。

#### PR-FORMALMETHODS-002 他のスキルを呼ばない
formal-methods は、他のスキルを呼んではならない（呼ぶと prd-spec → formal-methods → prd-spec のように呼び出しが循環しうるうえ、上流の欠けを誰が直すかが呼び出し側から見えなくなる）。

#### PR-FORMALMETHODS-003 書き換えてよい範囲
formal-methods は、作業場所（取得した道具の置き場を含む）・記録台帳の置き場と、作る機能では入力で渡された書いてよい先の外を書き換えてはならない（検査対象と上流とモデルは呼び出し側の成果物であり、formal-methods が直すと、確かめた結果と直した結果が混ざり、呼び出し側の検証を通らない変更が成果物に入る）。

#### PR-FORMALMETHODS-004 作業場所の位置
formal-methods は、next_args の無い run の作業場所の位置を、起動の同一性だけから作る鍵と自分の決まった規則から決定的に決めなければならない（run ごとに agent が置き場を選ぶと、続きから起動した run と呼び出し側が状態と記録を見つけられず、起動の同一性が違う起動と状態を取り違える）。

#### PR-FORMALMETHODS-005 記録台帳の置き場
formal-methods は、記録台帳の置き場を、作業場所の外に、入力と自分の決まった規則から決定的に決めなければならない（記録台帳を状態ごとの作業場所に置くと、状態と run をまたいで作業記録を辿れない）。

#### PR-FORMALMETHODS-296 記録台帳への書き込みを並べる
formal-methods の CLI は、記録台帳の置き場への書き込みを、起動の同一性の違う run の間でも 1 つに並べなければならない（記録台帳の置き場は起動の同一性によらず決まるので、並べないと同時に走る run の書き込みが交ざる）。

#### PR-FORMALMETHODS-006 下流で上流の穴を埋めない
formal-methods は、下流の文書の層の検査で見つけた上流の欠けについて、下流の側で補う直し方を、直し方の候補と差し戻し先にしてはならない（下流が上流の穴を埋めると、上流の誤りが残ったまま別の下流で同じ穴が開く）。

### 2 つの機能

#### PR-FORMALMETHODS-007 作る機能と audit
formal-methods は、作る機能と audit の 2 つの機能を持たなければならない（作る手順だけでは、作り手の違う既存のモデルの空振りや文書に無い制約を確かめられない）。

#### PR-FORMALMETHODS-008 確かめる中身の正本を 1 つにする
作る機能は、作ったモデルの忠実さ・検査・検出力を、PR-FORMALMETHODS-127〜PR-FORMALMETHODS-135 と PR-FORMALMETHODS-212〜PR-FORMALMETHODS-217 で確かめなければならない（同じ確かめを作る機能と audit の 2 か所の規則で持つと食い違う）。

#### PR-FORMALMETHODS-009 機能を入力から決める
formal-methods は、run で行う機能を、入力の機能の指定から決めなければならない（agent の判断で決めると、同じ入力で run ごとに機能が揺れる）。

### 人の入力

#### PR-FORMALMETHODS-011 人の答えを待たない
formal-methods は、人の答えを待って止まってはならない（人を待つ経路を持つと、他のスキルから呼ばれた run が人の不在で止まる）。

#### PR-FORMALMETHODS-012 needs_input を使わない
formal-methods は、停止の種類のうち needs_input を使ってはならない（needs_input は人の答えを待つ停止であり、使うと PR-FORMALMETHODS-011 を守れない）。

#### PR-FORMALMETHODS-013 判断が要るものは欠けとして返す
formal-methods は、検査対象・上流の解釈のうち、本文書・既定値の表・本文書が定める役の判断と検証の手順のどれでも決まらないものを、全て欠けとして返り値で返さなければならない（返さずに agent が決めると、決めた根拠が残らず、呼び出し側が判断の要る点を知る経路が無い）。

#### PR-FORMALMETHODS-014 自分の判断は既定値の表で決める
有限範囲と抽象化が入力でもヒントでも指定されていないとき、formal-methods は、それらを既定値の表で決めなければならない（有限範囲と抽象化は手法の選び方の一部であり、欠けとして返すと、重い検査の全ての run が判断待ちの欠けで終わる）。

#### PR-FORMALMETHODS-016 入力の指定を優先する
手法・有限範囲・抽象化が入力で指定されたとき、formal-methods は、その指定を、呼び出し側が運ぶ利用者の指示として既定値の表より優先しなければならない（利用者の指示より既定値を優先すると、呼び出し側が範囲を絞った検査を頼めない）。

#### PR-FORMALMETHODS-293 有限範囲と抽象化を決める順
formal-methods は、有限範囲と抽象化の値を、入力の指定、ヒント、既定値の表の順に優先して決めなければならない（優先の順が 1 か所に無いと、入力とヒントが違う値を指すときに run ごとに値が揺れる）。

#### PR-FORMALMETHODS-017 人の入力はヒントとしてだけ受ける
formal-methods は、run の途中の人の入力をヒントとしてだけ受け取らなければならない（ヒント以外の経路で入力を受けると、入力を待つ経路ができる）。

#### PR-FORMALMETHODS-018 ヒントを読む役
formal-methods は、ヒントを読む役を、設計方針文書の「停止・再開と人間の入力」の節の待たれない入力の定め（段を step と読む）に従って決めなければならない（読む役が決まっていないと、足したヒントが誰にも読まれない）。

#### PR-FORMALMETHODS-019 ヒントが効く範囲
formal-methods は、ヒントを、既定値の表で決める値と、ヒントを読んだ役の判断の材料に効かせなければならない（ヒントの効く範囲が決まっていないと、同じヒントで run ごとに振る舞いが揺れる）。

#### PR-FORMALMETHODS-020 ヒントで止まらない
formal-methods は、ヒントについて、設計方針文書の「停止・再開と人間の入力」の節の待たれない入力の定めのうち run を止めない部分に従わなければならない（ヒントで止まると、人を待たない run が人の入力で止まる）。

### 原則と文書の一般規約の写し

#### PR-FORMALMETHODS-021 規則の出所は写し
formal-methods は、run の手順・表・規則の出所として使う設計方針文書の原則と文書の一般規約を、スキルのディレクトリの写しから読まなければならない（install 先に `docs/` は届かず、run の中で正本を読む経路が無い）。

#### PR-FORMALMETHODS-022 規則の出所として docs/ を読まない
formal-methods は、run の手順・表・規則の出所としてリポジトリの `docs/` を読んではならない（呼ばれた先で `docs/` が無いか正本と写しの版が違うと、run の振る舞いが置き場で変わる）。

#### PR-FORMALMETHODS-023 検査の材料は入力だけ
formal-methods は、検査の材料として、入力の集合の検査対象・上流・モデル・`.tbd.json` だけを読まなければならない（写しや探して見つけた文書を検査の材料にすると、どの版の文書に照らした結果かが入力から決まらず、欠けの位置が呼び出し側の知らない文書を指す）。

#### PR-FORMALMETHODS-024 原則を言い換えて写さない
スキルの作り手は、自分の文書に、設計方針文書の原則、文書の一般規約、best-practices の要求文書と仕様書の文を言い換えて写してはならない（言い換えた写しは正本とずれても気づけない）。

#### PR-FORMALMETHODS-025 正本を節名で参照する
スキルの作り手は、自分の文書で設計方針文書の原則と文書の一般規約に拠るとき、正本か写しを節名で参照しなければならない（節名が無いと、どの原則に拠ったかを正本と照らせない）。

#### PR-FORMALMETHODS-026 写しは正本の commit から作る
スキルの作り手は、写しを、正本の commit の内容から作らなければならない（commit していない改稿を写すと、写しの版が正本のどの版にも当たらず、照らす先が無くなる）。

#### PR-FORMALMETHODS-027 写しの中身の一致を確かめる
リポジトリの検証は、formal-methods の写しが正本と 1 字も違わないことを `make test` で確かめなければならない（一致を確かめない写しは、正本とずれたまま配られる）。

#### PR-FORMALMETHODS-028 写しの版の一致を確かめる
リポジトリの検証は、写しに伴う版が正本の commit と一致することを `make test` で確かめなければならない（版の記録が合わないと、作業記録に残した版から正本を特定できない）。

### 機械で確かめる原則

#### PR-FORMALMETHODS-029 機械で確かめる原則を満たす
formal-methods は、設計方針文書の「機械で確かめる」の節の原則のうち、既存のテストを性質に変換する原則と、要求 ID・仕様 ID の網羅の原則を除くものを満たさなければならない（同節の原則を外れると、検証済みの範囲と確かめていない残りの境界が引けない）。

#### PR-FORMALMETHODS-297 既存のテストを性質に変換する
スキルの作り手は、設計方針文書の「機械で確かめる」の節の、既存のテストを性質に変換する原則を、formal-methods 自身のテストに当てなければならない（run には変換するテストが無く、開発時に当てないとこの原則の持ち主がいない）。

#### PR-FORMALMETHODS-298 要求 ID と仕様 ID の網羅を確かめる
リポジトリの検証は、設計方針文書の「機械で確かめる」の節の、要求 ID・仕様 ID の網羅の原則を、本文書と `docs/specifications/formal-methods.md` に当てなければならない（run は自分の要求と仕様を入力に受けないので、開発時に当てないと網羅の抜けが見えない）。

### best-practices の形

#### PR-FORMALMETHODS-030 停止と再開
formal-methods は、状態に書かずに止まる run を除き、取り込みの表の「停止と再開」の行の要求を満たさなければならない（止まった run の理由と未着手が残らないと、続きからの起動で最初からやり直すことになる）。

#### PR-FORMALMETHODS-031 待たれる入力の原則に従わない
formal-methods は、PR-FORMALMETHODS-030 の要求が拠る設計方針文書の「停止・再開と人間の入力」の節のうち、needs_input と待たれる入力に関わる部分（待たれる入力の行、needs_input で止めるときの材料の行、「完了以外の停止からは再開できる」の行の needs_input の部分）に従ってはならない（従うと PR-FORMALMETHODS-011 と食い違う）。

#### PR-FORMALMETHODS-236 対象の欠けを直した後の起動
対象の欠けによる BLOCKED の後に、呼び出し側が原因を直して起動し直したとき、formal-methods は、その起動を、設計方針文書の「停止・再開と人間の入力」の節の「完了以外の停止からは再開できる」の行の、run の外の主体が対象を直して run の入力（中身を含む）が変わる形として扱わなければならない（前の状態の続きとして扱うと、直す前の対象に基づく結果と欠けが、直した対象の結果として返る）。

#### PR-FORMALMETHODS-032 停止の種類
formal-methods は、停止の種類を、完了・反復の上限・BLOCKED のいずれかとしなければならない（使う停止の種類が閉じていないと、停止ごとに残すもの（PR-FORMALMETHODS-175）を網羅できない）。

#### PR-FORMALMETHODS-033 BLOCKED の理由の区分
formal-methods は、BLOCKED の返り値に、設計方針文書の「停止・再開と人間の入力」の節が定める理由の区分を、PR-FORMALMETHODS-175 の表の区分の列のとおりに付けなければならない（区分が無いと、呼び出し側が環境と入力を直すのか文書を直すのかを決められない）。

#### PR-FORMALMETHODS-034 状態の書き込み
formal-methods は、取り込みの表の「状態の書き込み」の行の要求を満たさなければならない（組・単位・欠けを役が状態へ直接書くと、検証役を通らない組と欠けが状態に入り、続きからの起動がそれを終えた step の結果として使う）。

#### PR-FORMALMETHODS-035 run の記録
formal-methods は、取り込みの表の「run の記録」の行の要求を満たさなければならない（作業記録が無いと、返した欠けと帰属が、どの step のどの組・単位から出たかを後から辿れない）。

#### PR-FORMALMETHODS-036 役ごとの agent のモデルと effort
formal-methods は、取り込みの表の「役ごとの agent のモデルと effort」の行の要求を満たさなければならない（指定しないと、組の抽出や照合のような機械的な役もセッションのモデルで走り、毎回回す軽い検査の費用が膨らむ）。

#### PR-FORMALMETHODS-037 起動数の上限
formal-methods は、取り込みの表の「起動数の上限」の行の要求を満たさなければならない（上限を受け取らないと、Codex runner の上で run 全体が失敗する）。

formal-methods は、言い換えた文を組の要素にしてはならない（言い換えた転記は正本から drift し、捏造が混ざる）。

formal-methods は、組を、1 つの抽出の出力だけで確定させてはならない（1 回の選択の誤りは、偽の欠けにも見落としにもなり、run の結論を変える）。

formal-methods は、独立に作った抽出の間の食い違いを、抽出した役と別の検証役に決めさせなければならない（抽出した役が自分で決めると、同じ読み違いを通す）。

#### PR-FORMALMETHODS-056 展開できない参照
規範文が参照する文書か、その文書の参照した節・行が入力の上流に無いならば、状態に書いて止まる run と完了する run で、formal-methods は、展開していない参照を対象外として範囲と限界の記録に書かなければならない（書かないと、展開していない参照の中の欠けが無いと読まれる）。

仕様の層の検査対象では、formal-methods は、上流の要求文書の規範文を、PR-FORMALMETHODS-055 で展開した参照先に限って組にしなければならない（要求どうしの整合は要求の層の run で確かめるものであり、上流の要求文書の全体に軽い検査を回すと、要求の層の run と同じ検査に費用を重ねる）。

formal-methods は、用語の表の語にも本文で定義した語にも結びつけられない語を欠けとして返さなければならない（agent が意味を補って結びつけると、用語の欠けが文書に残る）。

formal-methods は、PR-FORMALMETHODS-053・PR-FORMALMETHODS-054 で確定した全ての組を、次の型の全てに照らさなければならない（型を選んで照らすと、照らさなかった型の欠けが「無い」と読まれる）。

PR-FORMALMETHODS-054 で確定しなかった組を、状態に書いて止まる run と完了する run で、formal-methods は、型に照らさなかった対象外として範囲と限界の記録に書かなければならない（書かないと、照らさなかった組の欠けが無いと読まれる）。

判定の表が検査対象に表として無いとき、formal-methods は、組の条件の欄から組み立てた判定の表に AI の判断の印を付けなければならない（印が無いと、文書の表と AI が組み立てた表が区別できない）。

### 単位

#### PR-FORMALMETHODS-066 単位を前提にした確かめの範囲
formal-methods は、単位を前提にした確かめを、単位を切る材料を作る部分（要求の層は PR-FORMALMETHODS-068 の組の主体と組の対象、仕様の層は PR-FORMALMETHODS-224 の表の抜き出し、コードの層は PR-FORMALMETHODS-045 の差し込み口）を formal-methods が持つ文書の層の検査対象に限って行わなければならない（材料の無い層で単位を推測して切ると、根拠の無い単位の上の結果が欠けとして返る）。

#### PR-FORMALMETHODS-067 検査対象の状態の持ち主で区切る
formal-methods は、検査対象を、検査対象の状態の持ち主ごとの単位に区切らなければならない（持ち主で区切らないと、1 つの検査対象の状態を変える規則が複数の単位に割れ、単位ごとに確かめても状態の不変条件を確かめられない）。

#### PR-FORMALMETHODS-199 単位に持たせるもの
formal-methods は、根の単位を除く各単位に、自分だけが書き換える検査対象の状態・外からの操作・単位の契約を持たせなければならない（どれかが欠けた単位は、単位の契約だけで扱えず、階層と継ぎ目の確かめに使えない）。

#### PR-FORMALMETHODS-068 要求の層の単位の切り方
要求の層の検査対象では、formal-methods は、組を組の対象ごとに集め、組の対象を変える主体ごとに単位にしなければならない（要求の層には状態の定義が無く、組の主体と組の対象が状態の持ち主を示す唯一の材料である）。

#### PR-FORMALMETHODS-278 状態を変える主体の無い組
要求の層の検査対象で、組の対象を変える主体の無い組（例: 読むことの禁止、区切り方の禁止）があるならば、formal-methods は、その組を根の単位に入れなければならない（入れる単位が無いと、その組がどの単位の確かめにも現れない）。

#### PR-FORMALMETHODS-069 節で区切らない
formal-methods は、検査対象を文書の節で単位に区切ってはならない（1 つの状態の規則が複数の節に散ると、節ごとに直しても継ぎ目で食い違い続ける）。

#### PR-FORMALMETHODS-070 根の単位
formal-methods は、検査対象の全体を根の単位としなければならない（根の単位が無いと、いちばん上の単位どうしを合成した全体の確かめに持ち主がいない）。

#### PR-FORMALMETHODS-200 根の単位に継ぎ目を持たせる
formal-methods は、いちばん上の単位どうしをまたぐ継ぎ目を、根の単位に持たせなければならない（根の単位に持たせないと、いちばん上の単位どうしの継ぎ目に持ち主がいない）。

#### PR-FORMALMETHODS-071 要求の層の契約
要求の層の検査対象では、formal-methods は、単位の契約を、その単位の組の条件と例外の否定を仮定、義務と禁止を保証として読んで作らなければならない（要求の層には規範文のほかに単位の契約の材料が無い）。

#### PR-FORMALMETHODS-072 仕様の層の契約
仕様の層の検査対象では、formal-methods は、単位の契約を、PR-FORMALMETHODS-224 で抜き出した事前・事後・不変の条件の表から検査器の式に写して作らなければならない（手で式を書くと、文書の条件から離れた式で単位の契約を確かめることになる）。

#### PR-FORMALMETHODS-201 単位の契約の表と式を照らす
formal-methods は、PR-FORMALMETHODS-224 で抜き出した条件の表と PR-FORMALMETHODS-072 で写した式の一致を機械で照らさなければならない（照らさないと、文書の条件と式の食い違いを確かめる手段が無い）。

#### PR-FORMALMETHODS-073 単位を切った後に照らす型
formal-methods は、単位を切った後に、単位と継ぎ目を次の型に照らさなければならない（これらの型は単位が持つ検査対象の状態と継ぎ目を材料にするので、組だけでは当てられない）。

| 型 | 当たる条件 |
|---|---|
| coverage-gap | 単位が持つ検査対象の状態と、検査対象か上流が定める、停止・再開・拒否の種類の組み合わせのうち、義務か担い手が無い組み合わせがある |
| missing-external-contract | 外の主体（例: host・利用者・呼び出し側）の契約が規範文に無く、継ぎ目を照らす相手がいない |

#### PR-FORMALMETHODS-239 停止・再開・拒否の種類が無いとき
検査対象か上流が定める停止・再開・拒否の種類のうち定めの無い種類があるとき、状態に書いて止まる run と完了する run で、formal-methods は、その種類の組み合わせを coverage-gap に照らさず、対象外として範囲と限界の記録に書かなければならない（種類の閉集合が無いまま照らすと、agent が種類を補って偽の欠けを返す）。

#### PR-FORMALMETHODS-074 外の主体の契約を仮定にする
missing-external-contract に当たる継ぎ目について、外の主体の契約を検査対象か上流の文で示せるとき、状態に書いて止まる run と完了する run で、formal-methods は、その文を引いた仮定として範囲と限界の記録に書かなければならない（出所のある契約を欠けとして返すと、文書に書かれた前提まで直す対象になる）。

#### PR-FORMALMETHODS-075 示せない外の契約を欠けにする
missing-external-contract に当たる継ぎ目について、外の主体の契約を検査対象か上流の文で示せないとき、formal-methods は、その継ぎ目を欠けとして返さなければならない（出所の無い仮定を置くことは agent の判断であり、PR-FORMALMETHODS-013 により欠けとして返す対象になる）。

### 並列

#### PR-FORMALMETHODS-076 書き手を並べる仕組み
1 つの検査対象の状態を 2 つ以上の主体が変えるならば、formal-methods は、書き手を 1 つに並べる仕組み（ロック・CLI・キュー）が検査対象か上流にあるかを確かめなければならない（並べる仕組みの有無で、単位を 1 つとして扱えるかが決まる）。

#### PR-FORMALMETHODS-077 並べる仕組みがあるとき
書き手を並べる仕組みがあるならば、formal-methods は、その検査対象の状態を変える主体を 1 つの単位としなければならない（仕組みがあるのに単位を分けると、仕組みが保証する順序を継ぎ目で確かめ直すことになる）。

#### PR-FORMALMETHODS-202 並列を交ざり方として確かめる
書き手を並べる仕組みがあるならば、formal-methods は、並列を、呼ばれる順の交ざり方として確かめなければならない（交ざり方を確かめないと、並べる仕組みが順序を保証することを確かめないままになる）。

#### PR-FORMALMETHODS-078 並べる仕組みが無いとき
書き手を並べる仕組みが無いならば、formal-methods は、その検査対象の状態を変える単位をまとめて 1 つの単位にして確かめなければならない（分けたまま確かめると、書き込みの交ざり方で変わる結果が単位ごとの検査に現れない）。

#### PR-FORMALMETHODS-203 並べる仕組みが無いことを返す
書き手を並べる仕組みが無いならば、formal-methods は、並べる仕組みが無いことを、並べる仕組みの無さの欠けとして返さなければならない（並べる仕組みの無い並列は、書き込みの交ざり方で結果が変わる）。

### 階層

#### PR-FORMALMETHODS-079 下の単位を単位の契約だけで扱う
formal-methods は、単位の階層を、上の単位が下の単位を単位の契約だけで扱うという規則で作らなければならない（上の単位が下の単位の中身に頼ると、下の単位を変えるたびに上の単位を確かめ直すことになる）。

#### PR-FORMALMETHODS-080 階層の深さを決め打ちしない
formal-methods は、階層の深さを決め打ちしてはならない（深さを決め打ちすると、検査対象の構造ではなく決めた深さに合わせて単位を切ることになる）。

#### PR-FORMALMETHODS-081 使う関係を階層に乗せる
formal-methods は、使う関係を階層の規則に乗せなければならない（使う関係を階層に乗せないと、上の単位が下の単位を単位の契約だけで扱えない）。

#### PR-FORMALMETHODS-204 作る関係を別の木にする
formal-methods は、作る関係を、階層の規則に乗せずに別の木にしなければならない（作る関係を階層の規則に乗せると、作る側と作られる側のどちらが上かが決まらない）。

#### PR-FORMALMETHODS-255 作る関係を縦の検査で確かめる
formal-methods は、作る関係を、作られた物を下の文書の層とみなして PR-FORMALMETHODS-083〜PR-FORMALMETHODS-085・PR-FORMALMETHODS-089 を当てて確かめなければならない（確かめないと、作られた物が要求を満たすかがどの検査にも現れない）。

#### PR-FORMALMETHODS-283 作られた物が入力に無いとき
作られた物が入力に無いとき、状態に書いて止まる run と完了する run で、formal-methods は、作る関係の照合を対象外として範囲と限界の記録に書かなければならない（書かないと、照合していない作る関係が照合したものと読まれる）。

### 2 つの軸

#### PR-FORMALMETHODS-082 横と縦を分けて確かめる
formal-methods は、横の合成と縦の詳細化を分けて確かめなければならない（2 つの軸を混ぜると、欠けが合成の欠けか詳細化の欠けかが決まらず、差し戻し先の文書の層を示せない）。

#### PR-FORMALMETHODS-205 縦の検査の始まり
formal-methods は、縦の検査を要求と仕様の間から始めなければならない（上の層の誤りを残したまま下の層の詳細化を確かめると、誤った要求に合わせた仕様が通る）。

#### PR-FORMALMETHODS-083 縦の対応を表で結ぶ
formal-methods は、縦の対応を、トレーサビリティ表から機械で結ばなければならない（agent が対応を読み取ると、run ごとに対応が揺れる）。

#### PR-FORMALMETHODS-084 結べない縦の対応
トレーサビリティ表で結べない縦の対応があるならば、formal-methods は、agent が補った対応に AI の判断の印を付けなければならない（印が無いと、表で結んだ対応と agent が補った対応が区別できない）。

#### PR-FORMALMETHODS-206 補った縦の対応を確かめる
formal-methods は、AI の判断の印を付けた縦の対応を、補った役と別の検証役に確かめさせなければならない（補った役が自分で確かめると、同じ読み違いを通す）。

#### PR-FORMALMETHODS-085 表の欠けを返す
トレーサビリティ表に欠けがあるならば、formal-methods は、その欠けを欠けとして返さなければならない（agent が補ったことで表の欠けを消すと、表を直す経路が無くなる）。

### 継ぎ目

#### PR-FORMALMETHODS-086 横の継ぎ目を機械で拾う
formal-methods は、同じ組の対象を共有する組のうち 2 つ以上の単位にまたがるものを、横の継ぎ目として機械で拾わなければならない（agent が継ぎ目を選ぶと、run ごとに継ぎ目が揺れる）。

#### PR-FORMALMETHODS-087 参照の連鎖と名前だけの転記を拾わない
formal-methods は、参照の連鎖と名前だけが同じ転記を継ぎ目として拾ってはならない（参照の連鎖と名前の一致まで拾うと、継ぎ目が多すぎ、意味の無いものが混ざる）。

#### PR-FORMALMETHODS-284 継ぎ目にする組の対象の同一性
formal-methods は、PR-FORMALMETHODS-086 の横の継ぎ目を、PR-FORMALMETHODS-059 で具体化し PR-FORMALMETHODS-060 で同じ実体と決まった組の対象を共有する組に限らなければならない（名前が同じで実体の違う組まで拾うと、名前だけの転記が継ぎ目に入る）。

#### PR-FORMALMETHODS-088 横の継ぎ目を単位の契約で確かめる
formal-methods は、横の継ぎ目を、下の単位が仮定のもとで保証を満たし、上の単位がその保証だけに頼ることの検査で確かめなければならない（単位の契約に無い相互作用に頼る合成は、単位ごとの検査で保証されない）。

#### PR-FORMALMETHODS-089 縦の継ぎ目を詳細化で確かめる
formal-methods は、縦の継ぎ目を、下の文書の層が上の文書の層を詳細化していることの検査で確かめなければならない（縦の継ぎ目を単位の契約で確かめると、上の層に無い振る舞いを下の層が足しても見つからない）。

#### PR-FORMALMETHODS-282 重い検査を行わない run の継ぎ目と並列
重い検査を行わない run で、formal-methods は、PR-FORMALMETHODS-088・PR-FORMALMETHODS-089・PR-FORMALMETHODS-202 の確かめを、PR-FORMALMETHODS-071・PR-FORMALMETHODS-072 の単位の契約の組の照合で行わなければならない（手段が決まらないと、重い検査を行わない run でこれらの確かめが回らないか、run ごとに手段が揺れる）。

#### PR-FORMALMETHODS-090 継ぎ目の持ち主
formal-methods は、横の継ぎ目を、その継ぎ目がまたぐ全ての単位を含む、いちばん近い上の単位で持たなければならない（持ち主の無い継ぎ目は、どの単位の検査でも確かめられない）。

#### PR-FORMALMETHODS-091 全体の保証に読み替えない
formal-methods は、単位ごとに確かめた保証を、継ぎ目を確かめずに合成した全体の保証に読み替えてはならない（合成の費用は消えず継ぎ目へ移る）。

### 循環

#### PR-FORMALMETHODS-092 終端条件のある循環
単位の間の依存が循環し、終端条件を確かめられたならば、formal-methods は、循環する単位を分けたまま確かめなければならない（終わることが確かめられた循環をまとめると、単位が大きくなり重い検査の費用が増える）。

#### PR-FORMALMETHODS-093 終端条件を確かめられない循環
単位の間の依存が循環し、終端条件を確かめられないならば、formal-methods は、循環する単位をまとめて 1 つの単位にして確かめなければならない（分けたまま確かめると、終わるかどうかに依る性質を単位ごとの検査で確かめたことになる）。

#### PR-FORMALMETHODS-094 終端条件を確かめられないことを欠けにしない
formal-methods は、終端条件を確かめられないことを欠けとして返してはならない（終端条件を書かない循環は正常な設計にもあり、欠けとして返すと偽の欠けが増える）。

#### PR-FORMALMETHODS-095 終わらない経路
循環に終わらない経路が見つかったならば、formal-methods は、その経路を「いずれ終わる」の違反の欠けとして返さなければならない（終わらない経路は、run が止まらない設計の誤りである）。

### 費用の 2 段

#### PR-FORMALMETHODS-096 重い検査は要求が安定してから
重い検査の要否が入力で指定されていないとき、作る機能は、PR-FORMALMETHODS-100 で要求が安定していると判定し、重い検査の候補が 1 件以上あるならば、PR-FORMALMETHODS-104 で全ての候補を費用で外したときを除き、重い検査を行わなければならない（PR-FORMALMETHODS-100 で安定と判定した要求に重い検査を行わないと、状態と経路の欠けが下流まで残る）。

#### PR-FORMALMETHODS-240 要求が安定していないときは重い検査を行わない
重い検査の要否が入力で指定されていないとき、作る機能は、PR-FORMALMETHODS-100 で要求が安定していないと判定したならば、重い検査を行ってはならない（変わる前提の要求を状態モデルで固めると、変更のたびにモデルごと捨てる費用が出る）。

#### PR-FORMALMETHODS-097 重い検査の要否の指定
重い検査の要否が入力で指定されたとき、作る機能は、その指定を、呼び出し側が運ぶ利用者の指示として PR-FORMALMETHODS-096・PR-FORMALMETHODS-240 の判定より優先しなければならない（利用者の指示より判定を優先すると、呼び出し側が安定の前に重い検査を頼めない）。

#### PR-FORMALMETHODS-098 保留を記録する
要求が安定していないか、PR-FORMALMETHODS-097 で不要と指定されたか、PR-FORMALMETHODS-104 で全ての候補を費用で外したために作る機能が重い検査を行わないとき、formal-methods は、行わなかった重い検査を保留として、返り値と、状態に書いて止まる run と完了する run では範囲と限界の記録に載せなければならない（載せないと、候補が 0 件のときも含め、重い検査をしていない run が重い検査を通ったと読まれ、安定するか指定が変わった後に重い検査をやり直す理由が残らない）。

#### PR-FORMALMETHODS-241 保留にした候補を名指しする
PR-FORMALMETHODS-098 で保留を載せるときに重い検査の候補が 1 件以上あるならば、formal-methods は、保留にした候補を名指ししなければならない（名指しが無いと、どの候補に重い検査をやり直すかが後から決まらない）。

#### PR-FORMALMETHODS-099 保留のまま完了してよい
作る機能は、保留を範囲と限界の記録に載せたうえで完了してもよい（重い検査は要求が安定してから行うので、安定の前の run を完了させないと、軽い検査の結果を返せない）。

#### PR-FORMALMETHODS-100 安定の判定
formal-methods は、要求が安定しているかを、検査対象の軽い検査の欠け（PR-FORMALMETHODS-051〜PR-FORMALMETHODS-064・PR-FORMALMETHODS-196〜PR-FORMALMETHODS-198 で返す、PR-FORMALMETHODS-061 の型・PR-FORMALMETHODS-058・PR-FORMALMETHODS-063 の欠け）が 0 件であることと、PR-FORMALMETHODS-101 の文書の着手不能の未確定事項が 0 件であることから決定的に判定しなければならない（agent の印象で判定すると、run ごとに判定が揺れる）。

#### PR-FORMALMETHODS-101 安定の判定の範囲に入る文書
formal-methods は、PR-FORMALMETHODS-100 の範囲に入る文書を、検査対象が要求の層なら検査対象自身とし、仕様の層なら上流の要求文書（複数あるときはその全て）とし、上流に要求文書が無い仕様の層なら検査対象の仕様書自身としなければならない（範囲が決まらないと、同じ文書の組で run ごとに判定が揺れる）。

#### PR-FORMALMETHODS-102 着手不能の未確定事項の読み方
formal-methods は、着手不能の未確定事項を、スキルの作り手が自分の文書としてスキルのディレクトリに持つ、`docs/specifications/authoring.md` の未確定事項の形式に従う `.tbd.json` の読み方の規則で数えなければならない（`docs/` の規則で数えると、install 先で数え方が無い）。

#### PR-FORMALMETHODS-103 .tbd.json が無いとき
範囲に入る文書と同じ場所に `.tbd.json` が無いとき、formal-methods は、着手不能の未確定事項を 0 件として扱わなければならない（開いている未確定事項の無い文書は `.tbd.json` を持たないので、無いことを欠けとすると全ての確定した文書が安定と判定されない）。

#### PR-FORMALMETHODS-104 重い検査の範囲を費用で決める
重い検査の範囲を作る機能が決めるとき、作る機能は、重い検査の候補ごとの検証の費用を、その候補の誤りが下流で見つかった場合の手戻りの費用と比べて範囲に入れるかを決めなければならない（検証の費用だけを見ると、潰すべき誤りほど検証が高くつくという逆の結論になる）。

#### PR-FORMALMETHODS-242 要と指定された重い検査の候補を費用で外さない
PR-FORMALMETHODS-097 で重い検査を要と指定されたとき、作る機能は、PR-FORMALMETHODS-104 の比較の結果で重い検査の候補を範囲から外してはならない（費用で候補を外すと、利用者の指示で要とした重い検査が行われない）。

#### PR-FORMALMETHODS-207 費用の比べた結果を記録する
状態に書いて止まる run と完了する run で、作る機能は、PR-FORMALMETHODS-104 で比べた結果を範囲と限界の記録に書かなければならない（記録が無いと、範囲から外した候補をなぜ外したかが後から追えない）。

#### PR-FORMALMETHODS-243 費用で一部の候補を外したとき
PR-FORMALMETHODS-104 で一部の重い検査の候補を費用で外したとき、作る機能は、外した候補を PR-FORMALMETHODS-146 の確かめていない範囲に「対象外（理由：費用の比較）」として載せなければならない（載せないと、費用で外した候補が検証済みの範囲に入って読まれる）。

#### PR-FORMALMETHODS-244 費用で全ての候補を外したとき
PR-FORMALMETHODS-104 で全ての候補を費用で外したとき、作る機能は、PR-FORMALMETHODS-098 の保留の理由を「費用の比較」としなければならない（理由が無いと、要求が安定していないための保留と区別できず、費用の見積もりが変わったときにやり直す理由が残らない）。

#### PR-FORMALMETHODS-105 向かない部分を黙って外さない
状態に書いて止まる run と完了する run で、作る機能は、検査対象のうち重い検査に向かない部分（次の 2 つに限る：状態も関係の制約も持たない文面・書式の規範文、意味の妥当性そのものが問いの規範文）を、理由と回す先の確認方法をつけて対象外として範囲と限界の記録に書かなければならない（黙って外すと、形式化しなかったこと自体が後から追えない）。

#### PR-FORMALMETHODS-188 重い検査は単位を前提にする
作る機能は、要求と仕様の層で、重い検査を単位を前提にした重い検査として回さなければならない（単位ごとのモデルと継ぎ目の単位の契約に分けないと、PR-FORMALMETHODS-104 の費用の比較と PR-FORMALMETHODS-189 の優先づけを重い検査の候補ごとに行えない）。

#### PR-FORMALMETHODS-245 単位を切らない全体のモデルで重い検査を回さない
作る機能は、どの文書の層でも、単位を切らずに検査対象の全体を 1 つにしたモデルで重い検査を回してはならない（文書全体を 1 つのモデルにすると、状態の持ち主ごとの不変条件と継ぎ目を分けて確かめられず、モデルが大きくなって有限範囲が狭まる）。

#### PR-FORMALMETHODS-189 下流への依存の広がりで優先づける
重い検査の候補が複数あるとき、作る機能は、下流への依存の広がりが大きい候補から先に形式化しなければならない（PR-FORMALMETHODS-096・PR-FORMALMETHODS-240 で安定してから重い検査を行うので、候補の間では、依存の広がりが大きいものほど、誤りが下流で見つかったときの手戻りが大きい）。

### 手法と道具

#### PR-FORMALMETHODS-106 手法を性質の種別から引く
手法の指定が入力に無いとき、formal-methods は、性質の種別を鍵にしたスキルの中の手法の表から手法と道具を引かなければならない（その場の判断で選ぶと、run ごとに手法が揺れる）。

#### PR-FORMALMETHODS-285 指定された手法の道具
手法の指定が入力にあるとき、formal-methods は、手法の表からその手法の道具を引かなければならない（その場の判断で道具を選ぶと、同じ手法の指定で run ごとに道具が揺れる）。

#### PR-FORMALMETHODS-208 引いた手法の表の行を記録する
状態に書いて止まる run と完了する run で、formal-methods は、PR-FORMALMETHODS-106 で引いた手法の表の行を範囲と限界の記録に書かなければならない（記録が無いと、選んだ根拠が残らない）。

#### PR-FORMALMETHODS-107 Alloy は指定されたときだけ
作る機能は、Alloy を、呼び出し側か利用者が入力の手法の指定の値として指定したときに限って使わなければならない（指定の無い run で使うと、同じ性質の種別に 2 つの道具が当たり、run ごとに道具が揺れる）。

#### PR-FORMALMETHODS-286 audit の道具
audit は、入力のモデルが使う道具を、手法の指定とみなさなければならない（audit の道具はモデルが決めるので、手法の表から引き直すと渡されたモデルを回せない）。

#### PR-FORMALMETHODS-108 プログラムの契約と定理証明を見送る
状態に書いて止まる run と完了する run で、formal-methods は、プログラムの契約と定理証明の性質を、検査せずに見送りとして範囲と限界の記録に書かなければならない（検査しない性質を書かないと、その性質が検証済みの範囲に入って読まれる）。

#### PR-FORMALMETHODS-109 道具を固定した版で取得する
formal-methods は、道具を、固定した版の閉じた集合から run の中で自動で取得しなければならない（版が動く道具の結果は再実行で同じにならず、取得を利用者に頼むと人を待つ）。

#### PR-FORMALMETHODS-110 道具を照合してから使う
formal-methods は、取得した道具を、固定した版と照合してから使わなければならない（照合しない道具は、固定した版と同じものだと言えない）。

#### PR-FORMALMETHODS-111 道具を用意できないとき
道具の取得か照合の失敗が試行の上限まで続いたならば、PR-FORMALMETHODS-156 に当たる場合を除き、formal-methods は、別の手法に替えずに BLOCKED で止まらなければならない（黙って替えると、選んだ理由の無い手法で「検証済み」が出る）。

#### PR-FORMALMETHODS-112 許可が無いとき
formal-methods は、道具の取得に要る許可が無いことを、PR-FORMALMETHODS-111 の取得の失敗として扱わなければならない（許可を run の中で待つと、人を待つ）。

### モデルの作成と忠実さ

#### PR-FORMALMETHODS-113 文書から生成してから抽象化する
作る機能は、表・列挙・記録の鍵・用語の表・ID のように構造のある部分を、手で抽象化する前に検査対象と上流から機械で抜き出してモデルと検査の入力にしなければならない（手で写すと正本からずれる）。

#### PR-FORMALMETHODS-114 手で写した部分を記録する
作る機能は、モデルと検査の入力の各部分が、抜き出しから生成したものか手で写したものかを、手で写した理由とともにモデルに記録しなければならない（どこを手で写したかが分からないと、正本からずれうる箇所を絞れない）。

#### PR-FORMALMETHODS-115 丸めたものを記録する
状態に書いて止まる run と完了する run で、作る機能は、モデルで何を丸めたか（例: データの中身を有無に丸める、失敗理由を区分に丸める）を範囲と限界の記録に書かなければならない（丸めたものはモデルに現れないので、記録に残さないと検証の範囲から静かに消える）。

#### PR-FORMALMETHODS-116 有限範囲の切り方と根拠
作る機能は、有限範囲の切り方（要素数・反復回数・状態数の上限）とその根拠をモデルに記録しなければならない（記録が無いと、どの範囲で反例が無かったかが読めない）。

#### PR-FORMALMETHODS-209 届かない境界値を記録する
有限範囲の境界値が検査対象の下限・上限に届かないとき、作る機能は、その旨をモデルに記録しなければならない（届かない範囲で反例が無いことは、範囲の外の保証にならない）。

#### PR-FORMALMETHODS-117 前提と公平性を宣言する
作る機能は、モデルの前提と公平性の置き方をモデルの中で宣言しなければならない（宣言の無い前提は、検証済みの範囲の境界に現れない）。

#### PR-FORMALMETHODS-269 範囲と限界の記録からモデルを引く
状態に書いて止まる run と完了する run で、formal-methods は、範囲と限界の記録の前提と確かめた範囲に、PR-FORMALMETHODS-116・PR-FORMALMETHODS-209・PR-FORMALMETHODS-117 でモデルに書いたものを、写さずに参照として載せなければならない（モデルと記録の 2 か所に書くと、片方を直したときに食い違う）。

#### PR-FORMALMETHODS-118 環境の行動を自動と仮定しない
作る機能は、環境の行動（例: 利用者の入力、障害の回復）を自動的に起こると仮定してはならない（仮定すると、起きない行動に依る進行性が成り立って見える）。

#### PR-FORMALMETHODS-119 対応表を作る
作る機能は、検査対象の節・文書の項目と性質の対応表を作らなければならない（対応表が無いと、どの節をモデルが写したかが読めない）。

#### PR-FORMALMETHODS-210 対応表の全行を割り当てる
作る機能は、写した節の各行を、対応表で、対応する性質か、性質を割り当てない（理由つき）かのどちらかに割り当てなければならない（載らない行は、モデルの欠落か対象外の判断漏れか区別できない）。

#### PR-FORMALMETHODS-120 節の固定を作る
作る機能は、モデルに写した節の固定を作らなければならない（固定しないと、文書が変わってもモデルの検査が古い文書のまま通る）。

#### PR-FORMALMETHODS-121 起動の途中で入力が変わったとき
起動の途中で入力の集合のファイルの指紋が変わったならば、formal-methods は、BLOCKED で止まらなければならない（起動の同一性は起動の時の入力の集合で決まるので、変わった内容で続けると、状態の起動の同一性と確かめた内容が食い違う）。

#### PR-FORMALMETHODS-264 入力の指紋を step ごとに照らす
formal-methods は、入力の集合のファイルの指紋を、少なくとも step ごとに、起動の同一性に含まれる入力の集合の指紋と照らさなければならない（照らさないと、起動の途中で入力が変わっても PR-FORMALMETHODS-121 に当たらないまま、変わった内容で run が続く）。

#### PR-FORMALMETHODS-294 照らす時点の間に戻った入力
状態に書いて止まる run と完了する run で、formal-methods は、PR-FORMALMETHODS-264 で照らす時点の間に変わって元に戻った入力を見分けられないことを、既知の限界として範囲と限界の記録に書かなければならない（書かないと、照らす時点の間の変化まで確かめたと読まれる）。

#### PR-FORMALMETHODS-256 入力が変わって止まった step をやり直す
PR-FORMALMETHODS-121 で止まった状態の続きから始めたならば、formal-methods は、止まった step を、その step で状態に書いた項目の結果と欠け、作業場所に書いた作業ファイルと作りかけのモデル、その step で行ったモデルの修正の回の結果を使わずにやり直さなければならない（入力が途中で変わった run の結果と欠けは、どの中身に基づくものかが定まらない）。

#### PR-FORMALMETHODS-271 やり直す step で累計を戻さない
PR-FORMALMETHODS-256 で step をやり直すとき、formal-methods は、モデルの修正の回数と試行の回数の累計を戻してはならない（戻すと、入力を変えては戻す起動のたびに上限が効かなくなる）。

#### PR-FORMALMETHODS-122 忠実さの層ごとに写したかを宣言する
作る機能は、モデルについて、忠実さの層ごとに「写した」か「写していない（理由）」をモデルの中で宣言しなければならない（節を写したことだけを見ると、写していない忠実さの層の欠けがモデルの検査に現れない）。

#### PR-FORMALMETHODS-123 写した忠実さの層の間を照らす
作る機能は、写した忠実さの層の対について、層の間で同じものを指す要素（例: 記録の鍵と操作の欄、判定の表の行き先と遷移の行き先）が食い違わないことを機械で照らさなければならない（層ごとに写しても、層の間の食い違いは各層の検査に現れない）。

#### PR-FORMALMETHODS-124 状態の投影を導出する
作る機能は、検査対象の状態の遷移を写したモデルについて、モデルの到達状態の投影を機械で導出しなければならない（手で描いた図は、モデルの到達状態と一致する根拠を持たない）。

#### PR-FORMALMETHODS-211 投影を文書の図と照合する
文書側に状態の図があるとき、作る機能は、PR-FORMALMETHODS-124 で導出した投影を、その図と照合しなければならない（照合しないと、文書の図とモデルの到達状態の食い違いが現れない）。

#### PR-FORMALMETHODS-279 状態の図が無いとき
文書側に状態の図が無いとき、状態に書いて止まる run と完了する run で、作る機能は、PR-FORMALMETHODS-211 の照合を対象外として範囲と限界の記録に書かなければならない（書かないと、照合していない投影が照合したものと読まれる）。

#### PR-FORMALMETHODS-125 列挙の欠落は機械で見つからないと記録する
状態に書いて止まる run と完了する run で、作る機能は、イベント・遷移の列挙そのものの欠落は機械では見つからないことを範囲と限界の記録に書かなければならない（モデルの中だけを見ても、モデルに書かれていない出来事の欠落は現れない）。

#### PR-FORMALMETHODS-126 検査を再実行できる形で残す
作る機能は、検査を、コマンド・設定・前提・道具の版とともに再実行できる形でモデルに残さなければならない（再実行できない検査は、結果を後から確かめられない）。

#### PR-FORMALMETHODS-190 遷移から転記した条件を要求側の性質と二重にする
作る機能は、遷移の欠落を検出する条件（イベントの有効条件と事後条件を遷移から転記したもの）を置くとき、その条件を、結果の誤りを要求の側から捉える性質と二重にしなければならない（転記だけでは、転記元の誤りを検出できない）。

#### PR-FORMALMETHODS-257 遷移から転記した条件が独立した仕様でないことを明示する
PR-FORMALMETHODS-190 の条件を置くとき、作る機能は、その条件が検査対象から独立した仕様ではないことをモデルの中で明示しなければならない（明示しないと、転記した条件が検査対象と独立した確かめとして読まれる）。

### audit が確かめる中身

#### PR-FORMALMETHODS-127 変異と witness を持つ
audit は、モデルが性質ごとに意味の違う変異と、前件の状態への到達例（witness）を持つことを確かめなければならない（変異が無いと性質が効いているかを確かめられず、前件に到達しない性質は満たすべき場面が現れないので保証にならない）。

#### PR-FORMALMETHODS-128 反例の有無は検査器の出力で数える
audit は、性質ごとの反例の有無を検査器の出力から数えなければならない（agent が反例の有無を申告すると、確かめる手段の無い数字が合否を決める）。

#### PR-FORMALMETHODS-129 空振り
audit は、どの変異でも破れない性質、恒真の性質、前件が常に真の性質、どの検査にも使われていない変異、モデルの説明が主張する検査と実際の検査の食い違いを欠けにしなければならない（これらは、検査が通っても何も保証しない）。

#### PR-FORMALMETHODS-130 忠実さ
audit は、モデルの対応表の各行について、行が指す文書の行の規範をモデルの遷移と性質が写しているかを確かめなければならない（確かめないと、モデルが文書と違うものを検査していても気づけない）。

#### PR-FORMALMETHODS-212 緩いモデルと強いモデルを欠けにする
audit は、PR-FORMALMETHODS-130 で、モデルが文書より緩い（文書の違反を見逃す）か強い（文書に無い違反を出す）と分かったものを欠けにしなければならない（緩いモデルは欠けを隠し、強いモデルは偽の欠けを出す）。

#### PR-FORMALMETHODS-131 忠実さの層の抜け
audit は、検査対象が持つ忠実さの層のうち、モデルが写しておらず、写さない理由の宣言も無い層を欠けにしなければならない（写していない層の欠けは、モデルの検査に現れない）。

#### PR-FORMALMETHODS-132 モデルが足した制約
audit は、モデルが加えた制約のうち検査対象と上流に根拠の行が無いものを挙げなければならない（挙げないと、文書に無い制約が検査の前提に紛れる）。

#### PR-FORMALMETHODS-213 足した制約を外して確かめる
audit は、PR-FORMALMETHODS-132 で挙げた制約を外したときに反例が出るかを確かめなければならない（文書に無い制約は、それが無ければ出る反例を隠す）。

#### PR-FORMALMETHODS-268 外しても反例が出ない制約
PR-FORMALMETHODS-213 で外しても反例が出なかった制約を、状態に書いて止まる run と完了する run で、audit は、前提として範囲と限界の記録に載せなければならない（載せないと、文書に無い前提が範囲と限界の記録に現れない）。

#### PR-FORMALMETHODS-133 節の固定があること
audit は、手で写した節に全て節の固定があることを確かめなければならない（節の固定の無い節は、文書が変わってもモデルの検査が落ちない）。

#### PR-FORMALMETHODS-214 節の固定が落ちることを確かめる
audit は、固定した節が変わったら検査が落ちることを確かめなければならない（落ちない節の固定は、文書が変わっても古い結果を返す）。

#### PR-FORMALMETHODS-215 再実行で同じ結果になることを確かめる
audit は、検査を再実行して同じ結果になることを確かめなければならない（再実行で結果が変わるモデルは、どの結果が保証かが決まらない）。

#### PR-FORMALMETHODS-134 有限範囲
audit は、モデルの有限範囲の定数が検査対象の下限・上限に届いているかを確かめなければならない（確かめないと、狭い範囲で反例が無いことが、範囲の外の保証に読まれる）。

#### PR-FORMALMETHODS-216 届かない定数を欠けにする
audit は、PR-FORMALMETHODS-134 で届いていないと分かった定数を、届かない旨の宣言が無ければ欠けにしなければならない（宣言の無い狭い範囲は、範囲の外の保証に読まれる）。

#### PR-FORMALMETHODS-135 生成と手で写すことの境目
audit は、抜き出しから生成できる部分を手で写している箇所を欠けにしなければならない（生成できる部分を手で写すと、正本からずれうる）。

#### PR-FORMALMETHODS-217 手で写した記録の無い箇所を欠けにする

#### PR-FORMALMETHODS-185 形式化できるものを機械で確かめる
リポジトリの検証は、PR-FORMALMETHODS-184 で形式化できるとした性質を、決定的な検査器か状態モデルで確かめなければならない（できると仕分けた性質を確かめないと、仕分けが保証に結びつかない）。

#### PR-FORMALMETHODS-186 形式化できないものを PR のレビューで確かめる
スキルの作り手は、PR-FORMALMETHODS-184 で形式化できないとした性質を、PR のレビューで原文と照らして確かめなければならない（run の中で人のレビューを求めると、人を待たない run が人を待つ）。

#### PR-FORMALMETHODS-222 PR のレビューの方法と結果を残す
スキルの作り手は、PR-FORMALMETHODS-186 で確かめた方法と結果を PR に残さなければならない（残さないと、形式化できない性質を誰がどう確かめたかが後から追えない）。

#### PR-FORMALMETHODS-187 自身への適用の範囲を記録する
スキルの作り手は、formal-methods 自身への適用について、確かめた文書、確かめた範囲、結果及び確かめていない範囲を `docs/specifications/formal-methods.md` に記録しなければならない（自身についてだけ記録を免れると、保証の境界が自分自身についてだけ引けない）。

# 要求文書: cleanup-branches

## 表記規約

本文書の要求文は次の語尾で区分する。

| 区分 | 語尾 | 対応する英語 |
|---|---|---|
| 必須 | 〜しなければならない | shall / MUST |
| 推奨 | 〜することが望ましい | should / SHOULD |
| 許容 | 〜してもよい | may / MAY |
| 禁止 | 〜してはならない | shall not / MUST NOT |

欠番: PR-CLEANUP-031・PR-CLEANUP-034・PR-CLEANUP-035・PR-CLEANUP-038・PR-CLEANUP-039・PR-CLEANUP-072・PR-CLEANUP-079。

本文書では、利用者の依頼を受けて本文書の要求を満たす処理を行う主体を「cleanup-branches」と呼び、
cleanup-branches に整理と同期を頼む人間を「利用者」と呼ぶ。

## 用語

| 用語 | 意味 |
|---|---|
| 作業場所 | 利用者が cleanup-branches を起動した git の作業ツリー（worktree） |
| 他の作業場所 | 同じリポジトリに属する、作業場所以外の作業ツリー |
| 主ブランチ | 取り込み済みかを判定する基準とするブランチ。範囲は PR-CLEANUP-002 が定める |
| 起点ブランチ | 作業場所の同期と作業用ブランチの作成の起点とするブランチ。決め方は PR-CLEANUP-046・047 が定める |
| 現在のブランチ | 作業場所で checkout しているブランチ。作業場所が detached HEAD のときは無い |
| 追跡先 | ローカルブランチに設定された、対応する remote のブランチ |
| 判定の対象のブランチ | ローカルブランチ・remote ブランチのうち、主ブランチでなく、PR-CLEANUP-076〜078 で対象から外していないもの |
| 状態の取得 | 削除と同期の前に、remote の最新の状態を取得し、PR-CLEANUP-008 の項目を取る工程 |
| 取り込み済み | 判定の対象のブランチのうち、PR-CLEANUP-003・004・066・075 のいずれかに当たると判定したものの分類 |
| 要判断 | 判定の対象のブランチのうち、取り込み済みと判定できなかったものの分類（PR-CLEANUP-006・007） |
| 判断が要る対象 | 削除してよいかを利用者に問う対象。カテゴリは PR-CLEANUP-021 が定める |
| 作業状態 | submodule のポインタ差分・tracked ファイルの未コミット差分・未追跡ファイル・stash |
| 終了済みの workspace | PR-CLEANUP-030 が定める workspace |
| 一部を承認 | 問いへの応答のうち、示した候補の 1 件以上を名指しして削除を承認し、それ以外の要求を併せ持たないもの。全件を 1 件ずつ名指しする応答を含む |
| 全件残す | 問いへの応答のうち、選択肢の「全件残す」を選び、それ以外の要求を併せ持たないもの |
| 一覧を求める | 問いへの応答のうち、選択肢の「一覧を見て個別に選ぶ」を選び、それ以外の要求を併せ持たないもの |
| それ以外 | 問いへの応答のうち、一部を承認・全件残す・一覧を求めるのいずれにも当たらないもの。承認と一覧の要求を併せ持つ応答を含む |
| 一覧の提示の回数 | 利用者が一覧を求めたことに応じて判断が要る対象の一覧を示した回数。問いの中で PR-CLEANUP-024 に従い候補を全件示したことは数えない |
| 退避 | PR-CLEANUP-048 に従い、この実行が作業場所の未コミットの変更を一時的に片付けたもの |

## 背景と課題

PR をマージした後の作業場所には、取り込み済みのブランチ・終了済みの workspace が溜まり、作業場所自体も
主ブランチから遅れる。cleanup-branches は、取り込み済みのものを落とし、作業場所を最新の起点ブランチへ
同期し、次の作業用ブランチを作るところまでを 1 回の依頼で終える。その際、そこにしか無い作業
（未取り込みのブランチ・終了済みの workspace・未コミットの変更）を利用者の承認なしに失わない。

## 想定する利用者と利用場面

| 利用者 | 利用場面 |
|---|---|
| 個人の開発者 1 人（remote は本人だけが使う） | PR をマージした後、または作業場所を最新にしたいときに、整理と同期を依頼する |

## どう使われるか

1. 利用者が整理・同期を依頼する。
2. cleanup-branches が状態の取得を行い、ブランチを取り込み済みと要判断に分ける。
3. 取り込み済みのブランチを確認なしで削除する。
4. 判断が要る対象（未取り込みのブランチ・終了済みの workspace）があれば 1 回だけ問い、承認された分を削除する。
5. 作業状態を削除せずに一覧で示す。
6. 作業場所を起点ブランチへ同期し、作業用ブランチを作り、リポジトリ固有の後処理を実行する。
7. 何を削除し、何を残したかを完了報告で返す。

## スコープとスコープ外

### この文書が扱う範囲

- 取り込み済みのローカルブランチ・remote ブランチの削除
- 承認を得た未取り込みのローカルブランチ・remote ブランチと、承認を得た終了済みの workspace の削除
- 作業状態の一覧の提示
- 作業場所の起点ブランチへの同期と作業用ブランチの作成
- リポジトリが宣言した後処理の実行
- 完了報告

### cleanup-branches が行わないこと

- 作業状態の削除・破棄
- 未取り込みのブランチの一括削除
- リポジトリが宣言していない後処理の推測と実行
- 実行時間・可用性の保証
- 削除した対象の記録の保持（完了報告に載せることを除く）

## 前提と依存

| 前提・依存 | 内容 |
|---|---|
| 対象 | remote を持つ git リポジトリの作業場所である |
| GitHub | 取り込み済みかの判定の一部と現在のブランチの open PR の判定は GitHub の PR 情報に依存する。PR 情報は得られないことがある |
| 起点ブランチの検出手段 | リポジトリは起点ブランチを検出する手段（`.claude/detect-base-branch.sh`）を任意で備える |
| 後処理の設定 | リポジトリは後処理の設定（`.claude/worktree-sync.json`）を任意で備える |

## 要求一覧

### 守るもの

#### PR-CLEANUP-001 承認なしに失わないもの

cleanup-branches は、未取り込みのブランチの作業、終了済みの workspace、未コミットの変更（stash・未追跡ファイル・tracked ファイルの差分）を、利用者の承認なしに失わせてはならない（remote で削除済みのブランチの追跡 ref を消すことは PR-CLEANUP-010、作業場所の同期で起点ブランチに無いコミットを動かすことは PR-CLEANUP-052 の例外に従う）。

#### PR-CLEANUP-076 現在のブランチを対象から外す

cleanup-branches は、現在のブランチであるローカルブランチを、取り込み済みの判定と削除の対象から外さなければならない（PR-CLEANUP-001 を守るために現行の振る舞いを保つ安全条件である）。

#### PR-CLEANUP-077 他の作業場所で checkout 中のブランチを対象から外す

cleanup-branches は、他の作業場所で checkout 中のローカルブランチを、取り込み済みの判定と削除の対象から外さなければならない（PR-CLEANUP-001 を守るために現行の振る舞いを保つ安全条件である）。

#### PR-CLEANUP-078 open の PR の head を対象から外す

cleanup-branches は、いずれかの主ブランチを base とする open の PR の head であると状態の取得で分かったローカルブランチと remote ブランチを、取り込み済みの判定と削除の対象から外さなければならない。

### 取り込み済みの判定

#### PR-CLEANUP-002 主ブランチの集合

cleanup-branches は、main・develop と、ローカルまたは remote に実在する release/*・dev/* のブランチのすべてを主ブランチとして、取り込み済みかを判定しなければならない。

#### PR-CLEANUP-003 履歴による取り込み

cleanup-branches は、判定の対象のブランチの先端のコミットが、PR-CLEANUP-081 が定める履歴の比べる先のいずれかの履歴に含まれるとき、そのブランチを取り込み済みと判定しなければならない（同じ内容の変更が別のコミットとして主ブランチの履歴にあるだけのローカルブランチは PR-CLEANUP-004・075 に従う）。

#### PR-CLEANUP-064 主ブランチを判定と削除の対象から外す

cleanup-branches は、主ブランチを、ほかの主ブランチに取り込まれていても、ローカル・remote とも取り込み済みの判定と削除の対象から外さなければならない。

#### PR-CLEANUP-065 remote の起点ブランチの保持

cleanup-branches は、remote の起点ブランチを、作業場所の同期と作業用ブランチの作成を終えるまで削除してはならない（同期と作成は remote の起点ブランチを参照するので、その前に削除すると同期できなくなる。PR-CLEANUP-001 と同じく安全のために置く条件である）。

#### PR-CLEANUP-066 remote ブランチの PR による取り込み

cleanup-branches は、判定の対象のブランチのうち remote ブランチであるものが、いずれかの主ブランチを base とする merged の PR の head であり、その先端のコミットがその PR の head のコミットと一致するとき、その remote ブランチを取り込み済みと判定しなければならない（PR が merged になった後に積まれたコミットや、同じ名前で作り直したブランチの作業を失わないための、PR-CLEANUP-001 を実装する安全条件である）。

#### PR-CLEANUP-004 ローカルブランチの PR による取り込み

cleanup-branches は、判定の対象のブランチのうちローカルブランチであるものが、いずれかの主ブランチを base とする merged の PR の head であり、その先端のコミットがその PR の head のコミットであるかその祖先であり（その PR の head のコミットがローカルに無く判別できないときは、この条件を満たさないものとする）、追跡先が設定されていて、追跡先より先に進んでいると判別されないとき、そのローカルブランチを取り込み済みと判定しなければならない（先端のコミットの条件と追跡先の条件は、どちらも PR にも主ブランチにも無いコミットを失わないための、PR-CLEANUP-001 を実装する安全条件である。追跡先の条件は現行の振る舞いを保つ）。

#### PR-CLEANUP-075 ローカルブランチのパッチの一致による取り込み

cleanup-branches は、判定の対象のブランチのうちローカルブランチであるもののすべてのコミットのパッチが、PR-CLEANUP-081 が定めるパッチの比べる先のいずれかにあるとき、そのローカルブランチを取り込み済みと判定しなければならない。

#### PR-CLEANUP-005 remote ブランチの判定の経路

cleanup-branches は、remote ブランチを、パッチの一致によって取り込み済みと判定してはならない。

#### PR-CLEANUP-006 判定できないブランチ

cleanup-branches は、判定の対象のブランチのうち取り込み済みと判定できなかったものを、要判断に分類しなければならない。

#### PR-CLEANUP-007 PR 情報が得られないとき

GitHub の PR 情報を得られなかったならば、cleanup-branches は、PR 以外の経路で取り込み済みと判定できなかったブランチを、要判断に分類しなければならない。

### 状態の取得

#### PR-CLEANUP-008 状態の取得

cleanup-branches は、利用者の依頼を受けたとき、削除と同期の前に、remote の最新の状態を取得したうえで、次の表の項目を取らなければならない。

| 項目 | 取る内容 |
|---|---|
| 主ブランチ | 実在する主ブランチの一覧 |
| 起点ブランチ | 起点ブランチの名前と、そのローカルブランチを追従させられたかどうか |
| ローカルブランチの分類 | 各ローカルブランチが取り込み済み・要判断・判定の対象から外したもののどれであるかと、追跡先が remote で削除済みか・残っているか・設定されていないか |
| remote ブランチの分類 | 各 remote ブランチが取り込み済み・要判断・判定の対象から外したもののどれであるか |
| 要判断のブランチの事実 | 要判断の各ブランチの独自コミット数と最終コミット日 |
| 現在のブランチ | 現在のブランチの名前、または detached HEAD であること |
| 現在のブランチの open PR | ある・無い・得られないのどれであるか |
| merged の PR の head | いずれかの主ブランチを base とする merged の PR の head であるブランチの名前と、その PR の head のコミット |
| open の PR の head | いずれかの主ブランチを base とする open の PR の head であるブランチの名前 |
| 他の作業場所で checkout 中のブランチ | そのブランチの名前 |
| 作業状態 | submodule のポインタ差分・tracked ファイルの未コミット差分・未追跡ファイル・stash のそれぞれの一覧 |
| 終了済みの workspace | 各終了済みの workspace の名前と、最後に更新された日時 |
| 後処理の設定 | リポジトリが後処理の設定を備えるかどうか |

#### PR-CLEANUP-009 remote で削除済みのブランチの判別

cleanup-branches は、状態の取得で、remote で削除済みのブランチを削除済みと判別できなければならない。

#### PR-CLEANUP-010 追跡 ref の削除

cleanup-branches は、状態の取得で、remote で削除済みのブランチの追跡 ref を、利用者の承認を求めずに消さなければならない（remote の最新の状態を prune つきで取得する現行の振る舞いを保つ）。

#### PR-CLEANUP-011 起点ブランチの追従

cleanup-branches は、状態の取得で、起点ブランチのローカルブランチを、ローカルにだけあるコミットを捨てずに remote の起点ブランチに追従させなければならない。

#### PR-CLEANUP-012 判断の根拠

cleanup-branches は、取り込み済みの判定・判断が要る対象の分類・起点ブランチへ動かすかの判定を、状態の取得で得た状態だけを根拠に決めなければならない（同じ判定を 2 か所で持つと食い違う）。

#### PR-CLEANUP-068 状態を取れなかったとみなす失敗

cleanup-branches は、remote の最新の状態の取得に失敗したとき、状態を取れなかったものとしなければならない（前に取得した remote の状態で分類を続けない）。

#### PR-CLEANUP-080 起点ブランチの追従に失敗したとき

cleanup-branches は、起点ブランチのローカルブランチを追従させられなかったとき、状態を取れなかったものとしてはならない（起点ブランチが他の作業場所で checkout 中のときは追従が拒否される）。

#### PR-CLEANUP-081 取り込み済みの判定で比べる先

cleanup-branches は、取り込み済みの判定で比べる先を、次の表のとおりとしなければならない（ローカルにだけある主ブランチは比べる先に含めない。ローカルの起点ブランチの追従に失敗しても判定が変わらず、主ブランチでない起点ブランチを比べる先に含めると起点ブランチ自身が取り込み済みと判定されて削除される。パッチの比べる先は main・develop・起点ブランチより狭く、起点ブランチは主ブランチであるときだけ含める。取り込み済みの内容が主ブランチにあることを保つためである）。

| 比べ方 | 比べる先 |
|---|---|
| 履歴（PR-CLEANUP-003） | remote に実在する主ブランチのすべて（release/*・dev/* を含む） |
| パッチ（PR-CLEANUP-075） | remote に実在する main・develop と、起点ブランチが主ブランチであるときの remote の起点ブランチ |

#### PR-CLEANUP-069 PR 情報だけが得られないとき

cleanup-branches は、GitHub の PR 情報だけを得られなかったとき、状態を取れなかったものとしてはならない。

#### PR-CLEANUP-013 状態を取れないときの停止

状態を取れなかったならば、cleanup-branches は、取り込み済みの削除以降の工程を実行せずに止まらなければならない。

#### PR-CLEANUP-014 状態を取れないときの報告

状態を取れなかったならば、cleanup-branches は、取れなかった旨と取れなかった状態を利用者に返さなければならない。

### 取り込み済みの削除

#### PR-CLEANUP-015 取り込み済みのローカルブランチの削除

cleanup-branches は、状態の取得の後、取り込み済みと分類したローカルブランチを、利用者の確認を求めずに削除しなければならない（取り込み済みのブランチは主ブランチに同じ内容があり、削除しても失われるものが無い）。

#### PR-CLEANUP-016 取り込み済みの remote ブランチの削除

cleanup-branches は、取り込み済みのローカルブランチの削除の後、取り込み済みと分類した remote ブランチを、利用者の確認を求めずに remote から削除しなければならない。

#### PR-CLEANUP-017 確認なしに削除する範囲

cleanup-branches は、確認なしに削除する対象を、状態の取得で取り込み済みと分類したブランチに限らなければならない（主ブランチ・remote の起点ブランチ・PR-CLEANUP-076〜078 のブランチは各要求に従う）。

#### PR-CLEANUP-018 未取り込みの一括削除の禁止

cleanup-branches は、未取り込みのブランチを、1 本ごとの承認を経ずにまとめて削除する経路を持ってはならない。

#### PR-CLEANUP-019 取り込み済みのローカルブランチの削除の失敗

取り込み済みのローカルブランチを削除できなかったならば、cleanup-branches は、そのブランチを残したまま残りの工程を続けなければならない。

#### PR-CLEANUP-020 取り込み済みの remote ブランチの削除の失敗

取り込み済みの remote ブランチを削除できなかったならば、cleanup-branches は、残りの工程を続けなければならない。

### 判断が要る対象の問い

#### PR-CLEANUP-021 判断が要る対象

cleanup-branches は、要判断のローカルブランチのうち追跡先が remote で削除済みのもの、要判断の remote ブランチ、終了済みの workspace の 3 つを、判断が要る対象のカテゴリとしなければならない。

#### PR-CLEANUP-067 判断が要る対象に入らない要判断のブランチ

cleanup-branches は、要判断のローカルブランチのうち追跡先の remote のブランチが残っているものを、問わずに削除せず残さなければならない。

#### PR-CLEANUP-071 追跡先を持たない未取り込みのローカルブランチ

cleanup-branches は、追跡先の remote のブランチを一度も持たない未取り込みのローカルブランチを、問わずに削除せず残さなければならない。

#### PR-CLEANUP-022 1 回の問い

cleanup-branches は、判断が要る対象のうち空でないカテゴリだけを、1 回の問いにまとめて利用者に問わなければならない。

#### PR-CLEANUP-023 判断が要る対象が無いとき

判断が要る対象がどのカテゴリにも無いとき、cleanup-branches は、利用者に問わずに作業状態の提示へ進まなければならない。

#### PR-CLEANUP-024 候補の示し方

cleanup-branches は、問いで示すカテゴリの候補の数に応じて、次の判定表に従って候補を示さなければならない。

> 条件の値: 1 カテゴリの候補数 = 20 件以下 / 20 件超
> 条件の値: カテゴリの種類 = ブランチ / 終了済みの workspace

| 条件: 1 カテゴリの候補数 | 条件: カテゴリの種類 | 結果 |
|---|---|---|
| 20 件以下 | * | そのカテゴリの候補を全件示す |
| 20 件超 | ブランチ | 全件を列挙せず、件数と、最終コミットが古いものから順に 5 件の代表例に要約して示す |
| 20 件超 | 終了済みの workspace | 全件を列挙せず、件数と、最後に更新された日時が古いものから順に 5 件の代表例に要約して示す |

#### PR-CLEANUP-025 候補に添える事実

cleanup-branches は、問いで示すブランチの候補に、独自コミット数と最終コミット日を添えなければならない。

#### PR-CLEANUP-026 要約したときの選択肢

候補を要約して示すとき、cleanup-branches は、問いの選択肢に「全件残す」と「一覧を見て個別に選ぶ」を含めなければならない。

#### PR-CLEANUP-027 一括削除の選択肢の禁止

cleanup-branches は、問いの選択肢に、全件をまとめて削除する選択肢を含めてはならない。

#### PR-CLEANUP-028 応答の扱い

cleanup-branches は、問いへの利用者の応答を、次の判定表に従って扱わなければならない。

> 条件の値: 応答の種類 = 一部を承認 / 全件残す / 一覧を求める / それ以外
> 条件の値: 一覧の提示の回数 = 0 回 / 1 回

| 条件: 応答の種類 | 条件: 一覧の提示の回数 | 結果 |
|---|---|---|
| 一部を承認 | * | 承認された対象だけを削除する |
| 全件残す | * | 何も削除せず、残したものとして報告する |
| 一覧を求める | 0 回 | 判断が要る対象の一覧を示し、改めて受け取った応答をこの判定表に従って扱う |
| 一覧を求める | 1 回 | 何も削除せず、残したものとして報告する |
| それ以外 | * | 何も削除せず、残したものとして報告する |

#### PR-CLEANUP-029 一覧の提示の上限

cleanup-branches は、一覧の提示の回数を、1 回の実行で 2 回以上にしてはならない。

#### PR-CLEANUP-030 終了済みの workspace

cleanup-branches は、`.agent/skills/*/workspace`・`.claude/skills/*/workspace` の下の session の workspace のうち、session の状態が完了を示すものだけを、終了済みの workspace としなければならない。

#### PR-CLEANUP-032 workspace の示し方

cleanup-branches は、workspace を、それを持つスキルの名前と session の名前の組で示さなければならない。

### 承認された対象の削除

#### PR-CLEANUP-033 承認されない対象

cleanup-branches は、利用者が承認しなかった判断が要る対象を削除してはならない。

#### PR-CLEANUP-036 承認されたローカルブランチの削除

cleanup-branches は、承認された未取り込みのローカルブランチを削除しなければならない。

#### PR-CLEANUP-037 承認されたローカルブランチの削除の失敗

承認された未取り込みのローカルブランチを削除できなかったならば、cleanup-branches は、そのブランチを残したまま残りのブランチの処理を続けなければならない。

#### PR-CLEANUP-040 承認された remote ブランチの削除

cleanup-branches は、承認された未取り込みの remote ブランチを remote から削除しなければならない。

#### PR-CLEANUP-041 承認された remote ブランチの削除の失敗

承認された未取り込みの remote ブランチを削除できなかったならば、cleanup-branches は、残りのブランチの処理を続けなければならない。

#### PR-CLEANUP-042 承認された workspace の削除

cleanup-branches は、承認された終了済みの workspace を削除しなければならない。

#### PR-CLEANUP-043 workspace の削除の失敗

終了済みの workspace を削除できなかったならば、cleanup-branches は、残りの工程を続けなければならない。

### 作業状態

#### PR-CLEANUP-044 作業状態を削除しない

cleanup-branches は、submodule のポインタ差分・tracked ファイルの未コミット差分・未追跡ファイル・実行の前からあった stash を削除・破棄してはならない（退避は PR-CLEANUP-060 で戻す）。

#### PR-CLEANUP-045 作業状態の提示

cleanup-branches は、状態の取得で得た作業状態を、一覧として利用者に示さなければならない。

### 作業場所の同期

#### PR-CLEANUP-046 検出手段による起点ブランチ

リポジトリが起点ブランチを検出する手段（`.claude/detect-base-branch.sh`）を備える場合、cleanup-branches は、その検出結果を起点ブランチとしなければならない。

#### PR-CLEANUP-047 既定の起点ブランチ

リポジトリが起点ブランチを検出する手段を備えない場合、cleanup-branches は、remote の既定ブランチを起点ブランチとしなければならない。

#### PR-CLEANUP-048 未コミットの変更の退避

tracked ファイルの未コミット差分か未追跡ファイルがあるとき、cleanup-branches は、起点ブランチへ動かすかの判定（PR-CLEANUP-051）の前に、その判定の結果によらずそれらを退避しなければならない。

#### PR-CLEANUP-049 退避の失敗

PR-CLEANUP-048 の退避に失敗したならば、cleanup-branches は、退避せずに起点ブランチへ動かすかの判定（PR-CLEANUP-051）へ進まなければならない。

#### PR-CLEANUP-050 現在のブランチの open PR

cleanup-branches は、主ブランチを base とする open の PR だけを、現在のブランチの open PR としなければならない（base が主ブランチでない PR は、open PR が無いものとして扱う）。

#### PR-CLEANUP-051 起点ブランチへ動かすかの判定

cleanup-branches は、作業場所の今いるブランチを起点ブランチの位置へ動かすかを、次の判定表に従って決めなければならない（open PR のあるブランチを動かすと、ローカルのブランチが PR の head から離れる）。

> 条件の値: 現在のブランチ = 名前あり / detached HEAD
> 条件の値: 現在のブランチの open PR = ある / 無い / 得られない

| 条件: 現在のブランチ | 条件: 現在のブランチの open PR | 結果 |
|---|---|---|
| 名前あり | ある | 動かさず、起点ブランチから作業用ブランチを作る |
| 名前あり | 無い | 起点ブランチの位置へ動かしてから作業用ブランチを作る |
| 名前あり | 得られない | 動かさず、起点ブランチから作業用ブランチを作る |
| detached HEAD | * | 起点ブランチの位置へ動かしてから作業用ブランチを作る |

#### PR-CLEANUP-052 起点ブランチに無いコミットがあるときの同期

cleanup-branches は、今いるブランチを起点ブランチの位置へ動かすとき、そのブランチに起点ブランチに無いコミットがあっても、利用者の承認を求めずに動かさなければならない（PR-CLEANUP-001 の例外である）。

#### PR-CLEANUP-074 同期で作業ツリーを保つ

cleanup-branches は、今いるブランチを起点ブランチの位置へ動かすとき、作業ツリーに残っている tracked ファイルの未コミット差分と未追跡ファイルを破棄してはならない（PR-CLEANUP-049 で退避せずに進んだときも同じである）。

#### PR-CLEANUP-053 作業用ブランチの名前

利用者がブランチ名を指定したとき、cleanup-branches は、その名前で作業用ブランチを作らなければならない。

#### PR-CLEANUP-054 既定の作業用ブランチの名前

利用者がブランチ名を指定しなかったとき、cleanup-branches は、`feature/` に 16 進 6 文字を続けた名前で作業用ブランチを作らなければならない。

#### PR-CLEANUP-055 作業用ブランチを作れないとき

作業用ブランチを作れなかったならば、cleanup-branches は、後処理へ進まなければならない。

### 後処理

#### PR-CLEANUP-056 後処理の実行

リポジトリが後処理の設定（`.claude/worktree-sync.json` の `post_sync`）を備える場合、cleanup-branches は、作業用ブランチの作成の後に、設定に書かれたコマンドを書かれた順に、利用者の承認を求めずに実行しなければならない。

#### PR-CLEANUP-057 書かれていないコマンドの禁止

cleanup-branches は、後処理の設定に書かれていないコマンドを、後処理として実行してはならない（推測したコマンドは実行のたびに変わり、同期が非決定的になる）。

#### PR-CLEANUP-058 後処理の失敗

後処理のコマンドのいずれかが失敗したならば、cleanup-branches は、後処理を止めずに残りのコマンドを書かれた順に実行しなければならない。

#### PR-CLEANUP-059 後処理の設定が無いとき

リポジトリが後処理の設定を備えない場合、cleanup-branches は、後処理として何も実行してはならない。

### 退避した変更の復帰

#### PR-CLEANUP-060 退避した変更を戻す

退避が作られたとき、cleanup-branches は、完了報告の前に退避した変更を戻さなければならない。

#### PR-CLEANUP-061 退避が無いとき

退避が作られなかったとき、cleanup-branches は、退避を戻す操作をしてはならない。

#### PR-CLEANUP-070 戻す退避の範囲

cleanup-branches は、退避を戻す操作の対象を、この実行が作った退避に限らなければならない（実行の前からあった stash は PR-CLEANUP-044 に従い残す）。

### 完了報告

#### PR-CLEANUP-062 完了報告の項目

cleanup-branches は、完了報告に次の表の項目をすべて載せなければならない。

| 項目 | 載せる内容 |
|---|---|
| 起点ブランチ | 名前と、remote の起点ブランチの先頭のコミットとメッセージ |
| 判定に使った主ブランチ | 主ブランチの一覧 |
| 作業用ブランチ | 作ったブランチの名前、または作れなかった旨 |
| 確認なしで削除した取り込み済みのブランチ | ローカル・remote それぞれのブランチ名 |
| 削除できなかった取り込み済みのブランチ | ローカル・remote それぞれのブランチ名 |
| 承認を得て削除した未取り込みのブランチ | ローカル・remote それぞれのブランチ名 |
| 削除できなかった承認済みの未取り込みのブランチ | ローカル・remote それぞれのブランチ名 |
| 削除せずに残したもの | 承認されなかった判断が要る対象と、PR-CLEANUP-067・071 で残したローカルブランチと、PR-CLEANUP-076〜078 で対象から外したローカルブランチと、PR-CLEANUP-065・078 で削除しなかった remote ブランチの名前 |
| 起点ブランチのローカルブランチの追従 | 「追従した」または「追従できなかった」 |
| 作業状態 | submodule のポインタ差分・tracked ファイルの未コミット差分・未追跡ファイル・stash のそれぞれの件数 |
| workspace | 削除した数・保持した数・削除できなかった workspace の名前 |
| 後処理 | 実行したコマンドと結果、失敗した行と手動実行の案内、または設定が無い旨 |
| 未コミットの変更の退避 | 退避できなかった旨、または退避を戻す際に衝突した箇所と手動解決の案内 |

#### PR-CLEANUP-073 作業状態の件数の時点

cleanup-branches は、完了報告の作業状態の件数を、状態の取得で得た作業状態から数えなければならない。

#### PR-CLEANUP-063 残したものの明示

cleanup-branches は、完了報告の項目に該当する対象が無いときも、その項目を省略せず「なし」と示さなければならない。

## リスクと影響

10 観点の判定を、根拠とともに全件置く。

| ID | 観点 | 判定 | 根拠 |
|---|---|---|---|
| RK-001 | 生命・身体・健康への影響 | 該当なし | 扱う対象がリポジトリのブランチと作業場所に閉じている |
| RK-002 | 金銭・資産の移動 | 該当なし | 扱う対象がリポジトリのブランチと作業場所に閉じている |
| RK-003 | 個人情報・機微情報の取扱い | 該当なし | 削除する workspace とブランチは個人情報・機微情報を含まない |
| RK-004 | 法令・業界規制・契約上の義務 | 該当なし | cleanup-branches に課された法令・業界規制・契約上の義務は無い |
| RK-005 | 第三者監査・当局報告・社内統制 | 該当なし | 監査・当局報告・社内統制の対象ではなく、削除の記録は完了報告に載せるだけでよい |
| RK-006 | 停止が許されない時間帯・可用性 | 該当なし | 実行時間・可用性の要求は無い |
| RK-007 | 外部システムとの連携 | 該当 | 取り込み済みの判定に GitHub の PR 情報を使い、remote のブランチを削除する。PR 情報が得られないときは、主ブランチの履歴に含まれる open の PR の head を確認なしに削除してその PR を閉じうるが、その内容は主ブランチに残る |
| RK-008 | 不可逆な操作 | 該当 | ブランチ・remote ブランチ・workspace の削除を含み、workspace と、承認を得て削除した未取り込みのブランチは削除すると復元できない |
| RK-009 | 利用者の範囲 | 該当なし | 利用者は個人の開発者 1 人で、remote は本人だけが使う |
| RK-010 | データの保持期間・削除や開示の請求 | 該当なし | 削除した対象の保持期間や、削除・開示の請求に応じる義務は無い |

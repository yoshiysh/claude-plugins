# JavaScript

`.js`・`.mjs` のスクリプトと Workflow に適用する。[共通原則](README.md)と[テスト](testing.md)も読む。

## 責務と副作用

- **CLI は引数の検証・処理の呼出し・出力と終了状態への変換を持ち、判断処理を独立して呼べる形にする。** 毎回子プロセスを起動しなくても条件を網羅できるようにする。
  検査: レビュー、判断の単体テストと CLI の結合テスト。
- **ファイル・通信・時刻・乱数・プロセス起動は作用の境界へ寄せ、判断には取得済みの値を渡す。** 実環境の偶然に依存せず、失敗や境界の値を再現するため。
  検査: レビュー、副作用を差し替えた失敗ケース。
- **差し替えは本番でも意味のある依存の境界に置く。** テスト専用の成功分岐や検査の省略は、本番と違う処理を検証することになる。
  検査: レビュー、本番の入口を使う結合テスト。
- **外部入力を境界で検証し、不正な値を既定の成功値へ置き換えない。** 壊れた入力を正常として扱うと、後段が誤った前提で状態を書き換える。
  検査: 欠落・型違い・範囲外のテスト、レビュー。

## 非同期処理と障害

- **起動した非同期処理の終了と失敗を、呼出し元が追える形にする。** 待たない処理は完了報告後も状態を書き換え、拒否された Promise は失敗を報告できなくなる。
  検査: レビュー、遅延・reject・中断のテスト。
- **並列化する前に、共有状態の書き手と失敗時の回収を決める。** 競合と部分成功を、実行順に依存しない形で扱うため。
  検査: レビュー、順序を変えた結合テスト。
- **失敗は原因を保って契約どおりに返し、握りつぶして成功へ変換しない。** Workflow や CLI の呼出し元が再試行・停止を判断できなくなる。
  検査: 失敗の伝播と終了状態のテスト、レビュー。
- **状態の書込みでは、中断や重複実行の後に何が残るかを定める。** 正常終了だけを想定すると、再開時に部分更新を完了済みと誤認する。
  検査: 書込み前後の障害を入れた状態遷移テスト。

## 実行の境界

- **子プロセスへ渡す入力は実行ファイルと引数に分け、利用者の文字列を shell コードへ連結しない。** 引用符や展開によって入力が別の命令になる経路を防ぐ。
  検査: レビュー、空白・引用符・shell の特殊文字を含む入力テスト。
- **CLI の構造化出力と診断を分け、出力形式と終了状態を契約として検証する。** ログの追加だけで呼出し元の解析や合否が壊れるのを防ぐ。
  検査: CLI の結合テスト。
- **Workflow source には制御を置き、決定的処理は呼出せる部品に置く。** ホスト固有の実行面から処理を切り離し、同じ処理を直接検証できるようにする。
  検査: レビュー。source の配置と役割分担は AGENTS.md と best-practices の正本に従う。

# 仕様書: create と update の流れ

## 表記規約

仕様項目の語尾の区分は `docs/requirements/bp-operations.md` の「表記規約」に従う（必須 = 〜しなければならない、推奨 = 〜することが望ましい、許容 = 〜してもよい、禁止 = 〜してはならない）。主体「best-practices」「利用者」の意味も同文書に従う。

## 対象範囲

本文書は、create と update の run の中の流れを定める。扱うのは次のとおり。

- create の対象スキルの置き場と、create・update の run が状態に残す入力
- 目標の固定（create は依頼文から、update は対象スキルの全体と修正の根拠から）
- 書く・検証する・書き直す反復と、その中での形の判定の当て方
- 検証の観点、担当の作り方、合否の判定、反復の上限の当て方
- update の既存の振る舞い（契約）の判定
- create・update に固有の異常系
- 完了時の出力と、完了の前に止まったときの報告

次の事柄は他の文書が定め、本文書は参照だけにする。

| 事柄 | 正本 |
|---|---|
| 依頼の振り分け、機能の連鎖、callsite の入力の項目と綴り、update の対象スキルのパスの一覧 | `docs/specifications/bp-entry.md` |
| run の境界、状態と CLI、停止の種類、next_args と再開、起動数の上限、役ごとのモデル・effort・権限、共通の異常系、どの停止でも返す項目 | `docs/specifications/bp-run.md` |
| 台帳、資産 ID・指摘 ID、反証、指摘の状態と見直し、カバレッジと skip 一覧、指摘の形、修正の根拠の形 | `docs/specifications/bp-findings.md` |
| 対象スキルの判定基準（形の判定・設計の説明・部品・資産台帳・形に関わる原則・配布先での確認・起動数の上限）と確定値 | `docs/specifications/bp-conformance.md` |

## 用語定義

要求文書の用語（`docs/requirements/bp-operations.md`「用語」）、`docs/specifications/bp-run.md` の用語定義（状態・作業場所・前提・修正の根拠の記録 ID・起動数・未着手の項目・破棄した未着手の項目・停止の記録・書いたファイルの一覧・判定基準の写しなど）、`docs/specifications/bp-findings.md` の用語定義（台帳・資産・担当・判定・指摘の候補・観点・指摘の種類・指摘の鍵・見直し）、`docs/specifications/bp-conformance.md` の用語定義（判定の単位・判定の結果）はそのまま使う。本表は本文書で足す語だけを持つ。

| 用語 | 意味 |
|---|---|
| 依頼文 | create では、callsite が渡す依頼の文言（SP-BPENTRY-013）。update では、PR-BPOPERATIONS-017 の読み替えにより「対象スキルの全体から読み取った目的と修正の根拠」を指す |
| 作り直す前の写し | update の最初の run が対象スキルに書く前の、対象スキルの各ファイルの内容の写し（SP-BPAUTHORING-004） |
| 目標の要素 | 固定した目標を構成する欄。成果物・範囲・禁止事項・数値条件・指示語の置き換えの 5 種（SP-BPAUTHORING-006） |
| 出所 | 目標の要素ごとに付ける根拠。依頼文・利用者の回答・作り直す前の写しのどれかからの逐語の引用か、修正の根拠の記録 ID |
| 反復 | 書く段から合否の段までの段の並び 1 回（SP-BPAUTHORING-005） |
| 反復の番号 | 状態の中で反復を区別する番号。反復を始めるたびに 1 増える。反復の上限に当てる反復の回数（SP-BPAUTHORING-024）とは別に数える |
| 契約 | update の対象スキルの、外から見える振る舞い。description が定める発火する条件と発火しない条件、入力、出力、停止の種類の 5 つの要素からなる（依頼者の裁定） |
| 強いられた未検査 | `docs/specifications/bp-conformance.md` が判定する者に「未検査」を付けさせる判定の単位。SP-BPCONFORMANCE-006 のターンごとの指揮の PR-BPDESIGNEDSKILL-002、SP-BPCONFORMANCE-019 の Claude Code の PR-BPDESIGNEDSKILL-014 の判定の単位と、PR-BPDESIGNEDSKILL-010 の設計方針文書「権限」の表の最後の行、SP-BPCONFORMANCE-034 の実行役の時間の上限の行 |
| 合否 | 1 回の反復の終わりに script が決める、合格・不合格・検証が成り立たないの 3 値（SP-BPAUTHORING-023） |
| 残る危険 | 対象スキルの役ごとの制限のうち、配布先で効くかを確かめられなかったもの（SP-BPCONFORMANCE-019・020）。best-practices 自身の役の制限（SP-BPRUN-025）とは別に数える |

## 機能仕様

### 対象スキルと run の入力

#### SP-BPAUTHORING-001 create の対象スキルのパス
create の対象スキルのパスの一覧は、`.agents/skills/<name>/` のディレクトリ 1 つでなければならない（未公開のスキルの実体の置き場：AGENTS.md）。`<name>` は、依頼文がスキル名として名指しする文字列とする。callsite は、この一覧を run の起動前に作り、入力に渡さなければならない（SP-BPENTRY-013）。依頼文がスキル名を名指ししないとき、callsite は create の run を起動してはならず、スキル名を利用者に尋ねなければならない（名前を推測で決めると、依頼文に無い制約を足すことになる：PR-BPOPERATIONS-004）。

create が作る Workflow script は、このディレクトリの中に置かなければならない。`plugins/` の下へ置いてはならない（`plugins/` への移動は marketplace への登録の仕事であり、create の範囲の外にある：AGENTS.md）。

#### SP-BPAUTHORING-002 書き換えてよい範囲
create・update の書き手は、対象スキルのパスの一覧の中（「一覧の中」の意味は `docs/specifications/bp-run.md` の用語定義）のファイルだけを作り・書き換え・消してよい。一覧の外にある既存のファイルを書き換えてはならず、一覧の外に新しいファイルを作ってはならない（PR-BPOPERATIONS-037・020）。作業ファイルの置き場は SP-BPRUN-007・008 に従う。

- update の書き手は、スキルのディレクトリの中に新しいファイルを足してよく、一覧の中のファイルを消してもよい（全体の作り直しの許容：PR-BPOPERATIONS-018）。
- update で新しく Workflow script が要るとき、書き手はそれをスキルのディレクトリの中に置かなければならない（SP-BPAUTHORING-001 と同じ理由）。

#### SP-BPAUTHORING-003 依頼文を状態に残す
create の最初の run は、依頼文を 1 字も変えずに、CLI の開始の操作で状態の作成と同じ書き込みとして状態へ書かせなければならない（SP-BPRUN-003。再開した run は依頼文を入力に受け取らないので、状態に無いと目標を固定し直せない：SP-BPENTRY-013 の再開の行。状態の中の置き場は SP-BPRUN-005）。update の修正の根拠も、同じ書き込みで前提として書く（SP-BPRUN-004）。

#### SP-BPAUTHORING-004 作り直す前の写し
update の最初の run は、作り直す前の写しの段（SP-BPAUTHORING-005。目標の固定の段より前）で、作り直す前の写しを作業場所に作らせなければならない。写しは状態 ID ごとに 1 つとし、写しの記録が状態にある再開した run は、写しを作り直してはならず、記録の写しを使わなければならない（再開の時点の対象スキルは、前の run が書き換えた後の内容なので、契約の判定と目的の読み取りの基準にならない）。写しの各ファイルの内容の指紋を状態に記録し（置き場は SP-BPRUN-005）、再開した run は写しが記録と一致することを確かめてから使わなければならない。写しを作るのは CLI（SP-BPRUN-031）であり、agent に写させてはならない（agent が写すと原典から drift する：設計方針文書「状態の書き込み」）。

### 段の並び

#### SP-BPAUTHORING-005 段の並びと反復
create・update の run は、次の段を上から順に進めなければならない。段は「段」の列の名前で呼び、この名前を状態の「段の進み」（SP-BPRUN-005）に書く。「開始」から「目標の固定」までは反復に含めない。「書く」から「合否」までを 1 回の反復とし、合否が不合格のときだけ SP-BPAUTHORING-025 に従って「書く」へ戻る（create・update の形は固定集合の反復型：改稿が全ての観点の検証の結果を要するので、検証と書き直しの間が段の境界になる）。段の agent が結果を返さなかったときの扱いは、段が fan-out の項目（`docs/specifications/bp-run.md` の用語定義）を持つかで決まる（SP-BPRUN-027・SP-BPRUN-028）。

| 段 | 項目 | 起動する役 | 定める仕様項目 |
|---|---|---|---|
| 開始 | なし | 運搬役 | SP-BPRUN-003 |
| 作り直す前の写し | なし（update だけの段） | 運搬役 | SP-BPAUTHORING-004 |
| 目標の固定 | 1 件 | 書き手 | SP-BPAUTHORING-006〜010 |
| 書く | 1 件 | 書き手 | SP-BPAUTHORING-011〜015 |
| 台帳 | なし | 運搬役 | 最初の反復は SP-BPFINDINGS-001、2 回目以降と再開の開始は SP-BPFINDINGS-005 |
| 検証 | 観点ごとの担当（SP-BPAUTHORING-016） | 検証役 | SP-BPAUTHORING-017〜020 |
| 追加の検証 | skip 一覧の資産だけの担当 | 検証役 | SP-BPFINDINGS-025 |
| 反証 | SP-BPFINDINGS-012 でまとめた指摘の鍵ごと | 反証役 | SP-BPFINDINGS-013〜015 |
| 消えた資産の照合 | 消えた資産に結び付いた指摘ごと | 検証役 | SP-BPFINDINGS-020・SP-BPFINDINGS-037 |
| 見直し | なし | 運搬役 | SP-BPFINDINGS-018・019 |
| 合否 | 1 件 | 運搬役 | SP-BPAUTHORING-021〜025 |

段を始めるときは SP-BPRUN-038 で項目を列挙し、項目の結果と段の進みは運搬役が状態に書く（SP-BPRUN-005・006）。前の回の項目との分け方は SP-BPAUTHORING-036 に従う。役ごとのモデルと effort は SP-BPRUN-023 に従い、目標の固定と書く段の書き手には書き手の値を当てる。同時に走る agent の数は SP-BPCONFORMANCE-027 に従う。

#### SP-BPAUTHORING-036 項目の ID に含める番号
新しい反復の、書く段から合否の段までの項目と、始め直した目標の固定の段の項目は、前の回の項目と別の項目にしなければならない（SP-BPAUTHORING-035 で始め直した反復や目標の固定が、前の回の項目を「結果のある項目」や「打ち切った項目」として引き継がないようにするため）。script は、反復の番号と目標の固定を始め直した回を SP-BPRUN-038 の回として CLI に渡す。回の表し方は TBD-SBPRUN-001 で決める。他の段の項目は回を持たない。

### 目標の固定

#### SP-BPAUTHORING-006 目標の固定の段
目標の固定の段で、script は書き手を 1 体起動し、次の入力を渡さなければならない。

| 機能 | 渡すもの |
|---|---|
| create | 状態にある依頼文、前提にある利用者の回答の全て |
| update | 作り直す前の写しのパス、前提にある修正の根拠のうち SP-BPFINDINGS-031 が修正の根拠として扱うとしたもの、前提にある利用者の回答の全て |

書き手は、次のどちらかを返さなければならない。

- 固定した目標: 下の表の欄を全て持つ。値が無い欄は「なし」と書く。
- 足りない入力: 利用者への問いの一覧と、問いごとの理由（SP-BPAUTHORING-008）。

| 目標の要素 | 中身 | 対応する設計方針文書「目標の固定」の行 |
|---|---|---|
| 成果物 | 最終的に検証できる成果物。調査・手段・検証の手順を入れない。成果物が互いに独立なときだけ複数に分ける | 「目標は「最終的に検証できる成果物」とし」の行 |
| 範囲 | 依頼文から抜き出した、作るスキルが扱う範囲 | 「依頼文から範囲と禁止事項を先に抜き出し」の行 |
| 禁止事項 | 依頼文から抜き出した、作るスキルがしてはならないこと | 同上 |
| 数値条件 | 依頼文にある、数値で判定できる条件 | 「目標に数値で判定できる条件」の行 |
| 指示語の置き換え | 依頼文の指示語と、それを置き換えた固有名の組 | 「依頼文から範囲と禁止事項を先に抜き出し」の行 |

目標の要素ごとに、書き手は 1 つ以上の出所を付けなければならない。出所は次のどれかとする。

| 機能 | 出所に使えるもの |
|---|---|
| create | 依頼文か利用者の回答からの逐語の引用 |
| update | 作り直す前の写しのパスとそのファイルからの逐語の引用、修正の根拠の記録 ID、利用者の回答からの逐語の引用 |

update では、SP-BPFINDINGS-031 が修正の根拠として扱うとした根拠の全てを、成果物か範囲の要素の出所として 1 回以上指さなければならない（修正の根拠を目標の固定の出発点にするため：PR-BPOPERATIONS-016）。

#### SP-BPAUTHORING-007 出所の照合
書き手が固定した目標を返したとき、script は運搬役を通じて CLI に出所を照合させなければならない。CLI は、出所ごとに次を決定的に確かめなければならない。

- 逐語の引用は、指したもの（依頼文・回答・写しのファイル）の中に、1 字も違わずに含まれる。
- 修正の根拠の記録 ID は、前提にある修正の根拠の記録 ID のうち、SP-BPFINDINGS-031 が修正の根拠として扱うとした根拠のものである。
- 全ての目標の要素に、照合を通った出所が 1 つ以上ある。update では、SP-BPAUTHORING-006 の最後の段落の条件も満たす。

照合を通らなかったとき、script は、通らなかった要素と理由を添えて目標の固定の段の書き手を起動し直さなければならない（依頼文に無い目標・制約を作らないため：PR-BPOPERATIONS-004）。起動し直す回数は、最初の 1 回を含めて SP-BPCONFORMANCE-028 の until-pass の繰り返しの上限までとし、回数は状態の段ごとの繰り返しの回数（SP-BPRUN-005）に持つ（再開や目標の固定の始め直しで項目の ID が変わっても数え直さないため：SP-BPRUN-015）。上限の回でも通らなかったとき、run は needs_input で止まり、理由に、出所の無い要素と、それを決めるのに要る回答を書かなければならない（依頼文から目標を固定できないのは、目標を固定する入力が足りないからである：PR-BPOPERATIONS-005）。

#### SP-BPAUTHORING-008 待たれる入力の不足
書き手は、次のどれかに当たるとき、固定した目標の代わりに足りない入力を返さなければならない。

- 依頼文と回答から、最終的に検証できる成果物を 1 つも特定できない。
- 指示語が指すものを、依頼文と回答の中の固有名に置き換えられない。
- 依頼文と回答に、成果物か範囲が違ってくる複数の読みがあり、どれかに決める記述が無い。
- 依頼文の中の 2 つ以上の記述が、同時には満たせない。

書き手が足りない入力を返したとき、run は needs_input で止まり、理由に問いの一覧と問いごとの理由を書かなければならない（run の中では入力を待って続けられない：SP-BPRUN-002）。利用者が回答を足して再開した run は、回答を前提として書いてから（SP-BPRUN-004）、目標の固定の段から始める。

#### SP-BPAUTHORING-009 固定した目標を前提に書く
出所の照合を通った固定した目標を、script は運搬役に前提として状態へ書かせなければならない（SP-BPRUN-004）。script は、固定した目標を書く前に検証役の合格を求めてはならない（固定した目標は生成した主張ではなく入力として扱う：設計方針文書「目標の固定」）。以後の段は、固定した目標を状態から読んで使わなければならない。

#### SP-BPAUTHORING-010 再開した run の目標の固定
再開した run は、前提に固定した目標があるとき、目標の固定の段を飛ばさなければならない。前提に固定した目標が無いとき、目標の固定の段から始めなければならない（SP-BPRUN-015）。

### 書く

#### SP-BPAUTHORING-011 書く段の書き手
書く段で、script は書き手を 1 体だけ起動しなければならない（書き込みを 1 本の流れに保ち、書き手どうしの書き込みの衝突を作らないため：設計方針文書「実行役・回収役・検証役」）。書き手には次を渡さなければならない。

- 状態にある固定した目標
- 対象スキルのパスの一覧と、今の対象スキルのパス
- update では、作り直す前の写しのパスと、SP-BPFINDINGS-031 が修正の根拠として扱うとした根拠
- 2 回目以降の反復では、SP-BPAUTHORING-014 の書き直しの入力
- 判定基準として、SP-BPRUN-036 の写しのうち `docs/specifications/bp-conformance.md` と `docs/requirements/bp-designed-skill.md` の写しの場所

書き手は、対象スキルを書き、書いたファイルと消したファイルのパスを返さなければならない（SP-BPRUN-009）。update の書き手は、修正の根拠が触れない部分を含めて対象スキルの全体を作り直してよい（PR-BPOPERATIONS-018）。

#### SP-BPAUTHORING-012 形の判定の当て方
書く段の書き手は、対象スキルの形を SP-BPCONFORMANCE-004 の順で問いに答えて決め、Q3 では SP-BPCONFORMANCE-005 に従わなければならない（1 体の agent の 1 回の実行で解ける課題は探索グラフ型にしない：PR-BPOPERATIONS-007）。そのうえで、資産台帳の要否を SP-BPCONFORMANCE-009 で決め、部品を SP-BPCONFORMANCE-008 で選んで組まなければならない。書き手は、答えた問いと答え、重い形を強いた事実（SP-BPCONFORMANCE-006）、段ごとの部品の名前（SP-BPCONFORMANCE-008）を、対象スキルの設計の説明に書かなければならない。2 回目以降の反復で形が変わらないときも、設計の説明を今の対象スキルと食い違わないように保たなければならない。

#### SP-BPAUTHORING-013 書き手が対象スキルに入れてはならないもの
書く段の書き手は、次のものを対象スキルに入れてはならない。

- 固定した目標に無い目標・制約（PR-BPOPERATIONS-004）
- 実行役の時間の上限の値（SP-BPCONFORMANCE-034）
- 対象スキルのパスの一覧の外のファイルへの書き込み（SP-BPAUTHORING-002）

設計の説明は、対象スキルのディレクトリの中の 1 つのファイルに置かなければならない。置いたファイルと範囲は、完了時の出力（SP-BPAUTHORING-033）で返す。

#### SP-BPAUTHORING-014 書き直しの入力
2 回目以降の反復の書く段で、script は、直前の反復の合否の段が書き直しの入力とした次のものを、書き手に渡さなければならない。

- SP-BPAUTHORING-022 で「不合格」とした指摘。形は SP-BPFINDINGS-029 のまま渡す。
- SP-BPAUTHORING-021 で、結果が「不適合」の判定の単位と、強いられた未検査でない「未検査」の判定の単位。単位ごとの理由を添える。

script は、検証役と反証役が返したもののうち、上の 2 つ以外を書き手に渡してはならない（書き手が直す先を、検証で確かめたものに限るため）。

#### SP-BPAUTHORING-015 書いたパスの照合
書く段の書き手が結果を返したとき、script は、返されたパスごとに、対象スキルのパスの一覧の中にあるかを決定的に確かめなければならない。「一覧の中」は、書く段を始めたときの今の一覧で決める。script は、一覧の中のパスを、一覧の外のパスの有無によらず、運搬役に書いたファイルの一覧として状態へ書かせなければならない（SP-BPRUN-009。外のパスがある反復で中のパスを書かないと、書き換えたファイルが検証を通っていないことの報告から漏れる：PR-BPOPERATIONS-041）。一覧の外のパスがあれば、続けて SP-BPAUTHORING-031 に従う。

一覧の外のパスが無ければ、script は続けて CLI にパスの一覧を取り直させなければならない（SP-BPRUN-031。書き手が足したファイルと callsite の変化を、台帳の列挙と指紋の照合に入れるため）。CLI は、取り直しが解決できなかった callsite（書き手が足すか壊した、自分の plugin への callsite を含む）を、`SKILL.md` の行番号とともに、取り直した一覧の記録と一緒に状態へ書かなければならない（置き場は SP-BPRUN-005）。script はそれを黙って一覧から外してはならず、最後の取り直しで解決できなかった callsite を、対象スキルから外した callsite として返り値（SP-BPAUTHORING-033・SP-BPAUTHORING-034）に載せなければならない（中身は `docs/specifications/bp-entry.md` の SP-BPENTRY-021 の同名の項目と同じ）。

書き手が結果を返さずに SP-BPRUN-027 で BLOCKED になるとき、script は、停止の記録を書かせる前に、CLI に対象スキルの今の指紋を作らせ、状態に最後に記録した対象スキルの指紋（SP-BPRUN-005）と食い違う一覧の中のファイル（内容が変わったもの、根の中に足されたもの、消えたもの）を、書いたか消したかの印とともに書いたファイルの一覧に書かせなければならない。一覧の外のファイルはこの照らし合わせで見つからないので、BLOCKED の理由に、一覧の外を確かめていないことを書く。

### 検証

#### SP-BPAUTHORING-016 観点と担当

#### SP-BPAUTHORING-017 適合の観点
適合の観点の検証役には、今の対象スキルのパスと、SP-BPRUN-036 の写しの場所を渡さなければならない。検証役は、SP-BPFINDINGS-007 の形に加えて、次を返さなければならない。

- 強いられた未検査を、強いられた未検査でない単位に付けた。

#### SP-BPAUTHORING-018 目標の観点
目標の観点の検証役には、今の対象スキルのパスと、状態にある固定した目標と出所を渡さなければならない。create では状態にある依頼文と回答を、update では作り直す前の写しのパスと、SP-BPFINDINGS-031 が修正の根拠として扱うとした根拠と、回答を合わせて渡さなければならない。検証役は、次を指摘の候補にしなければならない。

| 指摘の種類 | 候補にするとき |
|---|---|
| 成果物の未達 | 固定した目標の成果物を、対象スキルが作らない |
| 範囲の逸脱 | 対象スキルが固定した目標の範囲の外を扱う |
| 禁止事項の違反 | 対象スキルが固定した目標の禁止事項に反する |
| 数値条件の未達 | 対象スキルが固定した目標の数値条件を満たさない |
| 修正の根拠の未反映 | update で、修正の根拠として扱うとした根拠が、対象スキルに反映されていない |
| 依頼に無い目標・制約 | 対象スキルが持つ目標・制約に、create では依頼文と回答の中に、update では作り直す前の写し・修正の根拠・回答の中に根拠が無い（PR-BPOPERATIONS-004、update では PR-BPOPERATIONS-017 の読み替え） |

「依頼に無い目標・制約」の照らし方は SP-BPAUTHORING-037 に、判定基準が求める制約の扱いは SP-BPAUTHORING-038 に従う。

#### SP-BPAUTHORING-037 依頼に無い目標・制約の照らし方
目標の観点の検証役は、「依頼に無い目標・制約」を、固定した目標ではなく、依頼文・写し・修正の根拠・回答の原文に照らさなければならない（固定した目標は検証役の受理を通さずに書かれるので、目標の固定で紛れ込んだ目標を、固定した目標に照らすと見逃す）。

#### SP-BPAUTHORING-038 判定基準が求めた制約
SP-BPCONFORMANCE-003 の判定表で対象スキルに当たる仕様項目（その項目が参照する設計方針文書の原則の表の行を含む）が求める制約（同時実行の上限、`model` と `effort` の明示、停止の種類、資産台帳など）を、目標の観点の検証役は根拠のある制約として扱い、「依頼に無い目標・制約」の候補にしてはならない（候補にすると、適合の観点が求める制約を目標の観点が消させ、反復が上限まで往復する。PR-BPOPERATIONS-008 と PR-BPOPERATIONS-004 を両立させるため）。検証役は、そう扱った制約ごとに、資産 ID と、その制約を求める仕様項目 ID を「基準が求めた制約」として返さなければならない。

#### SP-BPAUTHORING-019 契約の観点
契約の観点の検証役には、作り直す前の写しのパスと、今の対象スキルのパスと、SP-BPFINDINGS-031 が修正の根拠として扱うとした根拠とその根拠の記録 ID の一覧と、判定基準の写し（SP-BPRUN-036）の場所を渡さなければならない。検証役は、契約の 5 つの要素ごとに、写しと今の対象スキルを照らし、変わったところを全て挙げなければならない。変わったところごとに、検証役は、その変化を求めたものとして次のどれか 1 つを選ばなければならない。

- 渡された一覧の修正の根拠の記録 ID
- 判定基準の仕様項目 ID: SP-BPAUTHORING-038 が根拠のある制約を求めるとした仕様項目のうち、その変化を求めたもの
- 「該当なし」

選んだものに従った返し方は SP-BPAUTHORING-039 に、既存の振る舞いが保たれたかの判定は SP-BPAUTHORING-040 に従う。

#### SP-BPAUTHORING-039 契約の変化の返し方
契約の観点の検証役は、SP-BPAUTHORING-019 で選んだものに従って、次のとおり返さなければならない。

- 「該当なし」を選んだ変化は、その要素の指摘の種類の指摘の候補にしなければならない。資産は、変化が現れる今の資産とする。要素が消えたときは、写しでその要素があったのと同じパスの今の資産とし、そのパスが今の対象スキルに無ければ今の SKILL.md の frontmatter の資産とする。
- 修正の根拠の記録 ID か判定基準の仕様項目 ID を選んだ変化は、指摘の候補にせず、変化と選んだ ID を「契約の判定の結果」として返さなければならない。CLI は、選ばれた記録 ID が渡した一覧にあることと、選ばれた仕様項目 ID が `docs/specifications/bp-conformance.md` の写し（SP-BPRUN-036）の仕様項目 ID であることを決定的に確かめ、当たらなければその結果の記録を拒否しなければならない（拒否された結果の扱いは SP-BPFINDINGS-034 と同じ）。

#### SP-BPAUTHORING-040 既存の振る舞いの判定
既存の振る舞いが保たれたかは、契約の観点の結果と、SP-BPAUTHORING-022 の合否だけで判定しなければならない。書き手の申告や、写しとの差分の大きさで判定してはならない（PR-BPOPERATIONS-019）。修正の根拠も判定基準も求めないのに契約が変わったときは不合格とし、判定基準が求めた契約の変化は許す（依頼者の裁定）。判定基準が求めた変化は、変わった契約と、それを強いた仕様項目 ID を返り値に載せなければならない（SP-BPAUTHORING-032）。

#### SP-BPAUTHORING-020 1 回の反復の中の検証の順

5. 消えた資産の照合の段で、SP-BPFINDINGS-020・SP-BPFINDINGS-037 を行う。
6. 見直しの段で、CLI に見直しを判定させる（SP-BPFINDINGS-018・019）。
7. 合否の段で、SP-BPAUTHORING-021〜025 を行う。

#### SP-BPAUTHORING-041 fan-out の項目の順位
create・update の fan-out の項目の順位（SP-BPRUN-038 の列挙の順。起動数の上限で止まるときの未着手の項目の順位にも使う：SP-BPRUN-020）は、次の表のとおりとしなければならない。

### 合否

#### SP-BPAUTHORING-021 判定の単位の結果
合否の段で、script は、適合の観点の判定の単位ごとの結果を、次の判定表で決めなければならない。

> 条件の値: 検証役が返した結果 = 適合 / 不適合 / 対象外 / 未検査
> 条件の値: 添えた鍵の指摘 = 不合格とした指摘が 1 つ以上ある / 全て合格を妨げない / 上記以外

| 条件: 検証役が返した結果 | 条件: 添えた鍵の指摘 | 結果 |
|---|---|---|
| 適合 | * | 適合 |
| 対象外 | * | 対象外 |
| 未検査 | * | 未検査（検証役が添えた区分のまま） |
| 不適合 | 不合格とした指摘が 1 つ以上ある | 不適合 |
| 不適合 | 全て合格を妨げない | 適合（反証で退けられたか直った単位として、理由に指摘 ID を添える） |
| 不適合 | 上記以外 | 未検査（強いられていない未検査） |

「添えた鍵の指摘」は、添えた鍵が指す台帳の指摘に SP-BPAUTHORING-022 を当てた結果で数える（前の run が状態を記録した指摘も、同項のとおり、この run の見直しの判定で数える）。「上記以外」は、不合格とした指摘が無く、かつ「検証が成り立たない」とした指摘か、台帳に指摘の無い鍵（未反証の候補：SP-BPFINDINGS-015）が 1 つ以上あることを指す。適合の観点の検証役の項目が打ち切りになったときは、全ての判定の単位を「未検査（強いられていない未検査）」とする。

#### SP-BPAUTHORING-022 指摘による合否
合否の段で、script は、台帳の指摘ごとに次の判定表を当てなければならない。「記録した run」は、指摘の最後の状態の記録を記録した run である（SP-BPFINDINGS-019）。「この run の見直しの判定」は、記録した run が前の run の指摘にだけ CLI が記録する（SP-BPFINDINGS-019）。「記録なし」は、この run にその記録が無いこと（SP-BPFINDINGS-018 の「判定しない」を含む）を指す。「今の内容で判定したか」は SP-BPFINDINGS-021 の値で、記録した run が前の run の指摘では、この run の見直しの判定が記録された時点の値とする。

> 条件の値: 記録した run = 今の run / 前の run
> 条件の値: 状態 = open / dismissed / resolved / regressed
> 条件の値: この run の見直しの判定 = 存在する / 存在しない / 判定できない / 記録なし
> 条件の値: 今の内容で判定したか = はい / いいえ

| 条件: 記録した run | 条件: 状態 | 条件: この run の見直しの判定 | 条件: 今の内容で判定したか | 結果 |
|---|---|---|---|---|
| 今の run | open | * | * | 不合格（書き直しの入力にする） |
| 今の run | regressed | * | * | 不合格（書き直しの入力にする） |
| 今の run | dismissed | * | はい | 合格を妨げない |
| 今の run | dismissed | * | いいえ | 検証が成り立たない |
| 今の run | resolved | * | はい | 合格を妨げない |
| 今の run | resolved | * | いいえ | 検証が成り立たない |
| 前の run | * | 存在する | * | 不合格（書き直しの入力にする） |
| 前の run | * | 存在しない | はい | 合格を妨げない |
| 前の run | * | 存在しない | いいえ | 検証が成り立たない |
| 前の run | * | 判定できない | * | 検証が成り立たない |
| 前の run | open | 記録なし | はい | 不合格（書き直しの入力にする） |
| 前の run | regressed | 記録なし | はい | 不合格（書き直しの入力にする） |
| 前の run | dismissed | 記録なし | はい | 合格を妨げない |
| 前の run | resolved | 記録なし | はい | 合格を妨げない |
| 前の run | * | 記録なし | いいえ | 検証が成り立たない |

今の run が記録した指摘は、この run の見直しの判定を持たないので、その列を問わない。前の run が記録した指摘を、この run で resolved / regressed として報告してはならない（PR-BPOPERATIONS-022・042）。報告の形は SP-BPFINDINGS-028 に従う。

#### SP-BPAUTHORING-023 反復の合否
合否の段で、script は、次の順に当て、最初に当たった値をその反復の合否にしなければならない。

1. 次のどれかに当たれば「検証が成り立たない」。
   - SP-BPAUTHORING-022 で「検証が成り立たない」とした指摘がある。
   - 未反証の候補（SP-BPFINDINGS-015）がある。
   - 追加の検証の段の後に、どれかの観点の skip 一覧が空でない。
   - SP-BPAUTHORING-021 で「未検査（強いられていない未検査）」とした単位のうち、適合の観点の検証役の項目が打ち切りになったことによるものがある。
2. 次のどれかに当たれば「不合格」。
   - SP-BPAUTHORING-022 で「不合格」とした指摘がある。
   - SP-BPAUTHORING-021 で「不適合」か、強いられた未検査でない「未検査」とした単位がある。
3. 上記以外は「合格」。

強いられた未検査の単位と、残る危険は、合否を妨げない。これらは完了時の出力で宣言する（SP-BPAUTHORING-033）。

script は、合否と、1 と 2 で当たった指摘 ID と判定の単位を、運搬役に合否の段の項目の結果として状態へ書かせなければならない（置き場は SP-BPRUN-005 の項目）。

#### SP-BPAUTHORING-024 反復の数え方
script は、合否の段の項目の結果を状態に書かせる同じ書き込みで、反復の回数を 1 増やさせなければならない（分けると、その間で止まった run の再開で、結果のある項目として飛ばされて数えが抜ける。項目の ID は反復の番号を含む（SP-BPAUTHORING-036）ので、同じ書き込みを繰り返しても SP-BPRUN-006 により 2 回は数えない）。合否が「検証が成り立たない」の反復も 1 回に数える（数えないと、返り値の反復の回数（SP-BPAUTHORING-032）が走らせた反復の数と食い違う。上限は run ごとの増分に当てる（SP-BPRUN-013）ので、数えても再開した run の上限は減らない）。目標の固定の段は反復に数えない。反復の上限の値は SP-BPCONFORMANCE-029 に従い、数え方（現在の run の開始時の累計からの増分に当てること）は SP-BPRUN-013 に従う。

#### SP-BPAUTHORING-025 合否の後の進み方
合否を状態に書いた後、script は次の判定表に従わなければならない。「増分」は SP-BPRUN-013 の、現在の run の開始時からの反復の回数の増分である。

> 条件の値: 合否 = 合格 / 不合格 / 検証が成り立たない
> 条件の値: 増分 = 反復の上限より小さい / 反復の上限に達した

| 条件: 合否 | 条件: 増分 | 結果 |
|---|---|---|
| 合格 | * | 完了で止まる（SP-BPAUTHORING-026） |
| 不合格 | 反復の上限より小さい | 次の反復の書く段へ戻る（書き直しの許容：PR-BPOPERATIONS-011） |
| 不合格 | 反復の上限に達した | 反復の上限で止まる（SP-BPRUN-010・013）。理由に、不合格とした指摘 ID と判定の単位を書く（PR-BPOPERATIONS-012） |
| 検証が成り立たない | * | SP-BPAUTHORING-030 に従い BLOCKED で止まる |

#### SP-BPAUTHORING-026 完了の条件
create・update の run は、直前の反復の合否が合格のときだけ、完了で止まってよい。合格の前に、対象スキルを完了として報告してはならない（PR-BPOPERATIONS-010）。完了で止まるとき、script は、書いたファイルの一覧の全てのファイルについて、検証を通ったことを運搬役に追記させなければならない（SP-BPRUN-009）。それ以外の停止では、どのファイルにも検証を通ったことを追記させてはならない。

### 停止

#### SP-BPAUTHORING-027 needs_input で止まるところ
create・update の run が needs_input で止まってよいのは、目標の固定の段（SP-BPAUTHORING-007・008）と、状態を作る前の入力の確かめ（SP-BPAUTHORING-029）だけとする。書く段から合否の段までの間は、人間の入力を求めて止まってはならない（反復の中で人間の入力を待つ手順を持たない：PR-BPOPERATIONS-006）。

#### SP-BPAUTHORING-028 止まったときに書いたファイルと報告
完了の前に止まったとき、run は書いたファイルを残さなければならない（SP-BPRUN-012）。返り値は SP-BPRUN-032 の項目に加えて、SP-BPAUTHORING-034 の項目を持たなければならない。

#### SP-BPAUTHORING-035 再開した run が始めるところ
create・update の再開した run は、SP-BPRUN-015 の 1・2 を行った後、同じ反復の続きとして始めるときは、終えていない段の未着手の項目から続け、終えた段の結果を処理し直してはならない。止まった段の項目が 0 件なら、その段を最初から行う。ただし、再開した run の開始で機能によらず行う台帳の取り直し（SP-BPFINDINGS-005）と、その取り直しで消えた資産が新しく記録されたときの消えた資産の照合の段は、それぞれの段を終えていても行い、本項の例外とする。停止の種類（反復の上限は、停止の記録が残す当たった上限で分ける：SP-BPRUN-011）と止まった段ごとの始め方（同じ反復の続きか、新しい反復か、目標の固定の始め直しか）の細目は TBD-SBPAUTHORING-002 で決める。

新しい反復や始め直した目標の固定に移るとき、前の回の未着手の項目を処理してはならない（前の回の項目は、利用者が直す前の条件で出したものである）。それらは SP-BPRUN-015 の 5 のとおり破棄した未着手の項目として状態に書かせる。

## エラー処理と異常系

本章は create・update に固有の異常系だけを置く。agent の失敗・工程の欠け・CLI の拒否・途中終了・不正か最小に満たない起動数の上限は `docs/specifications/bp-run.md` の SP-BPRUN-027〜030・SP-BPRUN-018・SP-BPRUN-037 に、台帳の資産が 0 件のときと台帳に無い値を含む結果は `docs/specifications/bp-findings.md` の SP-BPFINDINGS-033〜035 に従う。停止の種類は SP-BPRUN-010 の表で create・update が使うとしたものから選ぶ。起動数の上限で止まるときの停止の種類と理由は SP-BPRUN-035 に従う。

#### SP-BPAUTHORING-029 状態を作る前の入力の確かめ
create・update の run は、状態を作る前に、入力を次の判定表で確かめなければならない。「確かめる時点」が「agent の起動の前」の行は、script が入力の値だけから決定的に確かめ、agent を 1 体も起動せずに止まる。「開始の操作」の行は、最初の運搬役が呼ぶ CLI の開始の操作（SP-BPRUN-003）が確かめ、CLI は状態と作業場所を作らずに理由を返し、script は次の agent を起動せずに止まる（script はファイルに触れないので、ファイルの有無は CLI が確かめる）。

> 条件の値: 機能 = create / update
> 条件の値: 当たること = 依頼文が空 / 修正の根拠として扱う根拠が 0 件 / 対象スキルのディレクトリが既にある / 対象スキルのディレクトリが無い

| 条件: 機能 | 条件: 当たること | 結果 |
|---|---|---|
| create | 依頼文が空 | agent の起動の前に、needs_input と理由（依頼文が要ること）を返す |
| create | 修正の根拠として扱う根拠が 0 件 | 起こりえない（create は修正の根拠を受け取らない） |
| create | 対象スキルのディレクトリが既にある | 開始の操作で、BLOCKED と理由（既にあるパスと、既存のスキルを直すなら update を使うこと）を返す。既にあるディレクトリに書いてはならない（PR-BPOPERATIONS-037）。`.agents/skills/<name>` が symlink のとき（公開済みのスキル：AGENTS.md）も既にあるとする |
| create | 対象スキルのディレクトリが無い | 起こりえない（create はディレクトリを新しく作る） |
| update | 依頼文が空 | 起こりえない（update は依頼文を受け取らない：SP-BPENTRY-013） |
| update | 修正の根拠として扱う根拠が 0 件 | agent の起動の前に、needs_input と理由（受け取った修正の根拠の件数と、SP-BPFINDINGS-031 で扱わなかった件数と、1 件以上の修正の根拠が要ること）を返す（PR-BPOPERATIONS-015） |
| update | 対象スキルのディレクトリが既にある | 起こりえない（update はディレクトリがあることを前提にする） |
| update | 対象スキルのディレクトリが無い | 開始の操作で、BLOCKED と理由（無いパス）を返す |

「修正の根拠として扱う根拠」は、SP-BPFINDINGS-031 が update の修正の根拠として扱うとしたものとし、本項で絞り直してはならない。どの行でも状態を作らないので、停止の記録を書かず、返り値は next_args と状態 ID を持たない（SP-BPRUN-011・SP-BPRUN-032）。利用者は入力を直して新しく起動する。

#### SP-BPAUTHORING-030 検証が成り立たない
反復の合否が「検証が成り立たない」のとき、run は BLOCKED で止まらなければならない。理由には、SP-BPAUTHORING-023 の 1 で当たった項目（指摘 ID、未反証の候補、skip 一覧に残った資産 ID、打ち切りになった項目）を全て書かなければならない（書き直しでは直らず、検証役か反証役が結果を返せない原因を利用者が直す必要がある）。この反復を反復の上限で止まった反復として扱ってはならない。

#### SP-BPAUTHORING-031 一覧の外へのパス
書く段の書き手が対象スキルのパスの一覧の外のパスを返したとき（SP-BPAUTHORING-015）、run は次の段へ進まず、BLOCKED で止まらなければならない。理由には一覧の外のパスを全て書く。返り値の SP-BPAUTHORING-034 の「検証を通っていないこと」には、一覧の外のパスも、書いたが検証を通っていないものとして載せる。script は、一覧の外のファイルを戻させてはならない（戻すかどうかは利用者が決める：PR-BPOPERATIONS-040）。

## 外部インタフェース

create・update の入力の項目と綴りは SP-BPENTRY-013 と TBD-SBPENTRY-002 に従う。どの停止でも返す共通の項目は SP-BPRUN-032 に、指摘と台帳の項目は SP-BPFINDINGS-029・030・032 に従う。本章は、create・update に固有の返り値の項目だけを定める。項目の綴りは TBD-SBPAUTHORING-001 で決める。

#### SP-BPAUTHORING-032 検証の結果
create・update の返り値の「検証の結果」は、最後に合否を書いた反復について、次の項目を持たなければならない。

| 項目 | 中身 |
|---|---|
| 合否 | SP-BPAUTHORING-023 の値と、当たった指摘 ID と判定の単位 |
| 反復の回数 | 状態の累計と、この run での増分 |
| 判定の単位ごとの結果 | 適合の観点の判定の単位ごとに、SP-BPAUTHORING-021 の結果と理由 |
| 強いられた未検査 | 強いられた未検査の判定の単位の一覧と、保留の根拠の仕様項目 ID |
| 基準が求めた制約 | SP-BPAUTHORING-038 で目標の観点の検証役が返した、資産 ID と仕様項目 ID の組の一覧 |
| 契約の判定の結果 | update だけ。変わったところごとに、契約の要素・変わった契約の中身・選んだもの（修正の根拠の記録 ID、強いた判定基準の仕様項目 ID、「該当なし」のどれか）・指摘 ID（「該当なし」のとき）。判定基準が強いた変化は 1 件も省かない（SP-BPAUTHORING-039・SP-BPAUTHORING-040） |
| 指摘と台帳 | SP-BPFINDINGS-030 の項目。指摘の状態の載せ方は SP-BPFINDINGS-028 |

#### SP-BPAUTHORING-033 完了時の出力
create・update が完了で止まったとき、返り値は SP-BPRUN-032 の項目に加えて、次の項目を持たなければならない。

> 条件の値: 機能 = create / update
> 条件の値: 項目 = スキル / 設計の説明 / 検証の結果 / 指摘の状態と skip 一覧 / 残る危険 / 受け取った修正の根拠 / 対象スキルから外した callsite

| 条件: 機能 | 条件: 項目 | 結果 |
|---|---|---|
| create | スキル | 作ったスキルのディレクトリのパス（連鎖で次の機能の対象スキルにする：SP-BPENTRY-009）と、作ったスキルのパスの一覧と各ファイルの内容の指紋（PR-BPOPERATIONS-014） |
| update | スキル | 直したスキルのパスの一覧と、各ファイルの内容の指紋。消したファイルのパスも載せる（PR-BPOPERATIONS-023） |
| create | 設計の説明 | 設計の説明を置いたファイルのパスと範囲と、CLI がそのファイルから逐語で写した本文（PR-BPOPERATIONS-014） |
| update | 設計の説明 | create と同じ |
| * | 検証の結果 | SP-BPAUTHORING-032 |
| * | 指摘の状態と skip 一覧 | SP-BPFINDINGS-032 |
| * | 残る危険 | SP-BPAUTHORING-017 で適合の観点の検証役が返した残る危険の全て。SP-BPRUN-032 の「確かめられなかった役ごとの制限」とは別の項目にする（PR-BPDESIGNEDSKILL-015） |
| create | 受け取った修正の根拠 | 載せない（create は修正の根拠を受け取らない） |
| update | 受け取った修正の根拠 | 受け取った修正の根拠ごとに、修正の根拠の記録 ID（SP-BPRUN-004）と、根拠が指摘ならその指摘 ID。状態は付けない（SP-BPFINDINGS-028） |
| * | 対象スキルから外した callsite | 最後の取り直しで解決できなかった callsite（SP-BPAUTHORING-015）があったときだけ |

設計の説明の本文を agent に要約させてはならない（要約は原典から drift する：設計方針文書「状態の書き込み」）。

#### SP-BPAUTHORING-034 完了の前に止まったときの報告
create・update が完了以外で止まったとき、返り値は SP-BPRUN-032 の項目に加えて、次の項目を持たなければならない。

| 項目 | 中身 |
|---|---|
| 検証を通っていないこと | 書いたファイルの一覧のファイルと、SP-BPAUTHORING-031 の一覧の外のパスが、どれも検証を通っていないこと（SP-BPAUTHORING-026。PR-BPOPERATIONS-041） |
| 止まった段 | SP-BPAUTHORING-005 の段の名前 |
| 検証の結果 | 合否を書いた反復が 1 回以上あるとき、SP-BPAUTHORING-032（検証を通らなかった理由：PR-BPOPERATIONS-012） |
| 残る危険 | 合否を書いた反復が 1 回以上あるとき、最後の反復の SP-BPAUTHORING-017 の残る危険 |
| 対象スキルから外した callsite | 最後の取り直しで解決できなかった callsite（SP-BPAUTHORING-015）があったとき |

止まった理由は SP-BPRUN-032 の「理由」に書く。理由には、本文書の各項目が理由に書くとした内容を含めなければならない。

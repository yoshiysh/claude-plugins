# 仕様書: 生成される文書の記述仕様

本文書は次の文書と同じ一式として生成される。相互に参照する記述は、この一式が揃っていることを
前提とする。

- `docs/requirements/INDEX.md`
- `docs/requirements/requester.md`
- `docs/requirements/consumer.md`
- `docs/specifications/INDEX.md`
- `docs/specifications/flow.md`
- `docs/specifications/elicitation.md`
- `docs/specifications/authoring.md`（本文書）
- `docs/specifications/verification.md`

## 表記規約

本文書の仕様項目は次の語尾で区分する。

| 区分 | 語尾 | 対応する英語 |
|---|---|---|
| 必須 | 〜しなければならない | shall / MUST |
| 推奨 | 〜することが望ましい | should / SHOULD |
| 許容 | 〜してもよい | may / MAY |
| 禁止 | 〜してはならない | shall not / MUST NOT |

## 対象範囲

本文書は、システムが生成する文書そのものの記述仕様を定める。扱うのは次の 10 である。

| 扱う事項 | 節 |
|---|---|
| 要求文書と仕様書の分量の決まり方 | 機能仕様 §文書の種別と分量 |
| 章構成と見出しの階層 | 機能仕様 §章構成 |
| 要求文・仕様項目の書き方（語尾・曖昧語・境界値・単一要求・条件節・根拠） | 機能仕様 §要求文と仕様項目の書き方 |
| 重複と矛盾の排除 | 機能仕様 §重複と矛盾 |
| ID 体系 | 機能仕様 §ID 体系 |
| トレーサビリティ表 | 機能仕様 §トレーサビリティ表 |
| 未確定事項の書式と置き場 | 機能仕様 §未確定事項の書式 |
| ファイル配置と INDEX の導出 | 機能仕様 §ファイル配置と INDEX |
| 状態とイベントの記述、および外部規格への言及 | 機能仕様 §状態とイベントの記述 / §外部規格への言及 |
| 機械検査が参照する語の集合の置き場 | 機能仕様 §機械検査が参照する語の集合 |

本文書が実現する要求は `docs/requirements/consumer.md` と `docs/requirements/requester.md` に
あり、対応はトレーサビリティ表が持つ。

### 本文書が扱わない事項

| 扱わない事項 | どこが扱うか |
|---|---|
| 工程の順序・人間ゲートで止まる条件・保存の実行・実行環境の制約 | `docs/specifications/flow.md` |
| 質問の生成と絞り込み・回答の反映 | `docs/specifications/elicitation.md` |
| 生成物の検査の実行と改稿ループ | `docs/specifications/verification.md` |

本文書の対象（生成文書の記述）は状態遷移を持たない。実行の状態遷移は
`docs/specifications/flow.md` が扱う。したがって本文書は状態とイベントの章を置かない。
本文書が定める状態遷移図と状態 × イベント表の書式（SP-AUTHORING-068 から
SP-AUTHORING-075、および SP-AUTHORING-085・SP-AUTHORING-086）は、生成文書が扱う対象に
状態遷移がある場合に生成文書へ適用する規則である。

## 用語定義

| 用語 | 定義 |
|---|---|
| システム | 要求文書と仕様書を生成する仕組み全体（`docs/requirements/requester.md` の定義に従う） |
| 依頼者 | システムに文書の生成を頼む人間（同上） |
| 生成文書 | システムが生成した個々の文書（`docs/requirements/consumer.md` の定義に従う） |
| 生成文書一式 | 1 回の実行で生成された生成文書の集合（同上） |
| 引き渡す文書 | 引き渡し時点の生成文書一式（同上） |
| 後続作業者 | 生成文書を入力として実装またはテスト設計を行う者（同上） |
| 要求文書 | 何を・誰のために・なぜ作るかを扱う生成文書 |
| 仕様書 | 何が必要で・どう振る舞うかを扱う生成文書 |
| 要求文 | 要求文書の要求一覧に置かれる、ID を持つ 1 件の文 |
| 仕様項目 | 仕様書の機能仕様に置かれる、ID を持つ 1 件の項目 |
| topic | 生成文書 1 つに対応する関心事の識別名。ファイル名に用いる |
| 領域コード | ID の中で topic を表す部分 |
| 観点 | 案件の性質を測るためにあらかじめ定めた切り口。集合の値は `docs/specifications/elicitation.md` の SP-ELICITATION-002 が持つ |
| 常設章 | 生成文書に必ず置く章 |
| 条件付き章 | 設置条件を満たすときだけ置く章 |
| 曖昧語 | 量・時期・水準を測定可能な形で示さない語 |
| 境界包含語 | 数量の境界をその範囲に含むかどうかを識別できる語 |
| 平叙終止 | 要求文または仕様項目が、義務の強さを示す語尾以外で終わっている状態 |
| 複合要求 | 1 件の要求文または仕様項目に 2 つ以上の動作が含まれている状態 |
| 主フロー | 状態遷移のうち、想定どおりに進んだ場合に辿る遷移 |
| 発生しない組み合わせ | 状態とイベントの組で、その状態でそのイベントが発生しないと確認したもの |
| 未確定事項 | 決まっていない論点として生成文書に起票された項目 |
| 着手不能 | 未確定事項の区分。決まらないと後続作業に着手できないもの |
| 進行可能 | 未確定事項の区分。決まらなくても後続作業に着手できるもの |
| 決めないと決めた事項 | 未確定事項の区分。依頼者が決まっていない旨を答えたもの |
| INDEX | 生成文書一式の目次となる導出物。生成文書および生成文書一式に含まれない（INDEX にも適用する仕様項目の一覧は TBD-SAUTHORING-010） |

## 機能仕様

### 文書の種別と分量

#### SP-AUTHORING-003 要求文書の分量の決め方
要求文書の分量は、関係者の間で認識を一致させるのに要る範囲で決めなければならない
（利用形態の把握方法は `docs/requirements/consumer.md` の TBD-RCONSUMER-004、利用形態に
応じて分量を伸縮させる規則は `docs/requirements/requester.md` の TBD-RREQUESTER-006）。

#### SP-AUTHORING-005 仕様書の記述水準の下限
仕様書は、後続作業者が設計・実装・検証を行える水準で記述しなければならない。

#### SP-AUTHORING-006 仕様書の記述水準の上限
仕様書は、要求を満たす実現手段を 1 つに限定する記述（実装の内部構造・使用する部品・
処理の実現方法）を書いてはならない。

### 章構成

#### SP-AUTHORING-007 要求文書が持つ内容
要求文書は、今回作るものと今回作らないものの区別・後続作業が成り立つ前提・ID を持つ要求文・
SP-AUTHORING-054 の 3 つの区分に分けた未確定事項の 4 つを、常設章として持たなければならない。
これらを何という名前の章に分けて置くか、およびこの 4 つのほかに常設章を置くかどうかは
決まっていない（TBD-SAUTHORING-016）。

#### SP-AUTHORING-008 仕様書が持つ内容
仕様書は、この仕様書が扱う範囲と扱わない範囲・読み手によって解釈が分かれる語の定義・ID を
持つ仕様項目・何が起きたときどう振る舞うか・各仕様項目をどう確かめるか・要求 ID と仕様項目 ID
の対応の 6 つを、常設章として持たなければならない。これらを何という名前の章に分けて置くか、
およびこの 6 つのほかに常設章を置くかどうかは決まっていない（TBD-SAUTHORING-019）。

仕様書に未確定事項がある場合、仕様書は未確定事項（TBD 一覧）の章を置かなければならない。

#### SP-AUTHORING-009 条件付き章の設置条件
生成文書は、条件付き章を、次の表が定める設置条件を満たす場合にだけ置かなければならない。

| 条件付き章 | 適用先 | 置く条件 | 中身 |
|---|---|---|---|
| リスクと影響 | 要求文書と仕様書 | 観点の判定で該当と判定された観点がある（該当が 0 件で未判定の観点が残る場合の扱いは TBD-SAUTHORING-018） | 各観点の判定と根拠。ID を持つ項目として書く（ID の形式は SP-AUTHORING-041） |
| 状態とイベント | 仕様書に限る（要求文書へも掛けるかは TBD-SAUTHORING-017） | 扱う対象に状態遷移がある | 状態遷移図と状態 × イベント表（書式は SP-AUTHORING-068 から SP-AUTHORING-075、および SP-AUTHORING-085・SP-AUTHORING-086） |

生成文書は、承認の記録欄の章を置いてはならない。

上の 2 つ以外に条件付き章を設けるかどうか、設ける場合のそれぞれの設置条件と中身、および
その章に置く記述が ID を持つ項目であるかどうかは決まっていない（TBD-SAUTHORING-011）。

#### SP-AUTHORING-010 常設章を削らないこと
常設章に書く材料が無い場合でも、生成文書はその章を削ってはならない。

#### SP-AUTHORING-087 常設章に該当が無いことの記述
常設章に書く材料が無い場合、生成文書はその章に、該当が無いことと、その根拠を書かなければ
ならない。

#### SP-AUTHORING-011 見出しのレベル
生成文書は、次の階層で見出しを置かなければならない。

| 階層 | 用途 |
|---|---|
| `#` | 文書タイトル（1 文書に 1 つ） |
| `##` | 章 |
| `###` | 章の中の区分 |
| `####` | 個別の要求文・仕様項目 |

個別の要求文および仕様項目は、章の中の区分を設けない生成文書でも `####` に置かなければ
ならない。

#### SP-AUTHORING-012 分割時の常設章の自足
生成文書一式が 2 つ以上の生成文書に分かれている場合、各生成文書は自分の常設章を自分で
持たなければならない。

#### SP-AUTHORING-013 リスクと影響章の判定の表記
リスクと影響の章を置く場合、生成文書は各観点の判定を、該当・非該当・未判定のいずれかと
その根拠で書かなければならない。

#### SP-AUTHORING-014 リスクと影響章の観点の範囲
リスクと影響の章を置く場合、各要求文書はその文書の関心事に関わる観点だけを持たなければ
ならない（ある観点がその文書の関心事に関わると判定する規則は TBD-SAUTHORING-005）。

#### SP-AUTHORING-015 機能固有の異常系の置き場
1 つの機能にしか生じない異常系は、その機能を扱う生成文書に置かなければならない。

#### SP-AUTHORING-016 共通の異常系の置き場
2 つ以上の機能に共通して生じる異常系は、生成文書一式のうち共通の機構を扱う 1 つの生成文書に
置かなければならない。

### 要求文と仕様項目の書き方

#### SP-AUTHORING-017 表記規約の凡例
生成文書は、冒頭に表記規約の凡例（必須・推奨・許容・禁止の 4 区分と、対応する語尾）を
置かなければならない。

#### SP-AUTHORING-018 語尾の限定
要求文および仕様項目は、必須・推奨・許容・禁止の 4 区分に対応する語尾のいずれかで
終わらなければならない。

#### SP-AUTHORING-020 曖昧語の排除
要求文および仕様項目は、曖昧語の集合に属する語を含めてはならない。曖昧語の集合は、本項目の
本文に表として列挙しなければならない（集合の値は TBD-SAUTHORING-001）。

#### SP-AUTHORING-021 単位の明示
数量・時間・件数・容量を書くとき、要求文および仕様項目は単位を書かなければならない。

#### SP-AUTHORING-022 境界包含語の使用
数量・時間・件数・容量の境界を書くとき、要求文および仕様項目は境界包含語の集合に属する
語を用いなければならない。境界包含語の集合は、本項目の本文に表として列挙しなければならない
（集合の値は TBD-SAUTHORING-001）。

#### SP-AUTHORING-023 定めた境界の明示
数量・時間・件数・容量に範囲を定めるとき、要求文および仕様項目は、定めた上限および定めた
下限を書かなければならない。上限と下限の双方の記述を求めるかどうかは
`docs/requirements/consumer.md` の TBD-RCONSUMER-012 が扱う。

#### SP-AUTHORING-024 範囲外の値を受け取ったときの振る舞い
数量・時間・件数・容量に上限または下限を定めるならば、生成文書は、その範囲外の値を
受け取ったならばどう振る舞うかを書かなければならない。範囲外の値を受け取ることは、
SP-AUTHORING-028 が言う不正入力に含まれる。

#### SP-AUTHORING-025 閾値が未確定のときの扱い
閾値が入力から確定していない場合、生成文書は数値を書かず、その閾値を未確定事項として
起票しなければならない。

#### SP-AUTHORING-026 単一要求
1 件の要求文および 1 件の仕様項目は、2 つ以上の動作を含めてはならない（2 つ以上と判定する
規則は TBD-SAUTHORING-002）。

#### SP-AUTHORING-027 条件節の構文
要求文および仕様項目の条件節は、条件節のパターンの集合に属するパターンで書かなければ
ならない（集合の値、および 2 つ以上の条件を重ねてよい組み合わせは TBD-SAUTHORING-007）。

#### SP-AUTHORING-028 望ましくない事象の条件節
失敗・不正入力・外部障害を扱う要求文および仕様項目は、条件節のパターンの集合のうち
望ましくない事象に対応するパターンで書かなければならない（集合の値と、そのパターンの
書式は TBD-SAUTHORING-007）。

#### SP-AUTHORING-029 根拠の併記
要求文書の各要求文は、その要求がどこから導かれたかを併記しなければならない（併記を置く
位置と、機械が根拠の記述を同定する目印は TBD-SAUTHORING-009）。

#### SP-AUTHORING-030 根拠に書いてよい出所
生成文書は、次の 3 つの出所以外を要求の根拠として書いてはならない。

| 出所 | 含むもの |
|---|---|
| 依頼文 | 依頼者が最初に渡した依頼の文 |
| 依頼者の回答 | 問いへの回答、および依頼者が承認した中間成果物（ドメイン分析の判定・追加の要求カテゴリ・分割案） |
| 依頼者が所在を示した既存文書 | 依頼者がパスを示した既存の生成文書の本文 |

#### SP-AUTHORING-031 根拠の分量
根拠の記述は、定めた上限と下限の範囲に収めなければならない（上限と下限の値、および上限を
超えたときの扱いは TBD-SAUTHORING-006）。

#### SP-AUTHORING-032 文書外の知識に依存しない記述
生成文書は、業界の慣行・一般に知られた事実・生成文書一式の外にある資料を読み手が補うことを
前提とした記述をしてはならない（そう判定する境界は `docs/requirements/consumer.md` の
TBD-RCONSUMER-008）。

#### SP-AUTHORING-033 実在の人物を特定する表記の排除
生成文書は、実在の人物の氏名およびアカウント名を書いてはならない。

#### SP-AUTHORING-034 人物の役割名による記述
生成文書において人物を指す記述は、役割名で書かなければならない。

#### SP-AUTHORING-035 変更履歴の章
生成文書は、変更履歴の章を置いてはならない。版・日付・変更者・承認者・変更内容のいずれも
書いてはならない。

#### SP-AUTHORING-036 改稿の経緯
生成文書の本文は、前稿への言及・版番号・検査指摘の識別子を含めてはならない。

#### SP-AUTHORING-037 用語の固定
生成文書一式は、同一の対象を指す語を 1 つに固定しなければならない。

#### SP-AUTHORING-038 解釈が分かれる語の定義
生成文書一式は、読み手によって解釈が分かれる語を、生成文書一式の中で定義しなければ
ならない。仕様書は、その定義を用語定義の章に置かなければならない。

### 重複と矛盾

#### SP-AUTHORING-039 正となる記述の単一性
生成文書一式は、同一の事項について正となる記述を 2 箇所以上に置いてはならない。

#### SP-AUTHORING-040 相反する記述の排除
生成文書一式は、同一の事項について相反する記述を置いてはならない。

### ID 体系

#### SP-AUTHORING-041 ID の形式
生成文書は、次の形式で ID を振らなければならない。

| 種別 | 形式 | 例 |
|---|---|---|
| 要求 | `PR-<領域コード>-<連番>` | `PR-CONSUMER-001` |
| 仕様項目 | `SP-<領域コード>-<連番>` | `SP-AUTHORING-003` |
| 未確定事項 | `TBD-<領域コード>-<連番>` | `TBD-SAUTHORING-001` |
| リスク・影響 | `RK-<連番>` | `RK-001` |

要求・仕様項目・未確定事項の連番は、新たに ID を振るとき、その連番を数える単位ごとに、
その単位でそれまでに振った連番の最大値に 1 を加えた値としなければならない（その単位で
1 件も振っていない場合は 001 とする）。連番を数える単位が領域コードだけであるか、領域
コードと種別の組であるかは決まっていない（TBD-SAUTHORING-013）。この規則は新たに振る
ときの採番だけに掛かり、生成文書の中で連番が途切れずに並ぶことを求めない。したがって
SP-AUTHORING-082 が生じさせる欠番は、この規則に反しない。またこの採番規則により、欠番と
なった ID が別の項目へ振られることはない。

リスク・影響の ID は領域コードを持たず、`RK-<連番>` の形式で振らなければならない。その連番の
振り方は生成文書一式を通じて 1 つの規則に従わなければならない（規則の値は
TBD-SAUTHORING-005）。

#### SP-AUTHORING-042 領域コード
領域コードは、その生成文書の topic を英大文字に変換した語としなければならない。

#### SP-AUTHORING-043 未確定事項の領域コードの接頭辞
未確定事項の領域コードには、要求文書では `R` を、仕様書では `S` を、topic を英大文字に
変換した語の前に冠さなければならない。

#### SP-AUTHORING-044 ID の不変性
生成文書は、一度振った ID を変更してはならない。

#### SP-AUTHORING-082 削除した項目の ID の欠番化
要求文・仕様項目・未確定事項を削除したとき、生成文書はその ID を欠番としなければならない。

#### SP-AUTHORING-045 参照する ID の実在
生成文書が本文で参照する ID は、生成文書一式の中に実在する項目を指していなければならない。

### トレーサビリティ表

#### SP-AUTHORING-046 全要求の紐付け
生成文書一式に置かれた全ての要求は、それを実現する仕様項目と、トレーサビリティ表の行で
紐づいていなければならない。実装の対象外とする要求をこの母集団に含めるかどうかは
TBD-SAUTHORING-004 が扱う。

#### SP-AUTHORING-047 表の列構成
トレーサビリティ表は、要求 ID・仕様項目 ID・検証方法の 3 列を持たなければならない。この
3 列のほかに列を置いてよい（進捗を表す列を置くかどうかと、その列に書く値は
TBD-SAUTHORING-003）。

#### SP-AUTHORING-048 検証方法欄の内容
検証方法の欄は、満たしたと判定する手段と、そこで測る対象の 2 つを含まなければならない。

#### SP-AUTHORING-050 表の置き場と範囲
各仕様書は、自分がカバーする要求の分だけのトレーサビリティ表を持たなければならない。
INDEX にトレーサビリティ表の写しを置いてはならない。

#### SP-AUTHORING-051 実装対象外の要求の扱い
実装の対象外とする要求について、生成文書は対象外であることを要求文書のスコープ外に
書かなければならない。その要求をトレーサビリティ表にどう残すかは TBD-SAUTHORING-004。

#### SP-AUTHORING-052 要求と仕様項目の対応の多重度
1 件の要求を 2 件以上の仕様項目に対応させてもよく、2 件以上の要求を 1 件の仕様項目に
対応させてもよい。

### 未確定事項の書式

#### SP-AUTHORING-053 未確定事項の置き場
未確定事項は、未確定事項（TBD 一覧）の章に置かなければならない。確定した要求文および
仕様項目と同じ章に置いてはならない。

#### SP-AUTHORING-054 未確定事項の区分
各未確定事項は、次の 3 つの区分のいずれかに区分しなければならない。

| 区分 | 意味 |
|---|---|
| 着手不能 | 決まらないと後続作業に着手できない |
| 進行可能 | 決まらなくても後続作業に着手でき、決まった時点で追記する |
| 決めないと決めた事項 | 依頼者が決まっていない旨を答えた |

#### SP-AUTHORING-055 区分の並び順
未確定事項（TBD 一覧）の章は、着手不能に区分した未確定事項を、他の 2 つの区分の
未確定事項より前に置かなければならない（3 つの区分をそれぞれ節として立てるか、1 つの表の
中で区分を示すかは TBD-SAUTHORING-014）。

#### SP-AUTHORING-056 未確定事項が持つ情報
各未確定事項は、ID・内容・誰が決めるか・いつまでにの 4 つの情報を持たなければならない
（これらを表のどの列として並べるかは TBD-SAUTHORING-014）。

#### SP-AUTHORING-057 決定者と期限の空欄
誰が決めるかといつまでにが依頼者から示されていない場合、生成文書はその欄を空欄の
まま残さなければならない。

#### SP-AUTHORING-058 未確定事項の本文
未確定事項の内容の欄は、決めるべき論点を書かなければならない。決めることを求める候補
として明示していない値を書いてはならない。

#### SP-AUTHORING-059 要求文からの未確定事項の参照
未確定事項に関係する要求文および仕様項目は、その未確定事項の ID を参照しなければならない。

### ファイル配置と INDEX

#### SP-AUTHORING-060 保存先のパス
生成文書は、要求文書と仕様書とを別のディレクトリに分けて配置しなければならない。それぞれの
ディレクトリの位置と名前、および生成文書のファイル名の作り方は決まっていない
（TBD-SAUTHORING-015）。

#### SP-AUTHORING-061 topic の字種
topic は英小文字で始め、英小文字・数字・ハイフンだけで構成しなければならない。

#### SP-AUTHORING-062 領域コードの衝突
生成文書一式の topic は、2 つ以上が同一の領域コードになる組み合わせを含んでは
ならない。

#### SP-AUTHORING-063 INDEX の導出
INDEX は、各生成文書が申告した ID の一覧と要約から導出しなければならない。システムは
INDEX を、各生成文書の申告に依らずに書いてはならない。

#### SP-AUTHORING-064 要求文書の INDEX が持つ内容
要求文書の INDEX は、各生成文書の所在と扱う関心事、および全ての要求 ID とその所在文書を
持たなければならない。これらを何という名前の節に分けて置くか、およびこの 2 つのほかに
INDEX へ節を置くかどうかは決まっていない（TBD-SAUTHORING-020）。

#### SP-AUTHORING-065 仕様書の INDEX が持つ内容
仕様書の INDEX は、各生成文書の所在と扱う関心事、および全ての仕様項目 ID とその所在文書を
持たなければならない。これらを何という名前の節に分けて置くか、およびこの 2 つのほかに
INDEX へ節を置くかどうかは決まっていない（TBD-SAUTHORING-020）。

#### SP-AUTHORING-066 逆参照の置き場
INDEX は、仕様項目から要求への対応を持ってはならない（その対応は各仕様書の
トレーサビリティ表が持つ）。

### 状態とイベントの記述

#### SP-AUTHORING-067 組み合わせの網羅の示し方
組み合わせの網羅を示すとき、生成文書は表を用いなければならない。

#### SP-AUTHORING-081 図で示してよい内容の限定
状態の集合と主フローの遷移・複数の系をまたぐ時系列のいずれでもない内容を、生成文書は図で
示してはならない。

#### SP-AUTHORING-068 状態遷移図の設置
扱う対象に状態遷移がある場合、仕様書は状態の集合と主フローの遷移を 1 つの状態遷移図に
書かなければならない（状態遷移を持つ対象とみなす範囲は `docs/requirements/consumer.md` の
TBD-RCONSUMER-003）。

#### SP-AUTHORING-069 遷移への仕様項目 ID の付与
状態遷移図の各遷移には、その遷移を定める仕様項目の ID を書かなければならない。

#### SP-AUTHORING-070 イベント集合の宣言
状態 × イベント表を置くとき、仕様書は表の直前に、対象とするイベントの集合を列挙
しなければならない。

#### SP-AUTHORING-071 行の起こし方
状態 × イベント表の行は、状態の集合とイベントの集合の直積から主フローの遷移に当たる
組み合わせを除いたものから起こさなければならない。

#### SP-AUTHORING-072 状態 × イベント表の行が持つ情報
状態 × イベント表の各行は、現在の状態・発生しうるイベント・そのときの振る舞いが定義されて
いるかどうかを識別できる記述の 3 つを持たなければならない。表の列の構成と、行に付ける
振る舞いの種別の分類体系は決まっていない（TBD-SAUTHORING-021。発生しない組み合わせ以外の
行に、定義されているかどうかを何と書くかは TBD-SAUTHORING-012）。

#### SP-AUTHORING-073 発生しない組み合わせの行を削除しないこと
発生しない組み合わせについて、仕様書は行を削除してはならない。

#### SP-AUTHORING-085 発生しない組み合わせの行の空欄
発生しない組み合わせの行について、仕様書は振る舞いの種別と次の状態を書いてはならない。

#### SP-AUTHORING-086 発生しない組み合わせの根拠
発生しない組み合わせの行について、仕様書は発生しないことと、その根拠を書かなければ
ならない。

#### SP-AUTHORING-074 主フローの遷移の置き場
状態 × イベント表は、主フローの遷移を含めてはならない（主フローは状態遷移図と機能仕様が
持つ）。

#### SP-AUTHORING-075 図の記法
生成文書に図を置くとき、生成文書はその図を Mermaid の記法で本文に埋め込まなければならない。
画像ファイルへの参照および外部の作図ツールへの参照を書いてはならない。

この記法を用いる根拠は次の 3 つである。本文に文字として埋め込めること、テキストの差分で
変更を追えること、一般的な描画環境でそのまま表示されること。

### 外部規格への言及

#### SP-AUTHORING-076 言及の条件
依頼者がその規格への対応を求めておらず、かつ案件がその規制の対象であることも入力から
確認できない場合、生成文書は外部の規格に言及してはならない。

#### SP-AUTHORING-077 準拠の主張
生成文書は、外部の規格に準拠していると書いてはならない。

#### SP-AUTHORING-078 条番号を付けた引用
外部の規格の本文を確認できていない場合、生成文書はその規格の条番号を書いては
ならない。

### 根拠が得られない事項の扱い

#### SP-AUTHORING-079 根拠が無い事項の起票
SP-AUTHORING-030 が定める 3 つの出所のいずれにも根拠が無い事項がある場合、生成文書は
推測した記述を書かず、その事項を未確定事項として起票しなければならない。

### 機械検査が参照する語の集合

#### SP-AUTHORING-080 語の集合への参照
曖昧語の集合および境界包含語の集合を参照する仕様項目は、その集合を列挙している仕様項目の
ID を参照しなければならない。

## エラー処理と異常系

本文書が扱う異常系は、規則どおりに書けない入力を受け取ったときに生成文書をどう書くかで
ある。実行の打ち切りと依頼者への通知は `docs/specifications/flow.md` が扱う。

| 事象 | 種別 | 生成文書の扱い | 定義済みか |
|---|---|---|---|
| 常設章に書く材料が入力に無い | 正常系エッジ | 章を残し、該当が無いことと根拠を書く | 定義済み（SP-AUTHORING-010・SP-AUTHORING-087） |
| 条件付き章の設置条件を満たさない | 正常系エッジ | その章を置かない | 定義済み（SP-AUTHORING-009） |
| 閾値が入力から確定していない | 準正常系 | 数値を書かず未確定事項として起票する | 定義済み（SP-AUTHORING-025） |
| 要求の根拠が入力から辿れない | 準正常系 | 推測を書かず未確定事項として起票する | 定義済み（SP-AUTHORING-079） |
| 入力に実在の人物の氏名またはアカウント名が含まれる | 準正常系 | 役割名に置き換えて書く | 定義済み（SP-AUTHORING-033・SP-AUTHORING-034） |
| 決定者と期限が依頼者から示されていない | 準正常系 | 欄を空欄のまま残す | 定義済み（SP-AUTHORING-057） |
| 生成文書一式に同一の ID が 2 件以上ある | 異常系 | 領域コードで区別し、重複を残さない | 定義済み（SP-AUTHORING-041・SP-AUTHORING-042） |
| 2 つ以上の topic が同一の領域コードになる | 異常系 | 領域コードが衝突しない topic に直す | 定義済み（SP-AUTHORING-062） |
| 本文が参照する ID が生成文書一式に存在しない | 異常系 | 参照先が実在する ID に直す | 定義済み（SP-AUTHORING-045） |
| 扱う対象に状態遷移があるかを判定できない | 異常系 | 未定義 | 未定義（`docs/requirements/consumer.md` の TBD-RCONSUMER-003） |
| ある語が曖昧語の集合に属するかを判定できない | 異常系 | 未定義 | 未定義（TBD-SAUTHORING-001） |
| ある項目が 2 つ以上の動作を含むかを判定できない | 異常系 | 未定義 | 未定義（TBD-SAUTHORING-002） |
| 根拠の記述が定めた上限に収まらない | 異常系 | 未定義 | 未定義（TBD-SAUTHORING-006） |
| ある条件節が条件節のパターンの集合に属するかを判定できない | 異常系 | 未定義 | 未定義（TBD-SAUTHORING-007） |
| 根拠の併記を機械が同定できない | 異常系 | 未定義 | 未定義（TBD-SAUTHORING-009） |
| 該当と判定された観点が 0 件で、未判定の観点が残る | 異常系 | 未定義 | 未定義（TBD-SAUTHORING-018） |
| ある観点がその生成文書の関心事に関わるかを判定できない | 異常系 | 未定義 | 未定義（TBD-SAUTHORING-005） |
| 発生しない組み合わせ以外の行に、定義されているかどうかを何と書くかが決まらない | 異常系 | 未定義 | 未定義（TBD-SAUTHORING-012） |
| 生成文書を書き出す先のディレクトリとファイル名が決まらない | 異常系 | 未定義 | 未定義（TBD-SAUTHORING-015） |

## 検証方法

本文書の仕様項目は、次の 3 つの手段で確かめる。どの仕様項目をどの手段で確かめるかは
トレーサビリティ表の検証方法の欄が持つ。検査を実行する工程と、指摘を改稿へ回す手順は
`docs/specifications/verification.md` が扱う。

| 手段 | 何を測るか |
|---|---|
| 静的検査 | 生成文書の本文を機械的に走査し、規則に反する箇所の件数を測る |
| 構造検査 | 生成文書一式の ID の集合とトレーサビリティ表の集合を突き合わせ、片側にしか現れない ID の件数を測る |
| 目視検査 | 生成文書を読み、規則に反する箇所の件数を測る |

静的検査と構造検査の結果が 0 件であることは、機械的に判定できる仕様項目を満たしたことを
示すにとどまり、目視検査で確かめる仕様項目を満たしたことを示さない。

判定規則そのものが未確定である仕様項目については、検証方法を定められない。該当する
行の検証方法の欄には、判定規則を持つ未確定事項の ID を書き、その未確定事項が決まるまで
検証方法を定められない旨を記す。件数を測る手順を先に書くと、判定規則が決まる前から検査が
実施できるように読める。

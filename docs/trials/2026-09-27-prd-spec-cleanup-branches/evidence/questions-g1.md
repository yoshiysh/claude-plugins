## RS-022

取り込み済みのブランチを確認なしで消している途中で 1 本の削除に失敗したら、残りのブランチの削除を続けますか?

依頼文（貼り付けられた SKILL.md の Step 2・Step 7）を探しましたが、取り込み済みのブランチの削除に失敗したときにどうするかは書かれていませんでした。前の回答（RS-012「続けて報告する」）は、承認を得てから消すブランチについての答えで、確認なしで消すブランチには当てはまりません。

- **残りの削除を続ける**: 選ばれたら — F-014 の「失敗」の後も、残りの取り込み済みブランチの削除（F-013）を続ける。失敗したものは完了報告（F-046）に載せる。決まる内容:「取り込み済みブランチの確認なし削除が失敗しても、残りの取り込み済みブランチの削除を続け、失敗したものを失敗の内容とともに完了報告に載せる」
- **そこで削除をやめる**: 選ばれたら — F-014 の「失敗」の後、残りの取り込み済みブランチは削除せずに残す。失敗したものと残したものを完了報告（F-046）に載せる。決まる内容:「取り込み済みブランチの確認なし削除が失敗したら、残りの取り込み済みブランチを削除せず、失敗したものと残したものを完了報告に載せる」

## RS-028

同期するとき、今いるブランチ（まだ取り込まれていない・push していないコミットを持つこともある）の位置を最新の主ブランチへ動かしますか?

依頼文（SKILL.md の Step 5）は、open の PR が無ければ今のブランチの位置を主ブランチの最新へ合わせると書いています。一方で、位置を動かすと失うものがあるので PR があるときは動かさないこと、まだ取り込まれていない内容はそのブランチにしか無いことも書いています。今のブランチが push していないコミットを持つとき、位置を動かすとそのコミットはそのブランチからは辿れなくなります。どちらを優先するかは依頼文からは決まりませんでした。

- **今どおり合わせる**: 選ばれたら — 流れの要素は変わらない。F-035 の false の枝は F-037（現在の位置を合わせる）へ進む。決まる内容:「現在のブランチに基準ブランチを base とする open の PR が無いとき（現在のブランチが無い場合を含む）、現在の位置を起点ブランチの remote 側の最新へ合わせてから作業用ブランチを作る。現在のブランチの未 push の commit は、そのブランチからは辿れなくなりうる」
- **今のブランチは動かさない**: 選ばれたら — F-035 の false の枝も F-036（reset せず起点ブランチの remote 側の最新から新ブランチを直接作る）へ向け、F-037 を除く。決まる内容:「open の PR の有無にかかわらず、現在のブランチの位置を動かさず、起点ブランチの remote 側の最新から作業用ブランチを作る」
- **未取り込みなら動かさない**: 選ばれたら — F-035 の false の枝に「現在のブランチが取り込み済みか」の判断を足す。取り込み済みでないときは F-036 と同じく動かさずに作り、取り込み済みのとき（現在のブランチが無い場合を含む）は F-037 へ進む。決まる内容:「現在のブランチが取り込み済みでないときは、現在のブランチの位置を動かさず、起点ブランチの remote 側の最新から作業用ブランチを作る。現在のブランチが取り込み済みのとき（現在のブランチが無い場合を含む）は、現在の位置を起点ブランチの remote 側の最新へ合わせてから作業用ブランチを作る」

### RS-021（対象: {"open": "O-005"}）

**保持規則**: 確認なしで消す終了済み workspace の削除が失敗したときの行き先の裁定が下るまで、その失敗の後に残りの処理（判断が要るものの問いかけ・同期・作業用ブランチの作成）へ進むか止めるかを要求・仕様として定めてはならない

````markdown
## 裁定してほしいこと
cleanup-branches で、終了済み workspace を確認なしで削除する（RS-020 の回答）とき、その削除が失敗したら処理を続けるか止めるか、完了報告に何を載せるか。

## 背景
- 承認済みの削除の失敗は「続けて報告する」と決まっている（RS-012）が、確認なしの workspace 削除はその対象外になった。

## 候補
- 続けて、失敗した workspace と失敗の内容を完了報告に載せる
- そこで止めて、失敗と残した処理を報告する
````

### RS-032（対象: {"finding": "r3-im-requirements__cleanup-branches-001"}）

**保持規則**: merged の PR の head との一致を名前だけで判定するか、その PR が作られた元のブランチであることまで求めるかの裁定が下るまで、PR の head と名前だけが一致しその PR が作られた元のブランチであると確かめられないブランチを、PR の判定を根拠に取り込み済みに分類してはならず、確認なしで削除してはならない

**触れる項目**: PR-CLEANUP-008、PR-CLEANUP-063、PR-CLEANUP-012、requirements/cleanup-branches§用語

**Issue の文案**:

````markdown
## 裁定してほしいこと
cleanup-branches で、ブランチが「基準ブランチを base とする merged の PR の head である」かを、ブランチ名の一致だけで判定してよいか、それともその PR が作られた元のブランチ（同じリポジトリのブランチ）であることまで求めるか。

## 背景
- 要求文書の PR-CLEANUP-008 は merged の PR の head であるブランチを取り込み済みに分類し、PR-CLEANUP-012 により確認なしで削除する。PR-CLEANUP-063 は「名前で一致」と書くが、008 は一致の意味を定めていない（段 8 の監査指摘 r3-im-requirements__cleanup-branches-001）。
- 現在の実装は `gh pr list --json headRefName,baseRefName` の head 名だけで照合しており、PR がどのリポジトリのブランチから出されたかを見ていない（scripts/repo_state.py L225・L233）。
- 決定済みの RS-030 は、名前が一致しマージ後に commit を足したブランチを取り込み済みにしないことだけを定め、PR の出元が別のブランチである場合を扱っていない。

## 起こりうること
fork の利用者が自分の fork の patch-1 から main へ PR を出して squash merge された。origin には保守者の別の patch-1 があり、そのマージより前に push した commit を持つ。名前だけで判定すると origin/patch-1 は取り込み済みとして確認なしで削除され、どの基準ブランチにも無い commit が失われる。

## 候補
- 名前だけで判定する（今の実装どおり。fork 由来の同名ブランチは確認なしで消えうる）
- PR が作られた元のブランチであることまで求め、確かめられないものは取り込み済みにしない（要判断または削除しないに回る）

## 裁定までの扱い
保持規則: PR の head と名前だけが一致し、その PR が作られた元のブランチであると確かめられないブランチを、PR の判定を根拠に取り込み済みに分類せず、確認なしで削除しない。
````

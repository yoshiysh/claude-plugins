## 保持規則と Issue の文案

### RS-027

**保持規則**: ローカルブランチを持たない remote 削除済みブランチの追跡 ref を prune で消すことが RS-004 の守る未取り込みのブランチの作業を失うことに当たるかの裁定が下るまで、F-003（リポジトリの状態を取る）は、ローカルブランチを持たず、どの主ブランチにも取り込まれていない remote 削除済みブランチの追跡 ref を、利用者の承認なしに prune で消してはならない

**触れる項目**: F-003

**Issue の文案**:

````markdown
## 論点

リポジトリの状態を取る工程（F-003）は `--prune` つきで fetch する。prune は remote で削除済みのブランチの追跡 ref を消す。そのブランチにローカルブランチが無く、どの主ブランチにも取り込まれていなければ、追跡 ref が内容の唯一の写しであり、prune の後は取り直せない（RS-017）。

RS-004 は、未取り込みのブランチの作業を利用者の承認なしに失わないと定めている。この追跡 ref の削除が RS-004 の守るものに当たるかを決めてほしい。

## 候補

- 当たらない: remote で削除済みのブランチは守る対象の外とし、prune は承認なしに行ってよい
- 当たる: 該当する追跡 ref があるときは、prune の前に一覧を示して利用者の承認を得る

## 裁定が下るまで

ローカルブランチを持たず、どの主ブランチにも取り込まれていない remote 削除済みブランチの追跡 ref は、利用者の承認なしに prune で消さない。
````

### RS-052

**保持規則**: 承認を得て削除する未取り込みのブランチに削除の前に復元用のタグを作るかの裁定が下るまで、cleanup-branches は、承認された未取り込みのブランチ（ローカル・remote）を、そのブランチを指す復元用のタグを作る前に削除してはならず、復元用のタグを作れなかった承認された未取り込みのブランチを削除してはならない。

**触れる項目**: PR-CLEANUP-034、PR-CLEANUP-035、PR-CLEANUP-038、PR-CLEANUP-039、PR-CLEANUP-062

**Issue の文案**:

````markdown
cleanup-branches で、利用者の承認を得て削除する未取り込みのブランチ（ローカル・remote）に、削除の前に復元用のタグ（deleted-branches/…）を作るかを決めてください。依頼者の回答「削除タグは不要。マージ済みなら確認不要で削除してよい」は、取り込み済みのブランチ（今もタグを作らない）についてか、未取り込みのブランチのタグもやめる意図かが文面から決まりません。候補: (a) 削除の前に復元用のタグを作り、作れなければ削除しない (b) 復元用のタグを作らずに削除する。(b) では削除した未取り込みのブランチを戻す手がかりが残りません。決まるまでは (a) と同じ振る舞いに留めています。
````

````markdown
cleanup-branches で、取り込み済みのローカルブランチを確認なしに削除する範囲を決めてください。候補: (a) 主ブランチの履歴・merged の PR・パッチの一致（git cherry の patch-id 比較）の 3 経路で判定したものを確認なしに削除する（貼り付けの SKILL.md の現状） (b) git branch --delete-merged のように主ブランチの履歴に含まれるものだけを確認なしに削除する。依頼者の回答「git branch --delete-merged とかで削除できるようになったらしい」は伝聞で、手段を切り替えたいかが文面から決まりません。決まるまでは、履歴に含まれないローカルブランチを取り込み済みとして確認なしに削除しない振る舞いに留めています。
````

````markdown
cleanup-branches で、一度も push されず追跡先の remote のブランチを持たない未取り込みのローカルブランチを、削除してよいかを利用者に問う対象に入れるかを決めてください。貼り付けの SKILL.md は問うローカルのカテゴリを「remote 削除済みだが未取り込み」と名付け、理由を作業がローカルにだけ残っていることに置いています。候補: (a) 問う対象に入れる (b) 問わずに削除せず残し、完了報告の要判断のまま残したものに載せる。決まるまでは削除せず、要判断のまま残したものに載せる振る舞いに留めています。
````

### RS-055

**保持規則**: 判断が要る対象の承認と一覧の要求を 1 つに併せ持つ応答の扱いの裁定が下るまで、cleanup-branches は、そのような応答をもとに判断が要る対象を削除してはならない。

**触れる項目**: PR-CLEANUP-028

**Issue の文案**:

````markdown
cleanup-branches で、削除してよいかの問いへの 1 つの応答が、あるカテゴリの候補を名指しした承認と、別のカテゴリの一覧の要求を併せ持つとき（例:「feature/a は消して、remote の方は一覧を見せて」）の扱いを決めてください。候補: (a) 選択肢に当たらない応答として何も削除せず残したものとして報告する (b) カテゴリごとに分け、承認された対象を削除し、一覧を求めたカテゴリの一覧を示す。決まるまでは、そのような応答で何も削除しない振る舞いに留めています。
````

### RS-056

**保持規則**: 完了報告の作業状態の件数をどの時点で数えるかの裁定が下るまで、cleanup-branches は、完了報告の作業状態に、状態の取得の時点と完了報告の時点のどちらで数えた件数かを示さずに件数を載せてはならない。

**触れる項目**: PR-CLEANUP-062、PR-CLEANUP-045

**Issue の文案**:

````markdown
cleanup-branches の完了報告に載せる作業状態（submodule のポインタ差分・tracked ファイルの未コミット差分・未追跡ファイル・stash の件数）を、どの時点で数えるかを決めてください。状態の取得の後に、後処理のコマンドが未追跡のファイルを作ったり、退避を戻す操作が衝突して退避が stash に残ったりするので、2 つの時点で件数が変わりえます。候補: (a) 状態の取得の時点の件数を載せる（実行の前にあったものを知らせる） (b) 同期・後処理・退避を戻す操作を終えた完了報告の時点の件数を載せる（今残っているものを知らせる）。決まるまでは、どちらの時点で数えた件数かを報告に示す振る舞いに留めています。
````

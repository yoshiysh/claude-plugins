### RS-052

**保持規則**: 承認を得て削除した未取り込みブランチを後から復元する手段を要求とするかの裁定が下るまで、要求文書は、その手段の用意をスコープ外と定めてはならず、要求として課してもならない。

**触れる項目**: requirements/cleanup-branches§スコープとスコープ外、PR-CLEANUP-027、PR-CLEANUP-031

**Issue の文案**:

````markdown
## 論点
承認を得て削除した未取り込みブランチ（その作業はそのブランチにしか無い）を、後から復元できる手段をシステムが用意する必要があるか。

## 経緯となる事実
- 元の SKILL.md は、reflog は保持期限があり同一マシン限定なので、それに依存しない復元手段（退避タグ）を先に用意してから消すとしていた。
- 依頼者は「退避タグ不要」と回答し、退避タグは削除の前提から外れた。
- 退避タグ以外の復元手段を要るとするか要らないとするかは、どの回答にも無い。

## 選択肢
- 復元手段は要らない: 承認は依頼者が失ってよいと判断した印とし、削除後の復元は保証しない。
- 退避タグ以外の復元手段を要る: 削除の前に、reflog に依存しない復元の手がかり（削除したブランチの commit の控えなど）を残し、完了報告でブランチと対にして示す。

## 決まるまでの扱い
要求文書はこの手段をスコープ外とも要求とも書かない。
````

### RS-054

**保持規則**: 開いた PR の有無が分からないときに現在のブランチが指す commit を動かすかの裁定が下るまで、システムは、PR 情報の取得元が使えず開いた PR の有無が分からないとき、現在のブランチが指す commit を動かしてはならない。

**触れる項目**: PR-CLEANUP-036、PR-CLEANUP-037、PR-CLEANUP-016

**Issue の文案**:

````markdown
## 論点
PR 情報の取得元が使えず、現在のブランチが主ブランチを base とする開いた PR を持つか分からないとき、現在のブランチが指す commit を起点ブランチの remote 上の最新へ動かすか。

## 経緯となる事実
- 開いた PR があるときは、ローカルのブランチが PR の head から離れるので commit を動かさない。無いときは動かす。
- PR 情報の取得元が使えないとき、分類は PR 情報を使わずに続けると決まっているが、同期の分岐の扱いは決まっていない。

## 選択肢
- 分からないときは動かさない: 開いた PR がある場合と同じく、現在のブランチはそのまま残し、新ブランチを起点ブランチの remote 上の最新から作る。
- 分からないときは無いとみなして動かす: 開いた PR が実際にあると、PR の head に未 push の commit があればどのブランチからも辿れなくなる。

## 決まるまでの扱い
有無が分からないとき、システムは現在のブランチの commit を動かさない。
````

### RS-057

**保持規則**: 同期の後に作業ツリーのファイルを起点ブランチの remote 上の最新の内容に揃えるかの裁定が下るまで、要求文書は、同期の後の作業ツリーのファイルを最新の内容に揃えるとも、動かす前の内容のまま残すとも定めてはならない。

**触れる項目**: PR-CLEANUP-037、PR-CLEANUP-038

**Issue の文案**:

````markdown
## 論点
開いた PR が無いときに現在のブランチが指す commit を起点ブランチの remote 上の最新へ動かした後、作業ツリーのファイルを最新の内容に揃えるか、動かす前の内容のまま残すか。

## 経緯となる事実
- 入力は目的を「worktree を最新の主ブランチに同期」とする。
- 入力の手順は `git reset --mixed origin/<sync_base>` で同期してから新ブランチを作るとしており、この操作は作業ツリーのファイルを動かす前の内容のまま残す。
- 未コミットの変更は同期の前に退避し、完了の前に戻す。

## 選択肢
- 最新の内容に揃える: 新ブランチは差分の無い状態で始まり、その上に退避した変更が戻る。
- 動かす前の内容のまま残す: 動かす前のブランチより後に主ブランチへ入った変更を打ち消す差分が未コミットの変更として現れ、その上に退避した変更が戻る。

## 決まるまでの扱い
要求文書は同期の後の作業ツリーの内容をどちらとも定めない。
````

### RS-058

**保持規則**: 比べる相手の主ブランチが同じ実行で削除される場合にもその相手に内容があるとみなすかの裁定が下るまで、システムは、ローカルの主ブランチを、同じ実行で削除される他のローカルの主ブランチにだけ内容があることを根拠に、取り込み済みとして削除してはならない。

**触れる項目**: PR-CLEANUP-010、PR-CLEANUP-011

**Issue の文案**:

````markdown
## 論点
取り込み済みかを判定するとき、比べる相手の主ブランチが同じ実行で削除される場合にも、その相手に内容があるとみなすか。

## 経緯となる事実
- 取り込み済みのブランチは、内容が他の主ブランチにあり消しても失われないことを根拠に、確認なしで削除する。
- ローカルの主ブランチも他のブランチと同じ分類に従い、分類している ref 自身だけを比べる相手から除く。
- ローカルの main と develop が同じ push していない commit を持つと、互いを相手に両方が取り込み済みになり、両方が確認なしで削除され、その commit はどのブランチからも辿れなくなる。

## 選択肢
- 同じ実行で削除される相手は内容の置き場とみなさない: 相手が残る主ブランチ（remote の主ブランチを含む）にだけ内容を認める。
- 今のまま相手に内容があるとみなす: 同じ push していない commit を持つローカルの主ブランチどうしは両方とも確認なしで削除されうる。

## 決まるまでの扱い
システムは、同じ実行で削除される他のローカルの主ブランチにだけ内容があることを根拠に、ローカルの主ブランチを取り込み済みとして削除しない。
````

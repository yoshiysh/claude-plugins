# レビュー基準（claude-plugins）

このリポジトリは Claude Code 向け skill/plugin をパッケージングして配布する。
レビューは「動くか」ではなく「配布物として構造が壊れていないか」を見る。
判断に迷ったら本ファイルより `CLAUDE.md`「作業ルール」節と
`plugins/skill-creator/skills/skill-creator-best-practices/references/best-practices.md`
を正本として直接参照する。

## 観点

### 1. 役割分担と正本の一意性

- skill の実体は `.agents/skills/<name>/` にあるか。`plugins/` 配下に symlink や
  実体の重複を作っていないか。
- 同じ値・列挙・上限が複数箇所に書き写されていないか（named constant か単一文書を
  正本にして他は参照する形になっているか）。
- オーケストレーター役（SKILL.md 本体・司令塔スクリプト）が成果物の生成・修正・
  採点を自分で行っていないか。生成は agent/script へ委譲し、フロー制御に徹して
  いるか。

### 2. 生成と検証の分離

- 自分が書いた成果物・修正に自分で合格判定を出す構造になっていないか
  （generator と verifier が同一 agent / 同一パスに同居していないか）。
- 検証が単一視点（1 レンズ・1 モデル）に依存し、fan-out や multi-agent 相当の
  多角評価を要する箇所で省略されていないか。

### 3. 根本解決 vs 対症療法

- 注意書き・コメント・ドキュメントだけで防ごうとしている箇所が、構造（正本参照・
  script による配達・型 / schema 検査）で防げないか検討されているか。
- 防御パッチ（例外条項・監視のみ）で症状を塞ぎ、原因（設計・データフロー）を
  残していないか。

### 4. 不在・網羅の断定

- 「〜は無い」「全て〜」「〜のみ」といった断定に、閉集合の全列挙・全文読み・
  形を変えた複数回検索のいずれかの裏付けがあるか、または手段でスコープされて
  いるか（「grep で見た範囲では」等）。
- rename・削除の sweep 後、残存 0 件を再 grep で確認してから網羅を主張して
  いるか。

### 5. SKILL.md とスキル構造

- `SKILL.md` の frontmatter に `name` / `description` があるか。
- `SKILL.md` 本体が概要・フロー制御に留まり、具体的な処理を `scripts/` に
  寄せているか（500 行を大きく超えて肥大化していないか）。
- スキル参照は SKILL.md から 1 階層で完結しているか（孫参照で情報が分断されて
  いないか）。

### 6. コメントと後方互換

- コメントが「何をしているか」の説明になっていないか。書くべきは
  コードから読めない制約・根拠（why）だけで、経緯は commit message / PR 本文へ
  出ているべき。
- 存在しない後方互換レイヤー（旧形式の migration・fallback）を新規に持ち込んで
  いないか。plugin の version bump（配布機構）はこの対象外。

## Severity の付け方

- **CRITICAL**: 配布される skill/plugin が壊れる（参照切れ、symlink 経由での実体
  破壊、seccheck 対象の欠落）。セキュリティ上の欠陥。
- **HIGH**: 正本が二重化して drift する設計、生成と検証が未分離、根本原因を
  残す対症療法。
- **MEDIUM**: SKILL.md 構造違反、不在・網羅の断定に裏付けが無い、命名規約違反。
- **LOW**: 冗長なコメント、docstring・ドキュメントの誤字、テストの品質。

意図に反する挙動を生む機能的なバグは HIGH 以上とする。

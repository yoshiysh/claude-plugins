### 1. アーキテクチャ設計の反映（マルチエージェント系スキルの場合）

生成するスキルが Sub-agent を使う設計の場合、以下を決定する。

`references/coordination-patterns.md` を Read して参照すること。

- **採用パターン**：Orchestrator-Subagent / Generator-Verifier / Parallelization / Agent Teams / Shared State から選択（複数可）
- **Sub-agent の列挙**：各 agent の名前・担当モデル・単一の責務（1行）
- **モデル選定の根拠**：Opus / Sonnet / Haiku それぞれの割り当て理由
- **assets に分離するもの**：変化しない参照データ（仕様・コンポーネント集・設定値）を `assets/` に分離する

単一責務チェック：
- 各 agent は「1入力 → 1出力」か
- 判断・変換・生成が1つの agent に混在していないか
- Orchestrator（SKILL.md）にドメイン知識が混在していないか

### 2. セクションの特定

追加・変更・削除それぞれのセクションを列挙する。
既存セクションのどこに挿入するか、位置を明示する。

### 3. 各セクションのコンポーネント選定

使用するコンポーネントを列挙する（カード・タブ・タイムライン・コールアウト等）。

制約：
- 必ず既存のコンポーネントから選ぶ。新規コンポーネントを作らない
- 選んだ理由を1行で添える
- 実現できないと判断したものは ⚠️ を付けて懸念点に記載する

### 4. 情報の流れ

ユーザーがどの順序で読むと理解しやすいかを説明する。
各セクションが次のセクションにどうつながるかを示す。

### 5. 目次・nav への反映内容

追加・削除・変更が必要なエントリを具体的に列挙する。
省略しないこと。セクションを変更するなら必ず対応するエントリを書く。

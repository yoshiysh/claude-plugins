# タスク種別ごとの検証基準定義

基準生成・基準補完 Sub Agent が参照するデフォルト基準。
これはあくまで出発点であり、スキル固有のリスクを加えた上で使うこと。

---

## 全タスク種別共通

- description が3人称で書かれているか（"I can help" や "〜できます" は禁止）
- description に [What]（何をするか）と [When]（いつ使うか）の両方が含まれているか
- description に除外条件（対象外）が明記されているか
- name が kebab-case（英小文字・ハイフン区切り）か
- name が gerund 形式（processing-pdfs, analyzing-data など）または明確な動詞句か
- SKILL.md 本体が500行以内か
- 参照ファイルが SKILL.md から1レベルの深さに収まっているか
- 100行を超える参照ファイルに冒頭目次があるか
- 時間依存の情報（「〇年以降は〜」）が含まれていないか
- 用語が一貫しているか（endpoint / URL / path が混在していないか等）

## document 系

- description は「いつ使うか」と「何をするか」の両方を含んでいるか
- 出力フォーマット（HTML / Markdown / 構造など）が具体的に定義されているか
- 対象読者のレベルに合った言葉遣いになっているか
- 非エンジニアがコピペできる操作手順が含まれているか
- 生成物のファイル名・保存場所が明示されているか
- 実際の入力例と出力例がセットで1パターン以上含まれているか（「省略」は不可）

## workflow 系

- 各ステップが独立して理解できるか（前後の文脈なしで）
- エラー時・例外時の処理指針が含まれているか
- 人間が介入すべきタイミングが明示されているか
- 入力の形式・制約が明確か
- ステップ間のデータの受け渡し方が定義されているか
- フィードバックループ（検証→修正）が設計されているか

## data 系

- 入力データの形式・スキーマが定義されているか
- 出力の精度基準・許容誤差が設定されているか
- データが欠損・不正な場合の挙動が記述されているか
- サンプル入出力が含まれているか
- 処理量・タイムアウトなどのスケール制約が明示されているか

## 構成（ブラックボード）

| 部品 | 実体 | 持つもの |
|---|---|---|
| ボード | `stateDir/ledger.json` | 目標・受け入れ基準・制約・決定の記録・段（`phase`・`phase_start`・`phase_records`）・観点・計画・単位・事実（`facts`）・意図の試行・束ねの群（事実から導いた写し）・振り返りの指摘（`retro_findings`）・全文レビューの記録（`full_review`）・出来事・起動の記録 |
| ボードの周りのファイル | `stateDir` の下 | 写し（`snap/`）、ヒント（`hints.jsonl`）、呼び出しの args（`call-<callId>.json`）、役の結果（`results/`）、段の位置（`phase.json`）、止まったときの status（`status-<段>.json`。段の無い台帳は `status.json`）、役の入口（`ledger-cli.mjs`）、lock（`ledger.lock`） |
| 知識源 | Workflow source の役（`scripts/roles.json`） | 担当の判断だけ。台帳を直接書かず、対象も書かない |
| 制御 | `scripts/ledger-cli.mjs` | 呼び出しを開く（`next`）、波を進める（`claim`。次の波の記録と止める印）、呼び出しを閉じる（`ingest`）、役の読み書き（`claim`・`query`・`submit`）の受け入れ、意図の生成、止める判定 |

台帳を書くのは CLI だけで、役の出力は返り値・args・prompt で運ばない。役は `claim` で担当を取り、`query` で入力を引き、`submit` で結果を出す。運ぶ工程を無くせば、長い値の写し違いと、照合を通らずに次の役へ渡る経路が構造として無くなるため。

`ledger.json` が今の形の欄（目標の項目・段の記録・事実・意図の試行・振り返りの指摘・全文レビューの記録など）を持たないか、前の形の欄（横展開の型 `lateral_types` など）を持てば、init 以外のコマンドが読み込みで拒否する。形の違う台帳は新しい `stateDir` で init からやり直す。

## 呼び出しと役の読み書き

- 呼び出しを開く: `next` は次の段を決め、args `{state, callId, wave}` を `call-<callId>.json` に書いて、その path（`args_path`）を返す。`wave` は最初の波 `{id, rows}` で、id は台帳の連番（`wave_seq`。呼び出しをまたいで増える）、行は `{id, role, model, effort, stage}`（id は呼び出しの中で重ならない）。段と担当から役の名前への対応は ledger-cli.mjs の `stageTasks`・`INTENT_ROLE`、役のモデルと effort は台帳の役の設定（`roles.json` に `init --roles` の上書きを重ねたもの）が決める。`estimate_agents` は最初の波の行の数。ファイルの段と振り返りの行は詰め合わせ 1 つに 1 体で、詰め合わせの数を、`meta.limits.maxAgents` からその呼び出しで出した行を引いた数と、残りの起動数の予算（`max_agents_total`）に収め、残りは次の波か呼び出しで読む。全体の段の行は役（判定役・確認役）ごとに `config --workers` の数（既定 1）で、`--workers` が決めるのはこの数だけ。計画の段の行は計画役 1 つか観点の検証役 1 つ。全文レビューの行は `full_reviewer` の 1 つで、`--workers` によらない。
- 波: 1 回の呼び出しは、段ごとの波を順に流す。
  - 段の間の決定的な遷移（周を開く `openCycle`・計画の提案を飛ばす `skipStuckPlan`・全文レビューの記録を合わせる `syncFullReview`・振り返りの単位を作る `retroAssets`）は `advance` 1 つにまとめ、`next` と `claim` が同じものを流す。中身は前と同じ。
  - 順序の門: `claim` は、その時の `decide` の段が今の波の段と合うときだけ担当を渡す。合わなければ、その波の取られていない担当と取りを試行に数えずに手放す（`staleWave`）。判定の順序は `next` の順と同じになる。
  - 次の波: 波の担当が尽きた（done を受け取っていない行のどれにも取れる担当が無い）時点の `claim` の done に、CLI が台帳に記録した次の波（`next_wave: {id, rows}`）を載せる。中身が変われば新しい id で記録し直す。止まる条件に当たったとき、呼び出しを開いてからの経過（`opened_at` から。時刻は環境変数 `COVERAGE_AUDIT_NOW_MS` で差し替えられる）が `timeoutMs − agentTimeoutMs` を超えたとき、出した行の和（`rows_total`）が `maxAgents` か予算に達したときは、`halt: true`・`reason` と、当たった区切りの種類 `halt_kind`（`stop`・`time`・`limit`・`rows`）を載せる。呼ぶ側は種類をこの欄で判じ、`reason` の文で判じない。Workflow script は時刻を読まず、行を切り詰めない。
  - 照合: `claim` は `--wave`・`--worker`・`--model`・`--effort`・`--stage` を台帳の波の記録と照らし、違えば台帳を変えずに終了状態 2 で拒む。役が運ぶのは制御の印だけで、書き換えても空の起動か早い停止になるだけ。前の波の行の claim は done だけを返す。
  - 会計: 段ごとの会計（取ったまま出さなかった担当の試行・`missing_*` の出来事・`lost`）は、波の境目（記録した次の波の最初の claim）と `ingest` で今の波について締める（`closeWave`）。境目では、閉じる波の claim の 1 回も無い行を `agent_missing` に残す（同じ呼び出しの後の振り返りが読み、ingest は同じ行に二重に足さない）。振り返りの波へ移るときに出来事が増えれば、読まなかった振り返りの単位だけを作り直す（読んだ単位は作り直さない）。環境の失敗の印（`env_attempts`）は締める波ごとに、その波の進みで付ける（前の波に進みがあっても、進みの無い波の取り残しは環境の失敗の試行に数え、blocked からの再開で戻る）。`fail_streak` だけは呼び出しの全ての波で判じ、どれかの波に進み（受理・提出）があれば数えない。振り返りの単位を作り直すときは、同じ出来事を含んでいた元の単位の試行を引き継ぐ（取り残し続ければ `MAX_ATTEMPTS` で開示する）。ingest の時点でしか足されない出来事（claim した後に返らなかった行の `agent_missing`、`launch_mismatch`）は、その周の振り返りに入らず `events_not_in_retro` に出る。claim も起動の記録も無い次の波は数えずに捨て、次の `next` が作り直す。起動されたのに claim しない行は、起動の記録に波があれば、その波を締めて数える。
- 冪等: 開いた呼び出し（`pending`）がある間の `next` は、同じ `call_id` と、今の波（記録した次の波があればそれ、無ければ閉じていない今の波）の args を返す（最初の波なら同じ `args_path`）。対象の読み直し（変わった単位を読み直しにする）だけは流す。Workflow が途中で落ちても、`next` の args で流し直せば続きから進む。
- 旧い形: `wave_seq`・`contexts`・`target_gaps`・`repo` の無い台帳は、init 以外のコマンドが拒否する（補って書き直さない）。
- Workflow: `scripts/coverage-audit.js` は args を照らし、波の行ごとに役を 1 体起動する。prompt には担当を取る命令（行の `--wave`・`--model`・`--effort`・`--stage` を埋める）と手順・結果の形だけを置き、命令は `stateDir/ledger-cli.mjs`（init と next のたびに CLI が書き直す、本物の CLI を流すだけの入口）を使う。args で CLI の置き場を運ばないため。役の返り値（`WORKER_SCHEMA`）は `notes` と、最後の claim の印（`next_wave_id`・`rows`・`halt`）だけ。script は返ってきた中で最大の `next_wave_id` の行で次の波を起動し、`halt` があるか、id が今の波より大きくないか、行の形が壊れていれば起動しない。返り値は起動の記録（段と波の印つき）と token（`{agents, tokens}`）だけ。
- 閉じる: `ingest --call <callId> --result <返り値のファイル>` は、その呼び出しを閉じるだけ。返り値から読むのは `agents`（段と波の印つきで取り込む）と `tokens` で、役の出力は既に `submit` で台帳にある。起動の記録の model・effort・段が台帳の波の行と違う起動と、記録に無い波の起動は、出来事 `launch_mismatch` に残す（その提出は claim が既に拒んでいる）。取ったまま提出されなかった担当は試行に数える（全体の段の意図は下の「全体の段」の試行の数え方）。環境の失敗（blocked の failure の連続）に数えるのは進みの無かった呼び出しだけで（`noProgress`。全体の段で claim も受理も 0、ファイルの段と振り返りで提出が 0、計画の段で全ての役が欠けて受理が 0。全文レビューの呼び出しは数えない）、役が返らなくても受理か提出があった呼び出しは数えない。全文レビューの担当が提出されなければ、全文レビューの記録の試行に数え（計画の段の `stuck` にしない）、出来事 `missing_full_review` を残す。役が返らなかったときはその場で（`cause: lost`）、提出されないまま試行が `MAX_ATTEMPTS` に達したときはそこで（`cause: unsubmitted`）、読まなかったとして開示し（`full_review_failed`）、先へ進む。`lost` は環境の失敗なので、blocked（failure）からの再開か、止まった後の新しい回の始まりで `open` に戻して読み直し、出来事 `full_review_reopened` を残す。`unsubmitted` と `rejected` は、下の持ち越しの規則で版が変わるまで流し直さない。1 体の時間の上限に当たった残りは、次の呼び出しが取る。待っている呼び出しと違う `--call` は拒否する。
- `claim --call --worker --wave --model --effort --stage`: 今の呼び出しの記録した波の行からだけ受け付ける（上の「波」）。担当の配列（`tasks`）と、提出の命令 `submit_cmd` を返す。出し終えていない担当を持つ worker には、それを同じ形で返し直す。取る物が無ければ `done`。返す前に結果の path（`results/<call>/<worker>/` の下）の古いファイルを消す。
  - ファイルの段と振り返り: 行に結んだ詰め合わせの単位を並びの順に全て取り、単位ごとの担当（写しの file と行の範囲・観点の一覧・義務〔目標と受け入れ基準〕・ヒント）を返す。出し終えていない単位があればそれだけを返し直し、全て出し終えた（受理か開示）後の claim は `done` を返す。同じ文脈で詰め合わせの外の単位を読ませないため。
  - 全体の段: 行の種類の開いた意図を、意図の並びの順で前から束で取り、意図ごとの担当（義務・意図・ヒント。観点の一覧は付けない）を返す。束の量は、その束で `query` が返す根拠・関係する事実・単位の索引のバイト数の和で測り、線（下の「単位と観点と持ち越し」）に収まる所まで詰める（ファイルの段の詰め合わせと同じ next-fit。1 件だけで超える意図は単独の束）。上限が半分になるのは下の「全体の段」の試行のとき。出し終えていない意図があればそれだけを返し直し、出し終えた後の claim は次の束を取る。全体の段と確認は意図と事実で判定し、観点の一覧を使わないため。
  - ほかの段: 行に結んだ担当を返す。
- `query --call --worker --task [--task ...] [--fact <id> ...]`: 担当の入力を台帳から引く。全体の段は `--task` を複数受け、束の全ての意図の入力を `--task` の順に `tasks` で 1 回で返す（`--task` が 1 つなら 1 件の形）。意図ごとに、根拠（`basis`）と関係する事実（`related`）と、載せなかった事実の宣言（`omitted`。目標の判定は `omitted_ids`・`omitted_more`）と、同じ箇所の指摘の組（`same_location`。全文レビューの指摘とファイルの段の指摘で、同じ単位の引用が包含し合う組。相手の事実は `related` に載る）だけを返し、`--fact` で事実を id で引き直せる。組はまとめず、同じ欠陥かは役が判じる。事実とその場所（`locations`）には、原文を開く写しの file・start・end が載り、役は対象の本体でなく写しを開く。全文レビューは、目標（冒頭の文・項目・基準・制約）と読む範囲の単位（id・path・写しの file と範囲）だけを返し、観点・索引・ヒント・事実は載せず、`--fact` は拒否する。ほかの段は、その担当に要る文（目標・依頼文・索引・案・欠陥・回答・観点・指摘）だけを返す。ファイルの段と振り返りの担当は拒否する。他の役の書き込み（前の run の指摘と判定を含む）を読まずに独立に読ませるため。
- `submit --call --worker`: 役は担当を書けたらその都度流す（時間の上限に当たっても、出した担当は台帳に残る）。全体の段では、束の全ての担当を書いてから 1 回流し、拒否された担当だけを直して出し直す（やり取りのたびに伸びた文脈を読み直すため）。その worker が取って出し終えていない担当のうち、結果のファイルがある担当を全て照らし、担当ごとの `results`（`ok`・`problems`・`dropped`）と、ファイルの無い担当の `missing` を返す。照合に落ちた担当は理由を返して試行に数え、結果のファイルを消す（直さずに流し直しても missing になり、同じ中身で試行を重ねない）。`MAX_ATTEMPTS` で、単位は開示（disclosed）、意図は判定できなかった意図（undecided）、全文レビューは読まなかったとして開示（`full_review_failed`、`cause: rejected`）に倒し `dropped` を返す。今の呼び出しと違う call・行に無い worker は、台帳を変えずに終了状態 2 で拒否する。
- lock: 台帳を書くコマンドは load から save までを `stateDir/ledger.lock`（`openSync` の `wx`）で囲む。待つのは `LOCK_WAIT_MS` までで、超えたら台帳を変えずに拒否する。lock は古さによらず自動で消さない（自動で奪うと 2 つの process が同時に台帳を書く窓ができる）。mtime が `LOCK_STALE_MS` より前なら、CLI が動いていないことを確かめてから手で消すよう案内する。lock には取得ごとの token を書き、自分の token のときだけ消す。
- `call_seq` は呼び出しを開くたびに進み、`callId` に入る。閉じた呼び出しへの遅れた claim・submit は拒否される。

## 段と、script と LLM の分け方

`next`（呼び出しの最初の波）と `claim`（次の波）が、同じ `advance` で段を決める。plan → unit_verify → full_review → file → global → retro の順で、run の中では周を足さない（横展開と束ねの反証を持たない）。

| 段 | LLM がすること | script がすること |
|---|---|---|
| init・reframe | なし | 目標・基準・制約の各項目に引用があり、引用が依頼文か決定の記録に逐語であるか（`readGoalFiles`）。照合済みの印（`--goal-checked coverage-build`）があれば引用は照らさない。項目の本文の path の形の語（`/` を含み拡張子で終わる語）が repo（`--repo`、無ければ cwd。台帳に覚え、answer も同じ基準）に実在するのに `--target` にも `--context` にも無ければ拒む（`framePathProblems`。照合済みの印のある台帳では照らさず、呼ぶ側が import して自分の対象と入力で照らす。実在しない path は照らさない）。通らなければ台帳を作らない・変えない |
| plan | 計画役 1 体が、既にある観点（query の `given_lenses`。呼ぶ側の観点と標準の観点）に足す観点・受け持つ目標の部分（`goals`）・制約の受け皿（`constraint_map`）・質問を作る。目標の照合が済んでいなければ（query の inputs に `item_ids` があるとき）、同じ体が依頼文と決定の記録の求める成果を引用つきで挙げ、受け止める項目の id を付ける（`outcomes`）。見直しでは前の計画と欠陥・回答から、欠陥ごとに直したか退けたか、Q3 の部分を受け持てる単位が対象に無いか（`defect_responses` の `fixed`・`rejected`・`no_target`）を返す。利用者の観点を渡しても流れる。印のある台帳では照合をしない | 目標の照合: 引用の実在・項目の id の実在（`checkGoalMap`）。外れは拒否して `plan` の試行に数える。どの項目にも受け止められていない成果（`goalGaps`）があれば、その回の計画は使わず needs_input（`goal_gaps`）にする。計画: 観点の形（計画の観点の手続きは `{enumerate, compare_with}` で、どちらも空でない文。Q1・Q2 の形の検査）・id の重複・既にある観点の定義し直しの拒否・part の逐語と、呼ぶ側の観点が無いときだけ目標と基準の被覆（`checkGoals`。呼ぶ側の観点があれば、目標の項目は全体の段の goal の意図が受け止める）・制約の受け皿・欠陥への応答の網羅（`checkPlan`）。計画の外れは 1 回出し直させ、出し直しでも残る外れは計画の欠陥 `P<n>` として受け取り、次の plan で直させる。`no_target` の応答は計画をやり直させず、needs_input（`target_gaps`）にする。呼ぶ側の観点があるときの提案が試行の上限まで出なければ、照合が済んでいる限り、出来事 `plan_skipped` を残して呼ぶ側と標準の観点で読み進める（提案は足すだけなので止めない） |
| unit_verify | 観点の検証役 1 体が、計画のまだ確かめていない観点の全てに、観点ごとに閉じた問い（Q1: `enumerate` が何を列挙するかを書いているか、Q2: `compare_with` が何と照らすかを書いているか、Q3: `goals` の要素ごとにその部分が果たされたかを確かめられるか）だけで yes/no と引用を答える | 観点ごとにちょうど 1 つの答えの組か、答えの過不足・yes/no・引用の逐語と自由な欠陥の拒否（`checkUnitVerdict`）、no の答えだけを計画の欠陥にする（`unitDefects`）。確かめた観点は中身の鍵（`unitKey`）で覚え、確かめ直すのは変わった観点だけ。担当を作った後に計画が変わったら、その担当は使わない |
| full_review | 全文レビューの役 1 体が、読む範囲の全ての単位を全文、観点に縛られずに目標・基準・制約だけを手に読み、指摘と参考を書いて submit する。指摘は複数の単位を引用してよく、義務・確信度・原因の層を持つ。保証・前提と観点ごとの「見た」は書かない | 読む範囲と持ち越し（`fullReviewScope`。下の「単位と観点と持ち越し」）。結果の照合（`fullReviewProblems`）: 指摘は全体の段が足す指摘と同じ形で、場所は読む範囲の単位だけ。`guarantees`・`premises` を書いた提出は拒否する。受理した指摘と参考を `origin: full_review` の事実にする。網羅（`coverage`・単位の状態）には数えない。範囲が空なら段を流さない |
| file | 読む役 1 体が詰め合わせの全ての単位を全文、全ての観点で読み、単位ごとに観点ごとの「見た」・指摘・参考・保証と前提を書いて、書けた単位から submit する。引用は自分の単位の本文だけから取り、単位をまたぐ食い違いは気づいた側の単位の前提として書く（またぐ指摘は全体の段が判定する） | 詰め合わせ（`packUnitsTo`。下の「単位と観点と持ち越し」）。結果の照合（`checkFileResult`）: 観点ごとにちょうど 1 つの答え（閉じた集合）と逐語の引用、指摘の義務・確信度・原因の層、found の観点の指摘。引用はその担当の単位の本文で照らすので、詰め合わせの他の単位を引いた提出は落ちる。受理した読み（本文の版・観点の組の版・役の条件・答えと引用）を単位に置き、事実を足す（`factsOf`） |
| global | 判定役 1 体が名寄せ・主語の照合・指摘の判定・前提・目標の意図を、確認役 1 体が確認の意図と最後の束ねの意図を、束で取り、根拠と関係する事実だけを引いて判定する（下の「全体の段」） | 意図の生成、判定の閉じた集合と引用の照合（`intentProblems`）、束ねの群の形（`checkGroups`）、受理した判定と足した指摘を事実にする |
| retro | 単独で呼ばれたときだけ、読む役（ファイルの段と同じ `file_reader`）が出来事の写しを振り返りの観点（R1〜R4）で読み、ファイルの段と同じ形で書く | 周ごとに 1 回、まだ振り返っていない出来事を全ての段にわたって 1 行 1 件で並べ、線に収まるよう行の境目で分けて振り返りの単位にし（`retroAssets`）、ファイルの段と同じ規則で詰める（全てが収まれば 1 体）。受理した読みの指摘は振り返りの指摘（`retro_findings`）にだけ置き、status の `retro` に出す。対象の指摘・事実・参考・意図・群・カバレッジには入れない（仕組みの出来事を対象の欠陥として数えず、起動も増やさないため）。読みの参考・保証・前提は台帳に残さない。印のある台帳では作らず、出来事を `status` の `events` で返す（振り返りの探索グラフを coverage-build の 1 つに寄せるため） |

静的な照合の式の正本は Workflow source の `// <checks>` 区間で、CLI（ledger-core.mjs）は同じ文を読み込む（runner の source は import できないので、写しを持たずに 1 か所にするため）。ファイルの段の結果の照合（`checkFileResult`）、全文レビューの結果の照合（`fullReviewProblems`）と意図の判定の照合は CLI だけが持つ。目標の照合の静的な部分（`// <goalmap>`）は coverage-build の Workflow source と同じ文を置き、一致は `tests/coverage-build-goalmap.test.mjs` が照らす（2 つのスキルは互いのファイルを読まないため）。計画役の目標の照合では、項目が依頼に無いものを足したか・範囲を狭めたかを判定させない（判定が回ごとに揺れたので）。

観点の検証役に閉じた問いだけを聞くのは、大きさ・層・制約との矛盾などを自由に判定させると、計画のやり直しのたびに新しい欠陥が出て `PLAN_ROUNDS` で止まったため。`PLAN_ROUNDS` は 1（計画 2 版とその検証の 2 巡）で、2 巡で終わらないのは目標の書き方か観点の作り方の誤りを疑う印なので、それ以上回さずに利用者へ返す（`docs/design/skill-design-patterns.md` の原則）。手続きの細部の良し悪しは、読んだ結果（見落とし・判定できなかった意図・振り返り）で直す。計画役が閉じた問いから作った欠陥に `rejected` と応答しても、その観点は検証済みにならず、次の検証で同じ問いに答え直す。計画の欠陥の id `P<n>` は台帳の連番で、前の番号を使い回さない（`answer --id P<n>` が今の欠陥だけを指すため）。

引用の規則の文 `QUOTE_RULE` は `<checks>` 区間の定数で、照らす関数（`quoteProblem`）と同じ字数の定数から作り、本文を引く段（unit_verify・full_review・file・global・retro）の prompt だけに載せる。`CITE_RULE`（`<goalmap>` 区間）は計画役の目標の照合の節に載る。食い違う規則を 2 つ並べないため。

## 単位と観点と持ち越し

- 線: 「1 体の文脈に収まらない」を判じる唯一の線は、単位を読む役（`READER_ROLES`: file_reader・full_reviewer・global_judge・confirmer）の `roles.json` の `context_tokens` の最小値から `context_tokens × 1/4 × 2` バイトで導く（`lineOf`）。大きいファイルを分ける処理も、全ての詰め合わせも、この 1 本を使う。規模による分岐は置かない。既定は 200k token の 100,000 バイト（`UNIT_MAX_BYTES`）。上げるのは、1 回の入力の token と、単位を大きくしても指摘と照合の拒否が落ちないことを実測で確かめてから（変えるのは roles.json）。
- 単位: 対象のファイル 1 つを 1 単位にし、id はファイルの path にする。本文のバイト数が線を超えるファイルだけを、構造の境目で同格の単位に分け、ファイルを隙間なく覆う（`splitAssets`）。細かく切ると文脈が落ち、無意味な指摘が増えるため。
  - Markdown は最も上の階層の見出しの境目で分けて上限まで詰め、1 つの節で収まらなければ下の階層の見出しで分ける。code fence の中の `#` は見出しにしない。
  - JS・MJS はトップレベルの文の境目（宣言の直前のコメントを含む）で分けて詰める。
  - 境目の無い所は空行、それでも収まらなければ行の境目で分ける。
  - 分けた単位の id は `<path>#<位置>`（見出しの経路・宣言の名前・`c<n>`。同じ位置は `~<k>`）。位置を構造から決めるので、大きさを変えない書き換えでは、書き換えた単位の外の id と hash は変わらない。
- 詰め合わせ: ファイルの段と振り返りの担当は、読む単位を並びの順で前から、本文のバイト数の和が線に収まる所まで詰めた組にする（`packUnitsTo`。前に戻って詰めない）。上限は大きいファイルを分ける基準と同じ 1 つで、新しい線を置かない。関係の近い単位を集める判断をさせず、詰め方を決定的にするため。単位どうしの関係は、同じ詰め合わせの中でも外でも全体の段の意図が受け持つ。
- 全文レビューの読む範囲: 全ての単位を並び（対象の指定の順、ファイルの中は行の順）に並べ、同じ規則で詰めた最初の組にする。ファイルの段が読み直す単位だけを詰めるのと違い、全ての単位を並べてから詰める。1 体の文脈に収まる対象は全てを読み、収まらない対象の残りは status の `full_review.unread` に開示してファイルの段以降に任せる。
- 参照（`--context`）: 検査しないが照らす根拠にするファイル。写しの単位は `context: true` の印を持ち、網羅（`coverage`）・読む単位（`todoUnits`）・全文レビューの範囲・`skip` に数えず、読む役には渡さない。全文レビューの `query` の `units` と判定役の goal の `units` に `context: true` で載り、指摘の場所に引け、引用はその本文で照らす。status には `context` の一覧で出す。
- 写し: `next` は対象と参照のファイルを読んだ内容を `snap/<内容の hash>.txt` に書き、単位は写しの file と行の範囲と hash を持つ。役は写しを Read で開く。全体の段の役も、`query` の事実が持つ写しの file と範囲を開き、対象の本体は開かない。`submit` は写しの hash が台帳と違えば受け付けない。
- 観点: 呼ぶ側が `--lenses` で渡した観点、仕組みの標準の観点（`STANDARD_LENSES`。観点を絞らない通読を含む）、計画の観点の和を、一覧で全ての単位に渡す。呼ぶ側の観点だけでは呼ぶ側の死角を共有し、固定した観点の外の欠陥を落とすため。当てる単位は選ばない（当たらない観点には、読む役が not_applicable と引用を書く）。振り返りの単位には振り返りの観点だけを渡す。`reframe --lenses` は利用者の観点を差し替え、渡さなければ今の利用者の観点を保つ。
- 持ち越し: 台帳は run をまたいで残る。`next` のたびに対象を読み直し、本文の hash か観点の組の版（渡す観点の id・名前・手続き）が変わった単位だけを読み直しにし、消えた単位は外す。持ち越しは単位ごとで、詰め合わせが変わっても（単位の増減や大きさの変化）、読み直すのは変わった単位だけを同じ規則で詰め直したもの。止まった後に対象が変わったら新しい回（`round_start`）を始め、前の回の読みは持ち越し（`status` の `units[].carried`）として新しい読みと分けて数える。読み直した単位は前の読みの hash と周（`prior`）を残し（手続きが変わって全てを読み直す reframe でも残す）、確定した指摘の出どころ（`provenance`: new・missed・fix・carried）を指紋の照合だけで決める。関わる単位は指摘の場所の単位で、全体の段が足した指摘では、それを足した意図の根拠と関係する事実の単位も含める。周の上限は今の回の始まりから数える。
- 全文レビューの持ち越し: 読む範囲・その全ての単位の hash・目標の版（冒頭の文・項目・基準・制約。観点は入れない）が前と同じなら読み直さない。観点が変わっただけ、範囲の外の単位が変わっただけでは読み直さない。読んだときも、`unsubmitted`・`rejected` で失敗して開示したときも同じで、同じ範囲・版では流し直さない（`lost` だけは上の「閉じる」のとおり再開で戻る）。どれかが変われば試行と読みを捨てて新しい 1 体が読み直し、前の全文レビューの事実を今の根拠から外す（記録は消さない）。`kept` でない reframe は記録を捨てるので読み直す。
- 意図の開き直し: 意図の鍵は根拠の事実と、それを足した読み（か判定）の組なので、単位を読み直せば、その単位の事実を根拠に持つ意図は開き直る。無いことを根拠にした判定（目標の gap・前提の unsatisfied）は、どれかの単位の読みが変われば開き直る。変わった単位が抜けを埋めたかもしれないため。
- 段と reframe: 台帳は呼ぶ側の段（`phase`）をまたいで 1 つ。`reframe` は照合済みの印のある台帳だけを受ける。
  - 同じ段で手続きの指紋（利用者の観点・目標・基準・制約・決定の記録・link）が前と同じなら `kept: true` で、対象だけを差し替え、`phase_start` の `reframes` を 1 つ増やす。読み直すのは次の `next` で内容の変わった単位だけで、止まった後なら新しい回を始める。
  - それ以外は、出ていく段の節（`findings`・`groups`・`events`）を `phase_records[<段>]` に写し、計画・回答・試行・pending を捨て、全ての単位を読み直しにし、周を 1 つ進めて `phase_start`（周・起動数・出来事の数）を置く。中身が同じでも読み直すのは、手続きを変えたら全体を検証し直すため。
  - init と reframe は段の位置（`phase` と `phase_start`）を `phase.json` に書く。呼ぶ側は台帳を読まずにこれを読み、`phase_start` が変わったことで reframe が流れたと判じる。
- 試行の回数と周の数は台帳にあり、再開しても 0 に戻らない（reframe は段を始め直すので試行を捨てる）。

## 全体の段（探索グラフ）

事実（グラフの点）は CLI が受理したものだけ: 全文レビューの指摘・参考、ファイルの段の指摘・参考・保証・前提、静的な検査の結果、全体の段の判定と、判定が足した指摘。意図（次に調べること）は、今の根拠の事実から CLI が毎回決定的に導く（`board`）。役は意図を出さない。何を調べるかは事実の種類で決まり、判断に任せると意図の漏れが run ごとに変わるため。

| 意図 | 作る条件 |
|---|---|
| alias（名寄せ） | 保証・前提の主語の正規化した名前が近い組（片方がもう片方を含む） |
| subject（主語の照合） | 2 つ以上の単位にまたがる主語（名寄せで統合した後）と、名寄せが不明のまま残った組。その主語に関わる名寄せが全て閉じてから作る |
| finding（指摘の判定） | 全文レビューの指摘・ファイルの段の指摘・静的な検査の結果の 1 件ごと |
| premise（前提の消化） | 他の単位に同じ主語の保証がある前提ごと |
| goal（目標の判定） | 目標と受け入れ基準の項目ごと。関係する事実は、その項目を義務に持つ事実。担当と query は単位の索引（`units`: id・path・写しの file と範囲）を持ち、載せなかった事実を件数（`omitted`）と id（`omitted_ids`。上限 `OMITTED_IDS_MAX` を超えた件数は `omitted_more`）で宣言する。支え（`support`）には `omitted_ids` の id も使え、引用と抜けの場所には全ての単位を使える。義務に結ばれた事実が無くても判定できるようにするため。足す指摘の義務は CLI が意図の項目にする |
| confirm（確認） | 全体の段が足した指摘の全件（mode `added`）、全文レビューの指摘の全件（判定役が残したものは `kept`、落としたものは `dropped`。重さによらない）と、他の落とした指摘（mode `dropped`。重いものは全件、他は抜き取り。`sampled`） |
| group（束ね） | 他の意図が全て閉じ（判定できずに閉じたものを含む）、確定した指摘があるとき 1 つ。根拠は確定した指摘の事実で、確定した指摘が変われば開き直す |

- 判定の閉じた集合は ledger-core.mjs の `VERDICTS`・`ALIAS_ANSWERS`、意図の種類から役への対応は ledger-cli.mjs の `INTENT_ROLE`・`INTENT_ROWS`（判定役は alias・subject・finding・premise・goal、確認役は confirm・group）。全体の段の行は、開いた意図のある役の組ごとに `workers` 体（既定 1）で、残りの予算に収める（足りないときは判定役の組から 1 体ずつ割り当て、割り当てられない組は次の呼び出しへ回す）。1 体が claim を繰り返して意図を束で取る。波の中で受理された事実から増えた意図も、行のある組なら同じ波で取る（確認役は確認に続けて束ねを取る）。行の無い組の意図は次の波が取る。
- 意図は、全文レビューとファイルの段 → 全体の段 → 確認 → 束ねの向きにだけ作られ、後ろへ戻る辺は無い。このため、開いた意図は有限の手順で 0 になる。
- 試行: 同じ根拠の鍵で、照合に落ちるか取ったまま提出されない試行が `MAX_ATTEMPTS` に達した意図（束ねを含む）は、判定できなかった意図（undecided）として理由つきで閉じ、開いた意図に数えない。止めずに他の意図を進め、complete まで行く。利用者の回答で試行を戻しても同じ失敗に戻り、止めた結果は呼ぶ側が取り込めないため。
  - 取ったまま提出されなかった意図は、その呼び出しで 1 件以上出した役のものなら、試行に数えずに手放す。1 件も出さなかった役の束が 2 件以上なら、試行に数えずに手放し、その役の種類の次の束の上限をその束の量の半分にする。1 件の束で 1 件も出さなかったときだけ試行に数える。その種類で 1 件以上出た波の後は、上限を線に戻す。submit が 1 回なので時間切れはほぼ 1 件も出さない形で起き、同じ束を繰り返すと束の全てが判定できなかった意図になるため。
- 引用: 判定の引用は、根拠と関係する事実の単位の本文に逐語であることを照らす。足す指摘の場所の `unit` は、引用が複数の単位にあるときだけ役が書く。1 つの単位にしか無ければ CLI が引き当て、複数にあれば候補を挙げて拒む。確認の判定の引用が逐語でなければ、拒否せずに検証不能（unverifiable）として受け取る。
- 確定: 指摘を確定にするのは、義務（目標か受け入れ基準の id）と原因の層の両方を持つものだけ（`deriveFindings`）。結べないものと、場所が参照（`--context`）の単位だけにあるもの（確認が検証不能でも `unverifiable` に入れない）は参考（`references`）にし、指摘の件数にも網羅にも数えない。
  - ファイルの段・静的な検査の指摘は、指摘の判定が keep なら確定。drop で、確認が disagree なら復活して確定。確認が検証不能なら検証不能の指摘として出す（黙って落とさない）。
  - 全文レビューの指摘は、確認を通ったものだけを確定にする。keep で確認が agree なら確定、disagree なら確定しない。drop で確認が disagree なら復活して確定。どちらも確認が検証不能なら検証不能の指摘。同じモデルの判定役だけで確定する経路を作らないため。
  - 全体の段が足した指摘は、確認が agree なら確定、検証不能なら検証不能の指摘。
- 静的な検査: `--link <正規表現>`（id の型。枠の一部で、`--link` の無い reframe は null に戻す）があれば、範囲で書いた参照（例: `U1〜U3`）を 1 件ずつに展開し、どの単位の本文にも無い id を事実にする（`staticFacts`）。単独の参照は、存在する id と見分けられないので照らさない。結果は指摘の判定にかけ、それだけで確定にしない。
- 束ね: 確認役が確定した指摘の事実を根本原因で群にし、群ごとに根本原因と原因の層を付ける。CLI は群の形と、根拠の事実の id が群か `unassigned` にちょうど 1 回ずつあるかを照らす（`checkGroups`）。群は束ねの判定から導き、id は `G<周>-<役が付けた id>`。上の層の群は needs_input の `upper_groups` で返す。反証と横展開は持たない。1 件ずつの指摘は確認で確かめてあり、同じ型が他のファイルにあるかは、全てのファイルの指摘を束ねた結果に既に出るため。
- status の指摘: `findings.confirmed` と `findings.unverifiable` は、判定・path の組・norm した quote と claim・layer・出どころ（`origin`）が同じ指摘を 1 件にまとめ、`id`（最初の指摘）と全ての `ids` を持つ。確定した指摘は `paths`・`obligation`・`confidence`・`origin`・`provenance` と、結ばれた群の id（`groups`）を持つ。

## 止める条件

`next` が返す `stop` の種類と、その条件。上から順に判定する（`decide`）。どの停止の出力にも、開いたままの意図（`open_intents`）、判定できなかった意図（`undecided`）、status のファイルの path（`status_path`）が載る。上限で止まったことを完了と取り違えないため。

| stop | 条件 | 再開のしかた |
|---|---|---|
| blocked（cause: input） | 台帳を作った後に対象のファイルが読めなくなった（init の時点で読めなければ台帳は作られない） | 置き場を直して `next` |
| blocked（cause: failure） | 進みの無かった呼び出し（上の「呼び出しと役の読み書き」の閉じる）が `MAX_FAIL_STREAK` 回続いた | 環境を直して `next`（環境の失敗に数えた試行は戻る） |
| limit | 今の回の始まり（`round_start`）からの周が `max_cycles` を超えた（周が進むのは、この周の振り返りまで済んだ後に読む単位か開いた意図が出たときだけで、run の中では進まない）、今の段の始まり（init か、`kept` でない reframe）からの起動数が `max_agents_total` に達した | `config` で上限を上げて `next` |
| needs_input | 依頼文・決定の記録が求める成果を、どの項目も受け止めていない（`goal_gaps`。その回の計画は使わない）／計画（目標の照合を含む）・観点の検証が試行の上限まで欠けた（`stuck`。キーは `plan`・`unit_verify`。`answer --id goal` などで目標を直すと `plan` の試行が戻る）／計画役が Q3 の欠陥に `no_target` を付けた（`target_gaps`: `{id: P<n>, goal_id, reason}`）／計画の欠陥が計画のやり直し `PLAN_ROUNDS` 回（2 巡）で消えない（`plan_defects`。理由に 2 巡で終わらなかったこと・残った欠陥・検証の答えの引用）／利用者への質問がある（`questions`） | `answer` を足して `next`（`P<n>` への回答で計画の段を 1 巡だけ回す。答えずに上限だけを変えても回らない） |
| blocked（cause: target / failure） | 単位が 0 件／読みを受け付けた単位が 1 つも無い | 対象を直すか、原因を直して `next` |
| needs_input | 上の層（方針・要求）が原因の確定した指摘（`upper`）・束（`upper_groups`）、検証不能の指摘（`unverifiable`）が残る | 指摘の id か群の id で `answer` |
| complete | 全ての単位を見たか見られなかった理由を開示し、開いた意図（束ねを含む）が 0 になり、この周の振り返り（印のある台帳では作らない）が済み、上の全てに当たらない | 対象が変われば、同じ台帳で `next` が変わった単位だけを読み直す |

- 全文レビューは止める条件に関わらない（失敗の扱いは上の「呼び出しと役の読み書き」の閉じると submit）。網羅はファイルの段が持つため。
- 単位の状態: unseen →（読みを受け付けた）seen。取ったまま提出されないか照合に落ちる試行が `MAX_ATTEMPTS` に達したら、理由つきの disclosed（`status` の `skip`）。
- 止まるたびに `status` と同じ中身を今の段の `status-<段>.json` に書く。呼び出しを開くときと reframe（入ってくる段のファイル）で消すので、今の段のファイルがあるのは止まっている間だけ（呼ぶ側が前の停止の status を取り込まないため）。
- 飽和（束ねの判定ごとの `{cycle, confirmed, groups}`。周、束ねた確定した指摘の数、群の数）は `status` の `saturation` に記録するだけで、止める条件に使わない。新しい指摘が 0 件でも見落としが無いとは言えないため。

## 記録

- 起動ごとに役・label・指定した model・effort・成否（`agents`）、呼び出しごとに起動数・欠け・提出の数・token（`calls`）。token は Workflow source が本体の始めと返す直前に読んだ `budget.spent()` の差で、どちらかが読めなければ（runner など）null と理由を残す。`budget.spent()` が何を数えるかは確かめていないので、同じ経路の差どうしだけを比べる。model は指定値で、実際に効いたかは確かめられない。
- run の指標（`status` の `metrics`）: 確定した指摘の出どころの内訳、新しく読んだ単位と持ち越した単位の数、全体の段で落とした数と確認で復活した数。止まるたびに `run_records` に 1 件足す。
- 出来事（`events`）: 拒否（`rejected_<種類>`。束ねの照合に落ちた提出は `rejected_group`）・返らなかった役・取ったまま提出されなかった担当（`missing_<種類>`）・全文レビューを読まなかったとしての開示（`full_review_failed`）と、その読み直し（`full_review_reopened`）・開示・判定できなかった意図（`undecided`）・目標の穴（`goal_gaps`）・確認での復活・不明のままの名寄せなど。種類の名前の正本は ledger-cli.mjs の `addEvent` の呼び出し。振り返りの単位に入らなかった出来事は `events_not_in_retro` に残る。
- 較正: `init --seeds` に既知の欠陥（`[{path, quote, lens?}]`）を渡すと、`status` の `calibration` が観点ごとの再現率を、ファイルの段の指摘（`origin: file`）だけで返す。全文レビューの指摘と全体の段が足した指摘は観点を持たないので数えない。仕込んだ欠陥を入れた対象は利用者が用意する。

## 汎用の設計の型から変えた点

このリポジトリの Workflow の設計の型（状態を CLI だけが書き、run の中では運搬役が CLI を呼んで出力を script へ運ぶ形）から、次の点を変えている。

- 運搬役を置かない。状態を書くのは CLI だけという点は守り、役が `claim`・`query`・`submit` を Bash で直接流す。`next`・`ingest` は Workflow の外で呼び出し側が流し、1 回の Workflow は、CLI が台帳に記録した次の波がある間、波を順に流す。役が返すのは次の波の印（制御の印）だけで、内容は運ばず、CLI が claim で記録と照らす。運搬役の写し違いと、照合を通らずに次の役へ渡る経路を作らないため。競合は lock で直列にし、遅れた書き込みは `callId` で拒否する。native Workflow の subagent が Bash で CLI を流せることは確かめてある。Codex の runner の worker が `stateDir` に書けるか・CLI を流せるかは確かめていない。
- 状態の寿命を 1 run でなく、run をまたぐものにする（利用者の決定）。対象が変わっても新しい状態から始めず、同じ台帳で変わった単位だけを読み直す。呼ぶ側の段が変わるときも台帳は 1 つのままで、`reframe` で枠を差し替えて全体を読み直す。
- 重要度で単位を絞らず、同じ範囲を重ねて読まない。独立は、判断を出す役と確かめる役（計画役と観点の検証役、判定役と確認役）を別のモデルにし、ファイルの段に他の役の書き込みを読ませず、新しい context で読むことで作る（体の分け方は SKILL.md の「目的」）。Anthropic のモデルどうしなので盲点の重なりは減りにくく、結果にそう開示する。

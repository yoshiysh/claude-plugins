# Agent: spec-updater

`/chat` での設計相談は複数ラウンドにまたがることがある。Notion（Step 5）が「毎ラウンドの全文
ログ」を担うのに対し、本 agent は「今この瞬間、設計がどこまで固まっているか」を1ファイルに
凝縮し続ける役割を持つ。1ラウンドで会話が収束しても、複数ラウンド続いても同じ仕組みで動く
（ラウンド数を先読みして判断しない）。

## Inputs

- `[SPEC_PATH]`: 書き込み先のファイルパス（Coordinator が解決済み。新規トピックなら新しい
  パス、既存トピックの継続ならその spec.md のパス）
- `[USER_CONSULTATION]`: 今回のラウンドの相談文
- `[RAW_ANALYSIS]`: 今回のラウンドの Fable 生分析（Step 3 の出力）
- `[FORMATTED_RESPONSE]`: 今回のラウンドの整形後回答（Step 4 の出力）

## Task

1. `[SPEC_PATH]` が既に存在するなら Read する（初回なら存在しない。その場合は空から始める）。
2. 今回のラウンドの3入力を読み、以下の3分類に落とし込む。
   - **決定事項**: 合意・確定した設計判断。理由も併記する（「なぜそう決まったか」が無いと
     後で再読したときに再検討の余地があるのか判断できない）
   - **未決の論点**: まだ結論が出ていない、あるいは相談者と Fable の見解が割れている点
   - **却下した案**: 検討した上で採用しないと決まった案。理由も残す（同じ案を後日また
     持ち出して同じ議論を繰り返さないため）
3. 既存の spec.md がある場合は**マージする**（単純追記ではない）。今回のラウンドで：
   - 既存の「未決の論点」が「決定事項」に格上げされたら、未決リストから削除し決定事項に移す
   - 既存の「決定事項」が今回のラウンドで覆されたら、決定事項から削除し「却下した案」に
     理由付きで移す（上書きで消さない。過去の判断が誤りだったと分かった記録も価値がある）
   - 今回新たに出た決定/未決/却下を追加する
4. `[SPEC_PATH]` に以下の構成で書き込む（新規作成 or 上書き）。

```markdown
# {トピックの短い説明}

## 決定事項

- **{決定内容}**: {理由}

## 未決の論点

- {論点の説明}

## 却下した案

- **{案}**: {却下理由}
```

## 出力

ファイルへの書き込みが本 agent の deliverable。Coordinator へは「更新完了」の一言と、今回の
ラウンドで変わった点（新規決定・格上げ・却下への移動）を短く返すだけでよい（全文を呼び出し元へ
返す必要はない。全文は Notion 記録の責務であり、本 agent の責務ではない）。

## 禁止事項

- **全文転記をしない**: これは Notion 記録（Step 5 / notion-recording-guide.md）の役割であり、
  本 agent は凝縮された仕様として書く。冗長な議論の経緯は書かず、結論と理由のみを残す。
- **投資判断の内容を書き込まない**: 委譲呼び出し（investment-strategist への委譲）はそもそも
  本 Step の対象外（SKILL.md 側でスキップされる）。
- **理由を欠いた決定事項を書かない**: 「なぜ」が無い決定事項は、後で読み返した相談者が
  再検討の必要性を判断できない。

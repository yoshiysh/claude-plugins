# 形式手法の知識

formal-method の担当と、結果を読む依頼元のための語の意味。規範の正本は仕様 `docs/specifications/formal-method.md`（以下 SP-FORMALMETHOD-NNN）で、値の字面は [成果物の形式](artifact-formats.md) と `scripts/lib/schemas.mjs` が持つ。この文書は語の意味と読み違えやすい点だけを置く。

## 保証の範囲

形式検証の結果は、形式モデル・性質・前提・検査した範囲の組についてだけ言える。対象そのもの、利用者の意図、対象の実装との一致は言えない（SP-FORMALMETHOD-015）。

| 語 | 意味 | 読み違えやすい点 |
|---|---|---|
| 形式モデル | 対象の性質を道具で調べるために書いたモデル又は命題。扱う対象・状態・出来事・前提・制約・扱わない範囲を持つ（SP-FORMALMETHOD-005） | モデルの外の振る舞いについては何も言えない |
| 前提 | 検査が成り立つとして置いた条件。環境、公平性、外部のものを含む | 前提が互いに矛盾すると、どの性質も成り立ってしまう。この成功は検証の成功にならない（SP-FORMALMETHOD-005） |
| 有限化 | 無界の値の領域・遷移数・探索の深さに境界を置き、有限の範囲で調べること | 境界の外では何も確かめていない |
| 範囲を限った検査 | 有限化した範囲で調べた保証。範囲と境界を併せて示す | 道具が成功しても `無界の証明` にはならない（SP-FORMALMETHOD-005） |
| 無界の証明 | 境界を置かずに命題を証明した保証。証明した命題と未解決の証明の義務を併せて示す | 未解決の義務が残る間は、その命題の全体は示せていない |
| 形式検証でない確認 | 形式化できない性質を、別の方法で独立に確かめた保証。確認の方法を併せて示す（SP-FORMALMETHOD-004） | 形式検証の結果と同じものとして数えない |
| 公平性の前提 | 進行性（いつか必ず起こる）を示すために置く、実行の選ばれ方の前提（SP-FORMALMETHOD-005） | 前提を外すと進行性の結論は成り立たないことがある |
| 独立した確認 | 確認する物を作っておらず、作成の過程の会話・推論の記録を受け取っていない者が行う確認（仕様の用語定義） | 作った者自身の見直しは、これに当たらない |

## 結果の語の意味

| 語 | 意味 | 読み違えやすい点 |
|---|---|---|
| 充足可能（sat） | 道具が、query の条件を全て満たす値の組が在ると答えた | 性質の検査は「前提 ∧ ¬性質」を問うので、sat は性質に反する例が在ること（反例）を表す |
| 充足不能（unsat） | 道具が、条件を全て満たす値の組は無いと答えた | 性質の検査では性質を満たすことを表す。前提の整合の確認（sanity）では、前提が矛盾していることを表す。種類ごとの読み方の正本は [CLI 契約](cli-contract.md#z3-の-adapter) |
| 反例 | 性質に反する、入力と経過の具体例 | 反例が在ることは、対象が性質を満たさないか、モデルが出所を正しく表していないかのどちらかを示す。どちらかは原因の分類が決める（SP-FORMALMETHOD-011） |
| unknown | 道具が判定できないと答えた | 「証明できなかった」は「成り立つ」ではない。成功に数えない |
| 時間切れ | 実行中の検査が、依頼元の時間の上限か道具自身の時間の上限に達した | 上限までに違反が見つからなかったことは、成り立つことを示さない |
| 実行失敗 | 止めていない道具の異常終了、読めない出力、判定以外のエラー（構文の誤りなど） | 構文の誤りによる失敗を、違反の検出として数えない（SP-FORMALMETHOD-012） |
| 未実行 | 検査を始めていない、又は道具の結果を得る前に formal-method が止めた | 何も確かめていない |
| 変異 | 性質に反するように書き換えたモデル又は query。検査がその違反を見つけるかで検出能力を確かめる（SP-FORMALMETHOD-012） | 期待する違反は、検査を実行する前に決める |
| 決定的な検査 | 構文、参照の解決、計画した検査の結果の有無、出力の形式、反例の再実行を、CLI が機械的に確かめること | 意味の確認の代わりにならない。逆も同じ（SP-FORMALMETHOD-012） |
| 意味の確認 | モデルの意味、前提と保証の範囲、分割の境界、結論を、独立した確認で確かめること | 対応が在ることだけを、意味が一致する根拠にしない（SP-FORMALMETHOD-005） |

## 判定と区分の字面

結果の値は仕様の日本語の字面のまま使う。英語に訳した値や旧版の値は、CLI の照合で拒まれる。

**性質の判定**（集合で示す。SP-FORMALMETHOD-011）

| 値 | 検証の成功か | 付く条件の要点 |
|---|---|---|
| `検証済み` | 成功 | 形式化できる性質で、検査が全て成功し、問いに依存せず、対応と意味の確認・合成の条件・SP-FORMALMETHOD-012 の確認が全て成り立つ |
| `別手段で確認済み` | 成功 | 形式化できない性質で、問いに依存せず、別の方法の独立した確認が成り立つ |
| `反例` | 成功でない | 検査が性質に反する例を返した |
| `未実行` | 成功でない | 検査を始めていない。検査が 0 件の性質には、適した道具が無いか準備できない場合だけ付く |
| `unknown` | 成功でない | 道具が判定できないと返した |
| `時間切れ` | 成功でない | 時間の上限に達した |
| `実行失敗` | 成功でない | 上の「実行失敗」 |
| `未確認` | 成功でない | 成功の条件が成り立たず、他の成功でない値も付かない（対応するモデルが無い、独立した確認が成り立たない、問いの回答を待つ） |

- `検証済み` と `別手段で確認済み` は、他の値と同じ集合に入らない。
- 検査の判定は `成功`・`反例`・`未実行`・`unknown`・`時間切れ`・`実行失敗` のどれか 1 つ。2 つ以上の条件が成り立てば `反例`・`時間切れ`・`実行失敗`・`未実行`・`unknown` の順で先の値になる。

**その他の区分**

| 区分 | 値 | 正本 |
|---|---|---|
| 結果の状態 | `完了`・`停止` | SP-FORMALMETHOD-015 |
| 保証 | `範囲を限った検査`・`無界の証明`・`形式検証でない確認` | SP-FORMALMETHOD-005 |
| 状態×出来事の組合せ | `許される`・`禁止された`・`対応できていない`。遷移が書かれていないことだけでは `禁止された` にしない | SP-FORMALMETHOD-006 |
| 原因 | `要求の不足`・`形式モデルの欠陥`・`分類処理の欠陥`・`対象が性質を満たさない`・`原因未確認` | SP-FORMALMETHOD-011 |
| 検出能力 | `検出を確認`・`検出せず`・`別の方法で確認`・`検出能力未確認`。性質の判定とは別に示す | SP-FORMALMETHOD-012 |
| 独立検証者の確認の結果 | `成り立つ`・`成り立たない`・`確認できず` | [担当の返り値](artifact-formats.md#担当の返り値) |

- `原因未確認` は、根拠をもって他の 4 つのどれとも決められないときの値である。形式モデルか分類処理の欠陥だけを根拠に `要求の不足` としない。出所に書かれた遷移が洗い出し・モデル化・分類で失われたなら、その処理の欠陥である（SP-FORMALMETHOD-011）。
- `対応できていない` 組合せと、`検証済み`・`別手段で確認済み` でない必要な性質は、未検証として結果に残り、状態は `完了` にならない（SP-FORMALMETHOD-015）。

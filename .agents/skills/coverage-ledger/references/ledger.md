## 構成（ブラックボード）

| 部品 | 実体 | 持つもの |
|---|---|---|
| ボード | `stateDir/ledger.json`（`hints.jsonl` は別ファイル） | 目標・制約・入力の項目・計画・資産・枡・指摘・出来事・束・起動の記録 |
| 知識源 | Workflow source の役（`scripts/roles.json`） | 1 体 1 単位の判断だけ。ボードを書かない |
| 制御 | `scripts/ledger-cli.mjs`（`next` と `ingest`） | 次の 1 手の決定、受け入れ、止める判定 |

探索グラフの事実は台帳の記録（受け入れた読み・確かめた指摘・束・出来事）で、意図は `next` が台帳から導く次の 1 手（読む枡・直す論点・横展開の観点）。出来事 → 束（根本原因と層）→ 横展開の観点、の辺は ID で辿れる（`events[].ref`・`groups[].keys`・`lenses[].origin`）。

## 段と、script と LLM の分け方

| 段 | 元にした run | LLM がすること | script がすること |
|---|---|---|---|
| plan | run 2a | 目標の照合、独立な計画役 2 体（別のモデル）、統合、入力の振り分け（小さい束）、単位ごとの反証 | 単位の形・ID の重複・依存の実在と循環・制約の受け皿・source_map・欠陥への応答の網羅・行き先がちょうど 1 つ・引用の逐語照合・単位の同一性（中身と送られた入力） |
| generate | 1 周目 S2・S3 | 論点ごとの案（依存の順に、上流の案の中身を渡す）、書き手 1 体 | 依存の波の計算、読んだ証拠の引用の照合、節の数の上限、全論点がどれかの節にあるか、節の見出しが本文にあるか、ファイルへの書き込み |
| review | 1 周目 S4・S5 と run 2a の学び | 枡ごとに読む役、枡ごとに別の枠組みの検証役 | 枡の生成、区画ごとの読んだ証拠の照合、指摘の引用の照合、判定の網羅、偽の引用での判定を検証不能にする |
| retro | 振り返りの run | review と同じ（資産が出来事、観点が R1〜R4） | 出来事を段ごとの資産にし、出来事ごとに区画を作る（全件を引用させる） |
| group | 1 周目 S6・振り返りの束ね・反証 | 根本原因で束ねる、別のモデル 2 体で反証 | 全 key がちょうど 1 つの群に入るか、層の値、横展開の観点の追加、直す論点への戻し |

静的な照合の正本は Workflow source の `// <checks>` 区間だけで、CLI は同じ文を読み込んで `ingest` で照らし直す（runner の source は import できないので、写しを持たずに 1 か所にするため）。呼び出し側が args を運ぶので、source は args の FNV（`argsSum`）を照らし、合わなければ役を起動せずに止まる。

## ID と持ち越し

- 資産: Markdown は見出しの経路（`path#親/子`）、それ以外は行の塊（`path#cN`）。1 体に渡す本文は 120 行まで。見出しだけの塊は資産にしない。
- 枡: `資産|観点|p回`。回は 1..k で、全ての枡に同じ k を使う。
- 指摘: `枡#hash(引用+主張)`。同じ枡の別々の指摘は潰れない。
- 持ち越し: 台帳は run をまたいで残る。`next` のたびに対象を読み直し、資産の hash か観点の版（名前・手続き・規準の入力）が変わった枡だけを未読に戻す。前の指摘は superseded にする。消えた資産の枡は gone。
- 試行の回数（枡・論点・振り分け・書き手・束ね）と周の数は台帳にあり、再開しても 0 に戻らない。

## 止める条件

`next` が返す `stop` の種類と、その条件。上から順に判定する。

| stop | 条件 | 再開のしかた |
|---|---|---|
| blocked（cause: input） | 対象・入力のファイルが読めない | 置き場を直して `next` |
| blocked（cause: failure） | 全ての役が欠けた呼び出しが 2 回続いた | 環境を直して `next` |
| limit | 周が `max_cycles` を超えた、起動数が `max_agents_total` に達した | `config` で上限を上げて `next` |
| needs_input | 目標が依頼文と合わない／計画の欠陥が統合のやり直し 2 回で消えない／試行の上限まで欠けた段がある／利用者への質問がある | `answer`（`goal`・質問の id・`attempts:<キー>`）を足して `next` |
| blocked（cause: target / failure） | 枡が 0 件／読みを受け付けた枡が 1 つも無い | 対象を直すか、原因を直して `next` |
| needs_input | 上の層（方針・要求）が原因の欠陥・束、検証不能の指摘、書き手が退けた指摘が残る | 指摘の id で `answer` |
| complete | 読み直す枡が 0、この周の振り返りと束ねが済み、上の全てに当たらない | 対象が変われば、同じ台帳で `next` が変わった枡だけを読み直す |

- 枡の状態: unseen →（読みを受け付け、指摘があれば全て検証役が判定）settled、欠けが `MAX_ATTEMPTS`（2）回で disclosed。指摘の無い settled の枡は検証役を通っていない（見ただけ）ので、`coverage.settled_no_findings` として別に数える。
- 全ての役が欠けた呼び出しの試行は別に数え、blocked（failure）から再開したときに戻す（環境の失敗で枡を開示に倒したままにしない）。
- 束ねの段で反証役の枠を超えた群は unverified のまま残し、横展開の観点も作る（絞らないため）。`status` の `groups` で状態が分かる。
- 振り返りは、その周までにまだ振り返っていない出来事を全て拾う。振り返りの後に起きた出来事は次の周で拾い、最後まで拾えなかったものは `status` の `events_not_in_retro` に残る。
- 飽和（周ごとの新しい確かめた指摘の数）は `status` の `saturation` に記録するだけで、止める条件に使わない（新しい指摘が 0 件でも見落としが無いとは言えないため）。

## 記録

- 起動ごとに役・label・指定した model・effort・成否（`agents`）、呼び出しごとに起動数・欠け・token（`calls`）。token は native の `budget.spent()` が読めるときだけ数で、runner では null と理由を残す。model は指定値で、実際に効いたかは確かめられない。
- 観点の外の気づきは枡ごとに残し、`status` の `outside_notes` で返す。効果の根拠は無い（開示して使う）。
- 較正: `init --seeds` に既知の欠陥（`[{path, quote, lens?}]`）を渡すと、`status` の `calibration` が観点 × 読む役（回）ごとの再現率を返す。仕込んだ欠陥を入れた対象は利用者が用意する。

## skill-design-patterns から離れたところ

- 運搬役を置かない。状態を書くのは CLI だけという原則は守り、CLI は Workflow の外で呼び出し側が流す。1 回の Workflow は 1 段を 1 回だけ流し、ループは台帳と `next` が持つ。運搬役の失敗・写し違い・競合の種類の欠陥を作らないため。
- 台帳の寿命は 1 run でなく、run をまたぐ（利用者の決定）。
- 重要度で枡を絞らない。全ての枡を同じ扱いにし、独立は別のモデル・別の枠組み（反証側）・新しい context で作る。Anthropic のモデルどうしなので盲点の重なりは減りにくく、結果にそう開示する。
